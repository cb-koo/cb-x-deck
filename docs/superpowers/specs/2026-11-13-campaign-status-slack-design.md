# 캠페인 현황 슬랙 자동 공유 설계 (2026-11-13)

캠페인 현황 페이지(`/campaigns/overview`, 설계 `2026-11-12-campaign-status-design.md`)의 **진행 상태**를 정해진 시각에 슬랙 채널로 이미지와 요약 글로 보낸다.

확정 시안:
- 이미지: `docs/mockups/campaign-status-slack-20261113.html`(그리는 HTML, 숫자는 예시) / `.png`(실제로 보낸 결과, 1600×1950 = 800px 배치 2배 해상도)
- 메시지: 2026-11-13 테스트 채널에 보낸 "테스트 4"(아래 §4에 블록 그대로 적음)

표기: **[koo]** = koo가 정한 것, **[판단]** = 설계자가 정한 것.

## 1. 왜

팀원 전체가 매일 아침 캠페인 진행 상황을 따로 화면을 열지 않고도 파악하게 한다. 캠페인은 회사의 메인 업무이고, 이 일이 막히면 다른 업무도 막힌다 [koo].

**담당자를 압박하려는 것이 아니다** [koo]. 그래서 사람(담당자) 이름은 넣지 않고, 늦은 건은 클라이언트 단위로만 말하며, 말투는 사실만 담는다(경고 이모지 🚨, ❗ 쓰지 않음) [판단].

## 2. 목표, 하지 않는 것

**목표**
- 정해진 시각에 이번 주 주차 캠페인의 진행 상태를 슬랙 채널에 보낸다.
- 슬랙 안에서(휴대폰 포함) 이미지와 글만 보고 상황을 안다. 더 볼 사람은 링크로 페이지에 간다.

**하지 않는 것** [koo: 진행 상태만]
- 성과 숫자(조회수, 저장수, CPV)와 흐름 차트
- 방문협찬(장기) 캠페인
- 화면에서 요일, 시각, 채널을 바꾸는 설정 UI [판단: 지금 정한 일정이 고정이라 필요할 때 코드에서 바꾼다. 바꿀 일이 잦아지면 그때 설정 탭을 만든다]
- 실제 페이지를 브라우저로 캡처하는 방식 (조사 뒤 koo가 2번 "서버에서 직접 그리기"를 골랐다)

## 3. 언제, 어디로

| 항목 | 값 | 출처 |
|---|---|---|
| 보내는 시각 (한국 시각) | 월요일 18:00, 수요일 10:30, 목요일 10:30, 금요일 10:30 | [koo] |
| 이유 | 월요일에 그 주 계획이 세팅되므로 월요일 저녁에 세팅 결과, 수요일부터 매일 아침 진행 | [koo] |
| 채널 | `C0AD9E5HE1K` (#f-x-채널-통합관리). 앱 초대 완료 | [koo] |
| 테스트 채널 | `C0CGWSFBDPV` (#test-channel). 앱 초대 완료 | [koo] |
| 보내는 앱 | 슬랙 앱 "CB Deck" (`A0CC33T5G0Y`, 불편 알리기와 같은 앱). 권한 `chat:write`, `files:write`, `files:read` 추가 완료 | [koo] |
| 봇 토큰 | Vercel 운영과 스테이징 환경 변수 `SLACK_BOT_TOKEN`(민감 정보로 등록, 다시 읽기 불가) 등록 완료 | |

**공휴일은 건너뛴다** [koo 11-13]
- 보낼 시각이 한국 공휴일(대체공휴일 포함)이면 그 회차는 보내지 않는다. 다음 회차는 평소대로.
- 공휴일 목록은 코드에 둔다(`src/lib/koreanHolidays.ts`, 2026년과 2027년). 외부 API는 쓰지 않는다 [koo: 방법 A 추천 수락].
- 목록 출처는 한국천문연구원 월력요항(공식 발표)으로 확인해 넣고, 파일 머리 주석에 출처와 "다음 해 목록은 해가 바뀌기 전에 추가" 안내를 적는다. 임시공휴일(선거일 등)은 지정되면 한 줄 추가한다.
- 목록에 없는 해(2028년 이후)가 되면 건너뛰지 않고 보내되, 응답과 로그에 "공휴일 목록 없음"을 남긴다 [판단: 안 보내는 것보다 보내는 쪽이 덜 해롭다].
- 판단은 라우트 안에서 한다(pg_cron 쪽은 요일과 시각만). 응답 JSON에 `skipped: 'holiday'`와 공휴일 이름을 담는다.
- 회사 휴무일은 넣지 않는다 [koo].

**보는 주:** 보내는 순간의 이번 주(`resolveWeek(null, kstToday())`). 월요일 저녁에 아직 작업이 없는 캠페인은 "세팅 전"으로 나온다.

## 4. 메시지

슬랙 블록 메시지 하나(`chat.postMessage`). 순서 [koo 확정, 테스트 4]:

```
📊 *11월 2주차 캠페인 현황*
11/12 (수) 10:30 기준

✅ 게시 완료  *41 / 63건* (65%)
⏰ 예정일 지난 미게시  *5건*  백수약국 3건, 벤자민클리닉 2건
🗓️ 남은 게시 예정  *17건*  예정일 미정 2건 포함
⚪ 세팅 전  *1개*  마인드

👉 <https://cb-x-deck.vercel.app/campaigns/overview|캠페인 현황 열기>  캠페인별 게시물과 성과는 여기서 봐요

[이미지]

진행률이 높은 캠페인부터 보여줘요. 방문협찬(장기) 캠페인은 빠져 있어요. 월 18:00, 수목금 10:30에 보내요.   ← context 블록(작은 회색 글씨)
```

블록 구성: section(제목 두 줄) → section(요약 네 줄) → section(링크 줄) → image(`slack_file: { id }`) → context(안내).
알림 미리보기용 `text`: `📊 11월 2주차 캠페인 현황: 63건 중 41건 게시, 예정일 지난 미게시 5건`.

**바뀌는 줄** [판단]
- 예정일 지난 미게시가 0건이면 그 줄은 `✅ 예정일 지난 미게시 없음`.
- 늦은 클라이언트는 많은 순 3곳까지, 넘치면 `외 N곳` (화면 상단 칸과 같은 `tiles.overdueBy`, `overdueMore`).
- 예정일 미정이 0건이면 "예정일 미정 N건 포함"을 뺀다.
- 세팅 전 캠페인이 없으면 `⚪ 세팅 전` 줄을 뺀다. 3곳 넘게 있으면 이름은 3곳까지 + `외 N곳`.
- 게시 완료 퍼센트는 반올림 정수. 계획이 0건이면 퍼센트를 빼고 `0 / 0건`.
- 그 주에 주차 캠페인이 하나도 없으면 이미지 없이 `📊 *11월 2주차 캠페인 현황*` + `이번 주에 시작한 주차 캠페인이 아직 없어요.` + 링크 줄만 보낸다.
- 날짜, 주차 표기는 화면과 같은 함수(`weekLabel`, `formatDateKo`, `kstDateTime`)를 쓴다. 가운뎃점 구분자 금지.

**링크는 버튼이 아니라 글 링크** [판단]: 슬랙 버튼은 앱에 상호작용 응답 주소가 없으면 누를 때 경고 표시가 뜰 수 있다.

## 5. 이미지

시안 HTML(`docs/mockups/campaign-status-slack-20261113.html`)과 PNG가 모양의 기준이다. 간격, 글자 크기, 색은 그 파일 값을 그대로 옮긴다.

- **배치 폭 800px, 2배 해상도(1600px 폭)로 출력** [koo: 휴대폰에서 1200px는 글자가 작았다 → 800px 확정]. `ImageResponse`에는 배율 옵션이 없으므로 1600px 폭으로 그리고 시안의 모든 크기를 2배로 쓴다. 높이는 캠페인 줄 수에 따라 늘어난다(줄당 56px, 출력 112px).
- 맨 위: `11월 2주차 캠페인 현황`(`weekLabel(week.weekStart)`, 띄어 쓴 형태) + 오른쪽 `11/12 (수) 10:30 기준`. 기준 시각은 **보내는 순간**(한국 시각)이다. `formatDateKo`는 '11/12 수', `kstDateTime`은 '2026-11-12 10:30'을 주므로 조각을 이어 만든다.
- 네 칸 보조 글('캠페인 10개, 1개는 세팅 전', 늦은 클라이언트 목록, '예정일 미정 N건 포함')은 지금 `OverviewTiles.tsx` 안에서 만든다. 화면과 이미지, 메시지가 같은 말을 쓰도록 이 문구 만들기를 순수 함수로 옮기고 셋이 함께 쓴다 [판단].
- 네 칸을 2×2로: 계획 / 게시 완료(막대) / 예정일 지난 미게시(1건 이상이면 주황 칸) / 남은 게시 예정. 보조 글은 화면 상단 칸과 같은 규칙.
- 캠페인 줄: 이름, 상태 칩(화면과 같은 네 가지), 진행 막대, `5 / 8건`. **진행률순** [koo] = `sortCards(cards, 'progress')`, 세팅 전은 맨 뒤.
- 맨 아래 한 줄: `진행률(게시 ÷ 계획)이 높은 순이에요. 방문협찬(장기) 캠페인은 빠져 있어요.`
- 그리는 방법: Next 내장 `ImageResponse`(`next/og`)로 JSX를 PNG로 [koo: 2번]. 새 라이브러리 없음.
  - 한글 글꼴을 넘겨야 한다(기본 글꼴은 라틴 문자만). 형식은 TTF, OTF, WOFF만(WOFF2 불가).
  - `ImageResponse`는 묶음(JSX, 글꼴, 이미지 포함) 약 500KB 한도가 있고 한글 글꼴 전체는 그보다 크다. 글꼴은 실행 시점에 디스크에서 읽고(Vercel 출력 파일 추적에 글꼴 파일을 포함시킨다), 모듈 수준에서 한 번만 읽어 재사용한다. 필요한 글자만 잘라 주는 CDN을 쓰는 방법도 된다.
  - 화면의 앱 글꼴과 가깝게 보이는 한글 글꼴 하나(예: Pretendard 또는 Noto Sans KR, 굵기 400과 700/800)를 고른다 [구현자에게 맡김, 라이선스가 OFL 등 재배포 가능한 것].
  - satori는 CSS 그리드를 지원하지 않으므로 flex로 같은 모양을 만든다.

## 6. 보내는 흐름

1. **예약 실행:** `scripts/campaign-status-slack-cron.sql`(마이그레이션 아님, 다른 `scripts/*-cron.sql`과 같은 방식). pg_cron 4개 항목, UTC 기준:
   - 월요일 18:00 KST = `0 9 * * 1`
   - 수목금 10:30 KST = `30 1 * * 3,4,5`
   - 각 항목이 `net.http_post`로 `POST {app_url}/api/campaigns/overview/slack`을 부른다. 인증은 기존 예약 작업과 같은 `Authorization: Bearer <measure_cron_secret>`(앱 쪽 `MEASURE_CRON_SECRET`).
   - 스크립트 머리 주석에 실행법, 멈추는 법(`cron.unschedule`), 확인법을 적는다.
2. **라우트 `POST /api/campaigns/overview/slack`:** 시크릿 확인(미설정이면 거부, 기존 auto-send와 같은 fail-closed) → `getCampaignOverview(sql, null, today)` → 메시지 블록과 이미지 생성 → 슬랙 업로드와 전송. `maxDuration = 60`.
   - 채널은 환경 변수 `SLACK_STATUS_CHANNEL`(운영 `C0AD9E5HE1K`). 요청 본문 `{ "channel": "..." }`로 덮어쓸 수 있게 해서 테스트 채널로 보낼 수 있다. 덮어쓰기는 허용 목록(`C0AD9E5HE1K`, `C0CGWSFBDPV`)에 있는 채널만 받고 나머지는 거부한다(시크릿을 가진 호출만) [판단].
   - **예약 등록은 운영에만** 한다. 스테이징은 예약 없이 손으로 부를 때만 보낸다(테스트 채널에 주 4번 쌓이지 않게) [판단].
   - 이 라우트는 기존 예약 라우트처럼 로그인 확인을 거치지 않는다(`src/proxy.ts`는 `/api/*`를 로그인 화면으로 돌리지 않는다). 시크릿만으로 막는다.
3. **슬랙 업로드:** `files.getUploadURLExternal` → 받은 주소로 파일 POST → `files.completeUploadExternal`(채널 없이, 앱 소유 파일로) → `chat.postMessage`의 image 블록에 `slack_file: { id }`. 테스트에서 올린 직후 쓰면 처리 전일 수 있어 3초 기다렸고 성공했다. 구현은 고정 대기 대신 `invalid_blocks`면 짧게 몇 번 다시 시도하는 방식을 권한다.
4. **실패 처리** [판단]
   - 이미지 생성이나 업로드가 실패하면 이미지 블록 없이 글 메시지만 보낸다(팀이 상황은 알 수 있게).
   - 글 메시지까지 실패하면 응답에 오류를 담고 서버 로그에 남긴다. 자동 재전송은 하지 않는다(중복 발송 방지).
   - 응답 JSON에 보낸 채널, 메시지 시각(ts), 이미지 포함 여부를 담아 pg_net 응답에서 확인할 수 있게 한다.

**미리보기** [판단]: 로그인한 사람만 볼 수 있는 `GET /api/campaigns/overview/slack-image?week=`가 같은 PNG를 돌려준다. 스테이징 QA와 디자인 확인용.

## 7. 구조

- `src/lib/campaignStatusSlack.ts`: 순수 함수. `Overview` → 메시지 블록과 알림 글(`buildStatusMessage`), 이미지에 그릴 줄 데이터. 단위 테스트 대상(§4의 바뀌는 줄 전부).
- `src/lib/koreanHolidays.ts`: 공휴일 목록과 `holidayOn(date): string | null`.
- `src/lib/slackUpload.ts`: 봇 토큰으로 업로드와 전송(외부 호출). 이 앱에서 처음 쓰는 봇 토큰 연동이라 기존 `issueSlack.ts`(웹훅)와 분리한다.
- `src/app/api/campaigns/overview/slack/route.tsx` (POST), `.../slack-image/route.tsx` (GET 미리보기): `ImageResponse`로 그리는 JSX는 공용 컴포넌트 하나에서.
- `scripts/campaign-status-slack-cron.sql`
- 마이그레이션 없음. 새 환경 변수 `SLACK_STATUS_CHANNEL`(운영 `C0AD9E5HE1K`, 스테이징은 테스트 채널 `C0CGWSFBDPV`). 빌드에서 쓰지 않으니 민감 정보로 등록해도 된다.

## 8. 검증

- 단위 테스트: 메시지 블록(늦은 건 0건, 3곳 초과, 예정일 미정 0건, 세팅 전 없음과 여러 곳, 캠페인 0개), 진행률순, 공휴일 판단(대체공휴일, 목록 없는 해).
- 스테이징: 연습용 DB에 [QA] 캠페인을 넣고 미리보기 PNG를 시안과 나란히 비교 → 라우트로 테스트 채널에 한 번 보내 koo가 휴대폰에서 확인.
- 운영: 예약 등록 전에 라우트를 테스트 채널로 한 번 불러 실제 숫자로 확인 → koo 확인 뒤 예약 등록.
- 머지 직전 `src/content/updates.ts`에 한 건(새 기능).
- main push는 koo 지시가 있을 때만.

## 9. 구현자에게 맡기는 것

- 한글 글꼴 선택과 불러오는 방법(§5 조건 안에서).
- `invalid_blocks` 재시도 횟수와 간격.
- 슬랙 API 호출의 타임아웃 값(라우트 60초 안).
