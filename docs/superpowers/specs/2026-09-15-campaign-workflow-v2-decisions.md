작성: 2026-09-15 · 브랜치 `cb-koo/campaign-workflow-v2` · 상태: **grilling 완료 + Codex 코드 대조 리뷰 반영(09-15). 가안 항목은 정적 시안 후 확정**
방식: mattpocock `grilling` → `domain-modeling`(용어집 `CONTEXT.md`, ADR 0001~0005) → 이 문서 → 정적 HTML 시안 → 확정 → 구현 계획
근거: koo 손그림(2026-09-14, 캠페인 생성 → 정산 요청 8단계 + 유형별 작업 추가 순서) · 옛 시도(2026-09-03 스펙)는 **전제로 삼지 않음**

## 0. 문제와 방향

- **문제**: 8단계에 필요한 기능(칸)은 다 있다. 그런데 캠페인 하나를 실제로 처리하면 ① 만들고 → ② 작업 넣고 → (DM 조율) → ⑤⑥ 확인 → ⑧ 정산까지 가는 동안 **화면이 손을 끊는다.** 지금 프로덕트는 단계의 결과값을 적는 장부이고, 그림은 단계를 밟는 절차다.
- **방향**: **한 화면에서 전체 플로우를 처리하는 UX.**

## 3. 화면 (가안 — 정적 시안 후 확정)

```
■ 마인드스킨 9월 3주  9/15–9/21  마인드스킨 · 콘텐츠     [캠페인 정보]
──────────────────────────────────────────────────────────
② 작업 추가                                       [+ 작업 추가]
   RT 3 · 인용RT 2 · 투고 1   비용 ¥21,000
──────────────────────────────────────────────────────────
진행 중 6건          예정일 미정 1건 ↓         예정일 순 · 오늘 9/15
   투고   @hana   원고 전달됨   9/14 · 1일 지남   [게시됨] [···]   ← 빨강, 맨 위
   투고   @mika   원고 전달됨   9/15 오늘         [게시됨] [···]
   RT     @a      → @mika 투고  9/17 수           [게시됨] [···]
   RT     @b      → @mika 투고  9/17 수           [게시됨] [···]
   인용RT @kei    원고 초안 ⚠   예정일 미정 [날짜] [···]           ← 맨 아래, 일반 진하기
──────────────────────────────────────────────────────────
완료 2건                                정산 대기 1건 → 정산 페이지 →
   RT     @d      9/15 게시 · 증빙 ✓    정산 대기
   투고   @yui    9/13 게시             정산 요청됨 9/14
──────────────────────────────────────────────────────────
▸ 취소 1건
```

- **세 자리**: 진행 중 / 완료 / 취소(접힘). 예정일 확인·게시 확인은 섹션이 아니라 진행 중 행에서 하는 **행동**이다 — 작업의 상태 전이는 "만들어짐 → 게시됨(또는 취소)" 하나뿐이라 섹션을 더 나누면 같은 상태의 작업이 자리를 옮겨 다니는 것처럼 보인다(koo 09-14).
- **진행 중 정렬**: 지남(빨강) → 오늘 → 앞으로 → 예정일 미정. 미정은 연하게 하지 않고 헤더에 **"예정일 미정 n건"** 배지(클릭 → 그 행들로) — 날짜 없는 무응답 작업이 묻히지 않게(ADR 0001).
- **원고 부가 정보**: 상태 라벨 한 단어. 예정일이 임박했는데 전달 전이면 ⚠. RT엔 없음.
- `[···]` = 취소 · 인플 교체 · 원고 열기 · 삭제.
- **완료**: 게시일·증빙·정산 배지(기존). 헤더의 **정산 대기 n건**은 정산 페이지와 같은 조건(게시+비용+인플+활성 요청 없음)으로 센다 — 완료 건수와 다름. 대기 ≥1일 때만 링크(R15).
- **취소**: 펼치면 유형·인플·사유 칩·메모·"원고 있었음: 제목"·[되돌리기]·[삭제].
- 좌측 캠페인 목록·[새 캠페인]·헤더는 기존 부품(R12).

## 4. 작업 추가 팝업 (가안 — 순서는 그림, 칸 모양은 시안)

유형 세그먼트를 먼저 고르면 그 유형의 칸이 순서대로 나온다. 원고 자리는 라디오 3개 — **없음**(인플이 직접 씀) / **우리가 씀**(만든 직후 원고 시트가 열림, R13) / **있는 원고 고르기**. RT엔 원고 항목이 없다.

| 유형 | 순서 |
|---|---|
| 인용RT | 대상 → 인플 → 원고 → 비용 → 예정일 · 메모 |
| 투고 | 인플 → 원고 → 비용 → 예정일 · 메모 |
| RT | 대상 → 인플(여러 명) → 비용(사람별) → 예정일 · 메모 |
| 방문협찬 | **인플 → 일정(방문일 · 게시 예정일) → 예산 → 원고** → 메모 |

방문협찬만 사람·일정을 먼저 잡고 원고가 마지막 — 그림에 명시된 실제 순서.

## 5. 원고 시트 (가안 — 내부는 별도 스펙 R14)

- 자리: **오른쪽 사이드 시트**(진행 목록을 보면서 쓸 수 있게). LLM 생성·레퍼런스 탐색이 들어올 수 있음을 전제로 폭을 잡는다.
- 입구 셋: **생성 / 직접 쓰기 / 고르기**. (팝업 라디오의 "우리가 씀"이 이 시트를 연다 — 팝업은 "우리가 쓸지"를, 시트는 "어떻게 쓸지"를 묻는다.)
- 재료(생성 폼)는 `/generate`의 `DraftComposer` 전부(가안). 클라이언트·인플은 작업에서 채워지고 잠김.
- 시안 여러 개면 **하나를 골라 작업에 붙인다**(가안). **이것은 새 흐름이다** — 기존 `createDraft({taskId})`(`draftStore.ts:148`)는 첫 시안을 생성과 같은 트랜잭션에서 자동 부착하는 것이라 그대로 못 쓴다. 별도 스펙에서 "생성은 미부착으로, 선택 시 부착"을 설계한다.
- 손보기(다시쓰기·버전·번역·이미지·상태)는 `DraftCard` 그대로(확정).

## 6. 취소·교체 세부 (확정 — ADR 0002·0005 요약)

- **취소**: 게시 전만. `where posted_at is null and cancelled_at is null` 조건부 갱신 + DB check로 게시 확인과 상호 배제. 원고는 떼고 `cancelled_draft_id`·제목 스냅샷 보존. 되돌리기 3갈래(재부착 / 다른 작업에 갔음 안내 / 원고 없음) — 작업 복원은 항상 성공. 제외되는 비용은 작업 비용만, 인플별 추가 비용은 남음.
- **사유 칩**: 이모지+단어, 값은 영어. 슬랙 관례 ✏️ 원고확인 · 💰 지급 · ❌ 취소(완료 리액션 💰/✅/🤑) — **취소 행동은 ❌**. 거절·무응답 전용 이모지는 슬랙에 없음 → §8.
- **교체**: 게시 전·방문 전만. 비용 있으면 묻기. 원고 전달됨→사용 확정. RT 증빙 제거. 사유 선택.
- **로그**: `task_declined`는 사유가 `declined`·`no_response`일 때만, payload `{taskId, campaignId, campaignName, taskType, reason, action:'cancel'|'replace'}`. 인플 미배정 작업은 로그 없음. 되돌리기 정정 이벤트 없음(한계).
- **기존 화면의 게시 확인 경로**(수동·자동 조회·트래킹 연결)는 취소 작업을 건너뛰고 문구로 알린다.
