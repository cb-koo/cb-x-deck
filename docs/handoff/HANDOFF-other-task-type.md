# 인계 — 작업 유형 '기타 협찬' (ISSUE-002 + ISSUE-015), 2026-11-06

## 무엇을 왜
- ISSUE-002(koo): 게시글 업로드 없이 승인하는 작업 유형이 필요(예: 상담회 참석자).
- ISSUE-015(moeka): 방문협찬에 구글맵 리뷰 등 다른 매체 업로드 건이 있음 → 추가 필요.
- 공통: 지금 작업 유형 4개(post 투고, quoteRt 인용RT, rt RT, visit 방문협찬)가 전부 X 전제라 "X 게시물이 아닌 결과물"을 담을 곳이 없다.

## koo 결정 (11-06)
1. 새 작업 유형 **'기타 협찬'** 하나로 시작. 종류 목록은 미리 정하지 않고 **"무엇을 했는지" 한 줄 글**(예: 구글맵 리뷰, 상담회 참석).
   - 입력 시 **전에 쓴 말을 추천**(이름이 흩어지지 않게 — 나중에 옮길 때 기준이 된다).
2. 나중에 자주 쓰는 종류는 **별도 유형으로 분리**하고, 기존 '기타 협찬' 작업을 그 이름으로 골라 한 번에 옮긴다.
   - 이미 정산팀에 보낸 요청(payment_request 스냅샷)은 '기타 협찬'으로 남긴다(지급 기록 불변).
3. **순서: 스테이징까지 구현 → 정산팀 확인 요청 → 확인 후 운영 배포.**
   - 정산팀은 스테이징 폴링도 해 봤던 곳 — 스테이징에 '기타 협찬' 정산 요청 1건을 만들어 두고 실제 수신을 확인받는다.

## 설계 메모 (제안, 시안에서 koo 확인 필요)
- 완료 확인: 링크 있으면 링크(어느 사이트든), 없으면 날짜 + 메모로 [완료 확인]. X 작성자 확인·성과 자동 측정 대상 아님.
- 015처럼 방문협찬에 다른 매체 업로드가 붙으면 그 업로드를 '기타 협찬' 작업으로 하나 더(010의 "업로드 하나 = 작업 하나"와 같음).
- 정산: 금액 있으면 다른 작업처럼 후보·자동 전송. 링크 없는 건(상담회)은 009 링크 없는 게시처럼 메모(note)를 확인 자료로.
- '같은 주 함께 보내기'(010) 판정에도 포함되는지 확인(작업 날짜 = 완료일 → 예정일 → 캠페인 시작일).
