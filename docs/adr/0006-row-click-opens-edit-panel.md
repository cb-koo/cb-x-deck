# 표의 행을 누르면 오른쪽 편집 패널이 열린다 — 읽기 전용 세부는 두지 않는다

09-15에는 "작업 편집은 행 인라인 + 원고는 DraftCard 한 표면"으로 정하고, 별도 편집 패널은 편집 표면이 셋이 된다며 반대했다(Codex 리뷰 10번). 09-18에 실제 업무 순서가 드러났다 — **작업은 유형별 개수로 뼈대를 먼저 만들고, 빈 작업 8~14건에 인플·비용·원고·대상·예정일을 차례로 채운다.** 이 흐름에서는 한 작업의 모든 칸을 한 자리에서 보고 `이전/다음`으로 넘기는 연속 입력이 핵심이라, 셀 하나씩 인라인으로 고치는 방식(10건 × 5칸 = 50번 클릭)은 맞지 않는다.

그래서 **행 클릭 = 오른쪽 패널(폭 560)** 로 바꾼다. 패널은 작업 모드(칸 채우기)와 원고 모드(생성·직접 쓰기·고르기)를 오가는 **하나의 표면**이고, 새 작업 만들기(`+ 작업 추가`)도 같은 패널이 맡는다. 표 행은 값만 있는 한 줄로 유지되며 버튼이 없다. 행 클릭이 편집을 여니 **읽기 전용 행 펼침은 두지 않는다** — 대상·방문일·증빙·메모는 패널에서 본다.

편집 표면이 늘어나는 문제는 이렇게 막는다: 표 셀은 편집하지 않는다(값만), 원고 본문 손보기는 여전히 `DraftCard`, 취소·교체·게시 확인은 액션 라우트 하나씩. 패널은 그것들을 **여는 자리**이지 두 번째 편집 규칙이 아니다.

## Considered Options

- 셀 인라인 편집(09-15 결정) — 뼈대→채움에서 클릭이 너무 많고, 원고·대상처럼 칸이 큰 값이 셀에 안 들어간다.
- 행 펼침(아코디언)을 편집 폼으로 — 표 안에서 해결되지만 펼친 행이 커져 "행 하나 = 한 줄" 원칙(koo)과 충돌.
- 오른쪽 패널(채택).

## Consequences

- 옛 작업 추가 팝업(한 작업의 모든 칸을 한 번에)은 폐기된다. 팝업의 유형별 칸 순서 결정은 패널 칸 순서(인플 → 비용 → 원고 → 대상 → 예정일, 방문협찬은 인플 → 일정 → 예산 → 원고)로 승계된다.
- 패널이 열린 동안 표는 어둡게 깔리고, 행 클릭으로 다른 작업으로 전환한다. 패널에서 고친 값은 표에 즉시 반영된다.
