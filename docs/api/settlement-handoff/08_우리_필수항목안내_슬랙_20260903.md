# 결제 요청 필수 항목 안내 (우리 → 정산 프로덕트, 슬랙용) — 2026-09-03

> 아래 그대로 붙여넣기. 근거: `src/lib/settlementCalc.ts`(assessReadiness·effectiveIssues), `settlementStore.createRequests`, 명세 `settlement-external-api.md` §5.

---

안녕하세요, 저희 쪽에서 **어떤 값이 없으면 결제 요청 자체가 만들어지지 않는지** 정리해 드립니다. 요청 목록(`GET /requests`)에 내려가는 아이템은 아래 항목이 **항상 채워져 있다고 보셔도 됩니다.** 9/2 배포부터 적용됐고, 그 전에 만들어진 요청은 소급하지 않습니다.

*1. 요청이 만들어지려면 반드시 있어야 하는 것(없으면 저희 화면에서 빨간 신호로 막혀 요청 불가)*
• `influencer.id` / `influencer.handle` — 인플루언서가 저희 명부에 있어야 합니다.
• `payment_method` — 계좌·PayPal·PayPay 중 하나가 등록돼 있어야 합니다. `type`·`holder`(수취인)·`currency`는 항상 있습니다.
• `clinic.id` / `clinic.name` — 캠페인에 클라이언트(병원)가 연결돼 있어야 합니다.
• `category.code` / `category.label` — 분류를 골라야 합니다.
• `amount_krw`·`payout.*`(net·fee_amount·gross·gross_krw·currency·rate) — 작업에 비용이 있어야 후보에 오르고, 금액은 저희가 계산해서 채웁니다.
• `deadline` — 기본값이 채워지고 날짜 형식을 검증합니다.
• `item`·`purpose`·`requester.name` — 저희가 자동 생성합니다.
• **`proof` — `task_type == "rt"`일 때 필수.** 증빙 스크린샷이 없는 RT는 9/2부터 요청을 만들 수 없습니다. 따라서 **새 요청에서 `rt` + `proof == null` 조합은 나오지 않습니다.**
• **`reference_url` — `task_type`이 `post`·`quoteRt`·`visit`일 때 필수.** 인플루언서 본인 게시물 링크입니다. 9/2부터 이 유형은 링크 없이 요청을 만들 수 없습니다.

*2. 비어 있을 수 있는 것(요청은 만들어집니다)*
• `reference_url` — `task_type == "rt"`일 때. RT는 새 게시물이 없어 클리닉 원본 트윗이 들어가거나 비어 있을 수 있습니다. RT의 확인 자료는 `proof`입니다.
• `proof` — `rt`가 아닌 유형일 때. 이 유형의 확인 자료는 `reference_url`입니다.
• `payment_method.identifier` — PayPay 수취 식별 정보. 아직 정책이 정해지지 않아 비어 있을 수 있습니다. 정해지면 다시 안내드리겠습니다.
• `campaign.id`·`task_id` — 캠페인·작업이 나중에 삭제된 경우에만 `null`(드묾).
• `cancelled` — 취소된 요청에만 값이 있습니다.

*3. 정리*
유형별 확인 자료는 이렇게 보시면 됩니다.
• `rt` → `proof.url`(항상 있음)
• `post`·`quoteRt`·`visit` → `reference_url`(항상 있음)

9/2 이전에 만들어진 요청 중에는 RT인데 `proof`가 없거나 링크가 빈 것이 남아 있을 수 있습니다. 그 건들은 지금처럼 보류로 돌려보내 주시면 저희가 채워서 다음 폴링에 반영되게 합니다.
