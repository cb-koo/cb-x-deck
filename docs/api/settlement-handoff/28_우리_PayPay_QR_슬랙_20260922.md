# 우리 통지 (우리 → 정산 프로덕트, 슬랙용) — 2026-09-22 PayPay QR 이미지 지원

> 아래 그대로 붙여넣기. 첨부: `settlement-external-api.md` 현재 판(§5 `payment_method.qr_url` 행, **§4-2 신설**, §6-1 허용 키에 `qr` 추가, §8 개정 기록).

---

PayPay로 받는 인플루언서 중 수취 식별값(계좌·전화번호 같은 문자열)이 아니라 **QR 이미지만** 주는 경우가 있어, 그 QR을 API로 함께 보내드립니다. **추가만 하는 변경**이라 그쪽 코드가 지금 그대로여도 아무것도 깨지지 않습니다.

*1. 아이템에 필드 하나가 늘었습니다*
```json
"payment_method": {
  "type": "paypay",
  "holder": "다나카",
  "currency": "JPY",
  "qr_url": "https://cb-x-deck.vercel.app/api/external/settlement/requests/<request_id>/payment-qr"
}
```
`identifier`(수취 식별값)와 `qr_url`은 **둘 중 하나만 있어도 되고 둘 다 있을 수도 있습니다.** `qr_url`이 없으면 그 인플루언서는 QR을 등록하지 않은 것입니다 — 이 경우 값은 `null`이 아니라 **키 자체가 없습니다**(다른 선택 필드와 같은 규칙).

*2. QR 이미지 내려받기*
```
GET /api/external/settlement/requests/{request_id}/payment-qr
Authorization: Bearer <지금 쓰시는 그 운영 키>
```
• 200 — 이미지 바이트(`Content-Type: image/jpeg` | `image/png` | `image/webp`)
• 404 — 요청이 없거나, QR이 등록되어 있지 않거나(가장 흔함), 등록됐는데 저장소에서 못 찾는 경우(드묾) — 셋 다 같은 404(본문 없음)
• 401 — 키 불일치(본문 없음)

증빙(`proof.url`, handoff 07)과 같은 방식입니다 — 주소는 **고정**이고 서명 URL이 아니라 만료되지 않습니다. `payment_method.qr_url`이 항상 이 주소이므로 캐시해 두셨다가 나중에 여셔도 그대로 열립니다.

*3. QR을 고치거나 지울 때 — 수취 정보 정정 API(§6-1, handoff 26)에 `qr` 키 추가*
결제 정보 정정(`POST …/payment-info`)의 `payment_method`에 `qr` 키를 함께 쓸 수 있습니다. 다른 6개 키(`holder`·`paypal_id`·`email`·`identifier`·`bank`·`branch`·`account`)와 값 형식이 다릅니다.
• **data URI(base64)로 보내 주세요** — 예: `"qr": "data:image/png;base64,iVBORw0KG..."`. **외부 URL(예: `https://...`)은 받지 않습니다.**
• 상한 **5MB**, 형식 **JPG·PNG·WebP**만.
• **`null`로 보내면 QR이 지워집니다**(잘못 올린 QR을 되돌리는 방법입니다).
• 반영되면 다른 정정과 똑같이 저희 인플루언서 명부(원본)에도 함께 반영되고(handoff 27), 다음 요청부터 새 QR이 나갑니다.

*4. 지금 보이실 상태*
아직 QR로만 받는 운영 데이터가 없어서 당분간 `qr_url`은 안 보이실 겁니다. 다음 PayPay 정산 요청 중 QR 등록된 인플루언서 건부터 채워집니다.

명세 전문은 `settlement-external-api.md`에 반영해 두었습니다(§4-2 QR 엔드포인트, §5 Item의 `payment_method.qr_url`, §6-1 정정 허용 키).
