# 초안 일괄 처리 · 제목 수정 · 스레드 칸 편집 설계

작성일 2026-08-13

## 배경

/generate 워크벤치에 원고가 쌓이면서 세 가지가 막힌다.

1. **정돈이 한 건씩만 된다.** 삭제·상태 변경·인플루언서 배정 모두 개별 초안 단위로만 있다. 쓸모없는 시안 여러 개를 치우려면 카드를 하나씩 열어 지워야 한다.
2. **목록에서 원고를 이름으로 못 고른다.** 표·칸반의 항목 라벨은 생성 시 자동으로 붙은 한국어 제목(`ko_title`)인데, 사람이 못 고친다. 게다가 본문을 편집하면 저장된 제목의 해시가 최신 본문과 어긋나 **제목이 사라진다**(`draftStore.ts` `toRow`의 `ko_title_hash === latestHash` 검사). 손을 댄 원고일수록 목록에서 이름을 잃는다.
3. **스레드 칸을 손으로 못 늘린다.** 편집 모달이 생성 시점의 포스트 개수를 고정으로 잡아(`DraftEditModal.tsx`의 `base.posts.map`) 칸을 추가·삭제할 수 없다. 단문으로 나온 걸 스레드로 마무리하려면 재생성뿐이다.

세 가지 모두 "재생성 없이 손으로 마무리하고, 쌓인 원고를 정돈한다"는 워크벤치의 방향에 속한다.

## 범위

**포함** — 표 뷰 다중 선택 후 일괄 삭제·상태 변경·인플루언서 배정 / 제목 직접 수정 / 스레드 칸 추가·삭제

**제외** — 초안 링크 팀원 공유(별도 논의). 클라이언트·시술 속성 변경(원고가 그 정보를 근거로 생성되므로 사후에 바꿀 이유가 없다는 사용자 판단). 방향성·참고 레퍼런스 수정(생성 근거 스냅샷이고, 방향성은 현재 화면 어디에도 표시되지 않아 고쳐도 보이는 게 없다).

## 확정 판단

### A. 사람이 붙인 제목은 자동 제목과 다른 컬럼에 둔다

`draft.title text` 컬럼을 새로 추가한다. 기존 `ko_title`/`ko_title_hash`는 그대로 둔다.

한 컬럼에 합치면 안 되는 이유: `ko_title`은 **최신 본문 해시와 일치할 때만** 표시되는 값이다(낡은 자동 제목을 숨기는 장치). 사람이 붙인 제목은 정반대로 본문을 고쳐도 살아남아야 한다. 같은 컬럼에 두면 이 두 규칙이 한 값에 동시에 걸린다.

목록 라벨 폴백 체인(`draftViews.ts`의 `draftLabel`)이 4단이 된다:

```
title (사람이 붙임, 해시 검사 없음)
  → ko_title (자동, 해시 일치 시에만)
    → 한국어 대역 첫 줄
      → 원문 첫 줄
```

부수 효과로 배경 2의 "편집하면 제목이 사라진다"가 해소된다 — 제목을 한 번 붙이면 영구히 남는다.

다시쓰기·재생성은 지금처럼 `ko_title`만 갱신한다(`generate.ts`). `title`이 있으면 라벨은 그대로 유지된다 — 사람이 지은 이름을 AI가 덮지 않는다.

### B. 일괄 처리는 컬렉션 라우트에서 단일 쿼리로 한다

개별 `PATCH /api/drafts/[id]`를 N번 병렬로 쏘지 않는다. 50건 선택 시 커넥션 50개가 동시에 붙는데, 이 저장소는 이미 커넥션 고갈로 "트윗 없음" 회귀를 겪은 적이 있다.

새 라우트 둘:

- `PATCH /api/drafts` — 본문 `{ ids: string[], status?: DraftStatus, influencerHandle?: string | null }`
- `DELETE /api/drafts` — 본문 `{ ids: string[] }`

둘 다 `requireMember()` 게이트. `draftStore`에 `updateDraftsBulk` / `removeDraftsBulk`를 추가하고 `where id = any(${ids})` 한 번으로 처리한다.

**서버에서도 ids 상한 100을 건다.** 목록이 최근 50건까지만 오므로 UI에서 50을 넘길 수 없지만, 라우트는 UI를 신뢰하지 않는다. 빈 배열·비 UUID는 400.

`influencerHandle`의 정규화 규칙은 단건 라우트와 같다: `undefined` = 건드리지 않음, `null`·공백 = 배정 해제, 그 외 = `parseXHandle`. 단건 라우트의 검증 블록을 공용 함수로 빼서 두 라우트가 같은 것을 쓴다(드리프트 방지).

### C. 선택은 표 뷰에만 둔다

카드 뷰에 체크박스 오버레이를 얹으면 X 타임라인 미러링이 깨진다(이 저장소가 제품 가치로 지켜온 것). 칸반은 드래그가 이미 상태 변경 수단이라 선택 제스처와 충돌한다. 표는 애초에 트리아지용으로 만든 뷰라(`DraftTable.tsx` 상단 주석) 다중 선택이 붙을 자리다.

일괄 처리를 하려면 표 뷰로 전환해야 하지만, 툴바에 뷰 전환이 이미 있어 마찰은 작다.

### D. 칸 추가·삭제는 이미지와 같은 즉시 저장이다

편집 모달은 텍스트를 "저장" 버튼으로, 이미지를 즉시 저장으로 처리하고 둘이 같은 `edited` JSON을 쓴다. 이미지 PATCH가 미저장 텍스트를 실어 보내지 않도록 `savedTexts`를 따로 들고 있는 구조다.

칸을 추가·삭제하면 텍스트 배열과 미디어 배열의 **길이가 동시에** 바뀐다. 이걸 "저장 버튼 누를 때 반영"으로 두면, 저장 전에 새 칸에 이미지를 붙이는 순간 `savedTexts`(옛 길이)와 `media`(새 길이)가 어긋난 채로 PATCH가 나간다.

그래서 칸 추가·삭제는 그 시점에 `texts` 전체를 함께 저장한다. 사용자에게는 "칸을 넣거나 빼면 그 자리에서 저장된다"가 된다. 이미지 첨부가 이미 같은 방식이라 모달 안에서 일관된다.

### E. 칸 수가 바뀌면 `format` 컬럼도 함께 갱신한다

**표시 라벨만 파생시키는 것으로는 부족하다.** `format`은 생성 조건의 기록이기만 한 게 아니라 다시쓰기의 **입력으로 재사용된다**:

- `generate.ts`의 다시쓰기가 `format: draft.format`을 프롬프트에 넣는다
- 같은 함수가 `if (draft.format === 'single') posts = posts.slice(0, 1)`로 결과를 자른다

즉 단문 초안에 칸을 3개로 늘려놓고 다시쓰기를 누르면 **사용자가 붙인 칸이 조용히 사라진다.** 표시만 고치면 이 동작은 그대로 깨진 채 남는다.

따라서 `edited`가 들어오는 PATCH에서 `format`을 `posts.length > 1 ? 'thread' : 'single'`로 함께 갱신한다. 그러면 컬럼이 항상 실제 형태와 일치하므로 표시 파생 로직도 따로 필요 없고(`DraftCard`·`DraftTable`·`DraftKanban` 세 곳 그대로), 다시쓰기의 slice도 옳게 동작한다.

**클라이언트가 `format`을 보내지 않는다.** 단건 라우트가 `edited.posts.length`에서 직접 파생한다. 클라이언트가 보낸 값을 믿으면 텍스트와 형식이 어긋난 요청을 저장할 수 있고, 그 어긋남은 다시쓰기에서 원고 손실로 나타난다. 다시쓰기 경로는 이미 자기 `format`에 맞춰 slice한 결과를 저장하므로 같은 규칙을 적용해도 값이 변하지 않는다.

`reference_mode`·`refs`·`direction`·`client_id` 같은 나머지 생성 조건은 계속 불변이다. `format`만 예외인 이유는 그것만이 "지금 이 원고가 어떤 모양인가"를 겸하고 있기 때문이다.

### F. 형제 시안 일괄 배정은 막지 않고 경고한다

`draftStore.ts`의 `influencerHandle` 주석에 명시된 원칙이 있다: *"배정 단위는 시안 하나(행)다 — 형제 시안 셋 다 배정하면 '원고 3개를 줬다'가 되어 사실과 어긋난다."* 표에서 A/B/C를 전부 골라 한 명에게 배정하면 정확히 그 상황이 만들어진다.

금지하지는 않는다. 상태 축이 전이 제약을 두지 않은 것과 같은 이유로(검수 생략 등 모든 경로를 수용) 일괄 배정도 사람이 결정할 몫이다. 대신 실행 전에 사실을 알린다:

> 같은 조건에서 나온 시안 3개가 함께 선택돼 있어요. 셋 다 같은 분께 배정하면 원고 3개를 전달한 것으로 기록됩니다. [그래도 배정] [취소]

판정은 선택된 초안들의 `batchId`를 세어 같은 값이 2개 이상이면 띄운다. `batchId`가 `null`인 단일 생성 초안들은 서로 형제가 아니므로 세지 않는다.

### G. 삭제 실행취소는 페이지를 떠날 때 확정한다

현재 단건 삭제는 낙관적 제거 + 5초 뒤 서버 DELETE다(`page.tsx`의 `requestRemove`). 그런데 그 5초 타이머에 **언마운트 정리가 없다.** "삭제했어요" 토스트를 보고 사이드바로 이동하면 서버 요청이 영영 나가지 않고, 새로고침하면 지운 초안이 살아 있다.

지금도 있는 결함이지만 일괄 삭제에서는 30건 규모가 되므로 이번에 함께 고친다. 언마운트 cleanup과 `beforeunload`에서 pending을 확정한다(`sendBeacon`이 아니라 일반 fetch — 언마운트 경로가 주된 경우이고, 탭 종료는 다음 방문 시 목록에 다시 보이는 것으로 족하다).

일괄 삭제도 같은 5초 실행취소를 쓴다. `pendingRemove`를 단일 행에서 배열로 일반화하면 단건이 길이 1인 특수 케이스가 되어 코드가 오히려 줄어든다.

## 화면

### 표 뷰 — 선택과 액션 바

체크박스 열을 맨 왼쪽에 추가한다. 행 클릭은 지금처럼 카드 열기이고, 체크박스 셀은 `stopPropagation`으로 차단한다(상태 칩 셀이 이미 쓰는 방식).

헤더 체크박스는 **현재 화면에 보이는 것 전체**를 고른다. 필터·검색이 걸려 있으면 걸린 것만이다. 필터·검색·기간이 바뀌면 선택을 비운다 — 안 보이는 것이 선택에 남아 함께 지워지는 사고를 막는다. 뷰를 카드·칸반으로 바꿔도 비운다.

하나라도 고르면 표 하단에 액션 바가 붙는다:

```
3개 선택됨   [상태 변경 ▾] [인플루언서 ▾] [삭제]   선택 해제
```

- 상태 변경: 기존 `DraftStatusChip`과 같은 5개 값
- 인플루언서: 기존 `InfluencerChip`의 후보 목록 + 배정 해제. 실행 전 F의 형제 시안 경고
- 삭제: 확인 다이얼로그 없이 즉시 낙관적 제거 + 실행취소 토스트("원고 3개를 삭제했어요 / 실행 취소"). 단건과 같은 무게로 다룬다

낙관적 갱신 실패 시 롤백은 단건 `changeStatus`의 조건부 롤백을 그대로 쓴다 — 이 요청이 세팅한 값이 아직 표시 중일 때만 되돌린다.

실행 후 선택은 이렇게 다룬다: **상태 변경·인플루언서 배정은 선택을 유지**한다(같은 묶음에 상태와 담당자를 연달아 지정하는 게 실제 흐름이다). **삭제는 선택을 비운다** — 지운 것을 계속 고른 상태로 둘 이유가 없다. 실행취소로 되살아나면 선택되지 않은 상태로 돌아온다.

### 편집 모달 — 제목

✕ 줄 아래에 제목 입력 한 줄을 둔다. 비어 있으면 현재 목록에 나오는 라벨(자동 제목 또는 첫 줄)을 흐린 placeholder로 보여준다. "지금 목록엔 이렇게 나오고 있고, 여기 쓰면 이 이름으로 바뀐다"가 한 자리에서 보이도록.

제목은 텍스트 "저장" 버튼과 함께 저장된다(같은 PATCH). 단건 라우트에 `title` 필드를 추가한다.

표에 인라인 편집은 넣지 않는다 — 행 클릭이 이미 카드 열기라 충돌한다.

### 편집 모달 — 칸 추가·삭제

렌더 루프를 `base.posts.map`에서 `texts.map`으로 바꾼다. 칸마다 삭제 버튼, 마지막 칸 아래에 "칸 추가".

- 칸이 1개면 삭제 버튼을 숨긴다(0칸 원고는 저장 불가 — 서버도 `posts.length === 0`을 이미 400으로 막는다)
- **이미지가 붙은 칸을 지울 때만** 확인을 받는다("이 칸의 이미지 2장도 함께 빠집니다"). 텍스트만 있는 칸은 확인 없이 지운다 — 편집 저장과 같은 무게다
- 스토리지 객체는 지우지 않는다. 버전 이력이 과거 버전의 media를 참조하므로(024 마이그레이션의 기존 판단 그대로)
- '원본과 비교' 모드는 `draft.content.posts[i]`를 읽는데 새로 추가한 칸은 원본이 없다. 그 자리에 "새로 추가한 칸 — 생성 원본 없음"을 표시한다

## 구현 순서

1. 마이그레이션 025 — `draft.title` 추가
2. `draftViews.draftLabel` 폴백 체인 확장 + 단위 테스트
3. `draftStore` — `title` 읽기/쓰기, `updateDraftsBulk`·`removeDraftsBulk` + 실 DB 테스트
4. 컬렉션 라우트 `PATCH`/`DELETE /api/drafts` + 단건 라우트에 `title` 필드, 인플루언서 검증 공용화
5. 표 뷰 선택 + 액션 바 (선택 상태 계산은 순수 함수로 분리해 단위 테스트)
6. 삭제 실행취소 배열 일반화 + 언마운트·이탈 flush
7. 편집 모달 제목 입력
8. 편집 모달 칸 추가·삭제 + `format` 갱신

## 검증

- **순수 함수 단위 테스트**(`tsx`로 수초): `draftLabel` 4단 폴백, 선택 상태 계산(전체 선택/부분 선택/필터 변경 시 초기화), 칸 추가·삭제 배열 변환, `format` 파생 규칙, 형제 시안 경고 판정
- **실 DB 테스트**(`draftStore.test.ts`, `npm test` 약 4분): 일괄 update/delete, `title` 왕복
- **하네스 없음**: 라우트·컴포넌트는 테스트 하네스가 없다. 화면 확인은 배포 후 사용자가 직접 본다(구글 OAuth 도메인 게이팅으로 개발자가 화면에 접근할 수 없음)
- **린트 기준선**: 기존 경고 24개. 새 경고를 늘리지 않는다

## 열린 항목

- 초안 링크 팀원 공유는 이번 범위 밖. 사내 로그인 사용자용 딥링크(`/generate?draft=<id>`)냐 비로그인 공개 링크(공유 토큰 + `proxy.ts` 공개 경로 + service_role 서버 서명)냐에 따라 규모가 크게 갈리므로 별도 설계로 다룬다
- 방향성(`direction`)은 저장되지만 화면에 표시되지 않는다. 표시할 자리가 생기면 그때 수정 가능 여부를 다시 본다
