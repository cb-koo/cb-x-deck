# 캠페인 워크플로 화면은 새 페이지("캠페인 v2")로 만들어 기존 캠페인 페이지와 병존시킨다 — 병존의 조건은 같은 판정 규칙

기존 `/campaigns` 상세(요약 카드·작업 표·주간 달력·인플별 비용 표)는 8단계 업무의 **결과값을 기록하는 장부**이고, 새 화면은 그 단계를 **순서대로 밟는 절차**다. 둘의 구조가 달라 상세 영역을 제자리에서 고치면 병존 기간에 두 구조가 한 화면에 섞인다. 새 페이지 `/campaigns/flow`를 사이드바 "캠페인" 아래 "캠페인 v2"로 두고, 자리를 잡으면 "캠페인"이 이 화면을 가리키게 바꾸고 옛 상세를 지운다.

**핵심은 URL이 아니라 데이터 계약이다.** 두 화면이 같은 `campaign_task`를 다루므로, 한쪽이 취소한 작업이 다른 쪽에서 "예정"으로 되살아나 합계·밀림에 들어가면 병존은 실패다. 그래서 병존의 필수 조건은:

1. **판정 함수가 하나** — `taskStage`에 `cancelled`(최상위)가 들어가고, 집계 제외 조건(`isTaskExcluded` = 취소)을 요약·유형 소계·인플별 합계·달력·캠페인 목록 SQL(`task_count`·통화별 합계)이 공통으로 쓴다. 미사용 원고 제외 규칙은 폐지된다(ADR 0002).
2. **기존 화면도 취소를 안다** — 표에 흐린 글씨 + '취소됨' 칩, 편집 불가. 새 개념을 보여주기만 하고 조작은 v2에서.
3. **칸 편집 부품과 동작이 하나** — 예정일·비용·대상·인플루언서·게시 확인·증빙 편집, 캠페인 목록·생성·헤더는 기존 부품 재사용. 인플루언서 교체는 공용 훅의 한 동작(ADR 0005)으로 두 화면이 같이 쓴다.

요약 카드·달력·인플별 비용 표는 새 화면에 가져오지 않는다(무엇이 그리웠는지 보고 대체 시점에 결정).

## Considered Options

- 상세 영역 제자리 교체 — 병존 불가, 실사용 검증 전에 옛 화면이 사라진다.
- 기존 상세에 "흐름 보기" 탭 추가 — 한 화면 안에서 두 구조가 경쟁한다.
- 새 페이지 병존(채택) — 사용자 2~5명이라 "새 화면 써보세요"를 직접 말할 수 있다.

## Consequences

- 2026-09-03 시도(`cb-koo/campaign-workflow`, `/campaigns/preview` 읽기 전용 + shadcn)는 이 결정의 전제가 아니다. 그 브랜치는 참고용으로만 남았다가 삭제된다.
- "기존 캠페인 페이지는 손대지 않는다"가 **아니다** — 판정·집계·취소 표시는 손댄다. 손대지 않는 것은 명부·결제 수단·트래킹 화면·성과·리포트·정산 연동·`/generate`. 트래킹 스토어의 취소 작업 연결 거절(ADR 0002)은 예외.
