# 인플루언서 조율 상태를 저장하지 않는다 — 진행이 기본값, 예외만 기록

인플루언서 섭외·조율은 X DM에서 일어나고 도구 밖이다. 작업이 "요청 전 / 요청 보냄 / 확정 / 거부" 어디에 있는지를 도구가 알려면 사람이 DM에서 한 일을 다시 적어야 한다. 캠페인 계획은 진행을 전제로 세우므로, **작업은 만들어지면 진행 중이고, 진행이 안 됐을 때만 취소(사유 선택 입력) 또는 교체로 기록한다.** 확정을 찍는 칸은 두지 않는다.

## Considered Options

- **확정 체크 1개** — 확정 안 된 작업이 눈에 보이지만, 흔한 경우(진행)에 클릭이 든다.
- **요청 보냄/확정/거부 3상태** — 거절 이력이 남지만 사람마다 2번 적어야 해 지켜지지 않을 확률이 높다.
- **예외만 기록(채택)** — 흔한 경우 입력 0.

## Consequences

- **한계를 그대로 안는다**: '진행 중'은 상대가 하겠다고 했다는 뜻이 아니다. 무응답 작업은 사람이 취소·교체하기 전까지 진행 중과 구분되지 않는다. 이 한계는 나중에 복구할 수 없다(기록하지 않은 정보는 없다) — 그래서 ADR로 남긴다.
- 그 대신 화면이 해야 할 일: 예정일 지남·오늘을 위로 띄우고, **예정일 미정 작업은 따로 세어 보이게** 한다(날짜 없는 무응답 작업이 묻히지 않게). 날짜 정하기·취소·교체는 그 행에서 바로.
- 그림의 ⑦ "작업 완료/미완료 처리"는 별도 기능 없이 이 결정으로 덮인다 — 작업의 끝은 게시 확인(완료) 또는 취소(미완료·사유).
- 거절·무응답 사실은 인플루언서 타임라인(`influencer_log`)에 남긴다. 작업 화면에서는 취소된 행의 사유 칩으로만 보이고, 교체로 빠진 사람의 사유나 인플루언서별 누적은 타임라인에서만 본다.
