# X 전용 확장 프로그램 제공 정보와 추가 구현 계획

작성일: 2026-10-02

대상: X에서 콘텐츠를 찾고 인플루언서에게 연락하며 캠페인을 운영하는 콘텐츠 기획 담당자

**추천 방향은 X를 보면서 계정 정보를 확인하고, 게시물을 보관함에 저장하고, 대화를 번역하고, 협업 기록을 남기는 확장 프로그램이다.** `CB Translate 1.13.2`의 DM 번역과 업무 패널을 참고하되, 타임라인·게시물 상세·프로필까지 지원 범위를 넓힌다. 콘텐츠와 캠페인 업무는 현재 `cb-x-deck`의 기능을 연결하는 편이 중복 개발을 줄인다.

첫 버전은 **계정 요약 조회, 게시물 저장, 요청한 내용의 번역, 연락 메모**에 집중하는 것을 제안한다. 이후 계정 분석, 원고 작성, 캠페인 연결, 대화 요약을 추가한다. 다음 내용은 제공 가능한 정보와 개발 제안이며, 신규 확장이 구현되었다는 의미는 아니다.

## 1 검토 범위와 현재 상태

로컬의 다음 두 프로젝트를 확인했다. 구현 여부는 문서 설명보다 실제 소스와 API 라우트를 우선했다. 실제 X 화면에서의 동작, 운영 서버 응답, 외부 API 계정의 사용 권한은 이번 문서 작성에서 실호출로 검증하지 않았다.

| 대상 | 확인한 역할 | 새 확장과의 관계 |
| --- | --- | --- |
| `x_managing/cb_translate 1.13.2` | LINE·Instagram·X 대화 번역, X 인플루언서·협찬 업무 보조 | X 화면 감지·번역·패널의 참고 구현 |
| `CB_LINE_MANAGE/cb-x-deck` | X 리서치, 보관함, 원고, 인플루언서 명부, 캠페인, 게시물 성과, 정산 | 콘텐츠·캠페인 기능의 재사용 후보 |

기존 확장의 `manifest.json` 버전은 **1.13.2**다. X 콘텐츠 스크립트는 `/i/chat`, `/i/chat/*`, `/chat/*`에 연결되어 있다. `host_permissions`에 `x.com/*`가 있다고 해서 타임라인과 프로필 기능까지 구현된 것은 아니다. 현재는 **X DM 중심 확장**으로 보는 것이 맞다. [확장 등록 설정][E1]

기존 확장이 인플루언서·협찬 업무에 사용하는 서버는 **`x_tracker`**다. `cb-x-deck`과 같은 서비스라고 가정하면 안 된다. 특히 기존 확장은 `X-CB-Token` 헤더를 사용하는 반면, `cb-x-deck`의 일반 업무 API는 Supabase 로그인 세션을 확인한다. 기존 API 주소만 바꾸는 것으로는 연결되지 않는다. [기존 API 클라이언트][E2], [현재 인증 가드][D1]

## 2 기존 확장에서 가져올 수 있는 기능

아래의 ‘구현됨’은 로컬 코드에 해당 동작이 있다는 뜻이다. 새 확장에 그대로 복사해도 동작한다는 보장은 아니며, X의 현재 화면과 연결 서버에 맞춘 이식 작업이 필요하다.

| 기존 기능 | 소스에서 확인한 내용 | X 전용 확장에서의 처리 |
| --- | --- | --- |
| 수신 DM 번역 | 메시지별 번역 버튼, 자동 번역 선택, 번역 표시 복원 | 버튼 번역을 기본으로 이식하고 게시물 번역까지 확대 |
| 발신 DM 번역 | 입력문을 번역한 뒤 X의 전송 동작 실행, 실패 시 원문 복원 | 처음에는 번역 미리보기와 입력창 반영을 제공 |
| 빠른 메시지 | 플랫폼별 문구 조회, 즐겨찾기, 대화 상대 정보 치환 | X용 템플릿만 제공하고 저장 서버를 정리 |
| 인플루언서 패널 | 등록 여부, 계정 정보, 메모, 표준 단가, 협찬 이력 조회·편집 | `cb-x-deck` 명부와 연결하거나 `x_tracker` 정보를 구분해 표시 |
| 인박스 배지 | 등록·협찬 상태, 단가, 정보 누락 표시 | 동일인 확인을 강화한 뒤 적용 |
| 방문·콘텐츠 협찬 | 예약 입력, 텍스트에서 예약 정보 추출, 상태 변경 | `x_tracker` 연동을 유지할 경우 이식 가능 |
| 요청자료와 결과자료 | 협찬 안내, 게시물 URL, 이미지 첨부, 메모 편집 | 콘텐츠 캠페인과 방문협찬의 저장 대상을 구분 |
| 마지막 연락일 | DM 전송 경로에서 연락일 저장 시도 | 전송 성공과 연락 기록의 기준을 다시 정의 |
| 패널 편의 기능 | 접기·펼치기, 표시명 복사, 대화 맨 위 이동 | 필요한 기능을 선별 이식 |

근거: [수신 메시지 처리][E3], [발신 메시지 처리][E4], [인플루언서 패널][E5], [빠른 메시지 데이터][E6], [협찬 등록][E7], [요청자료][E8], [결과자료][E9].

특히 다음 네 가지는 새 확장으로 옮길 때 함께 개선해야 한다.

1. **표시명만으로 사람을 확정하지 않는다.** 기존 코드에는 표시명으로 조회하는 경로가 있다. 동명이인·닉네임 변경에 대비해 X 사용자 ID를 우선하고, 확인된 핸들을 보조 식별자로 쓴다. 표시명만 보이면 후보를 제시하고 사용자가 연결하게 한다.
2. **연락일은 기록의 종류와 일치시킨다.** 기존 발신 코드에는 실제 전송 버튼을 누르기 전에 연락일을 저장하는 경로가 있다. 새 확장은 ‘연락 기록을 남긴 시각’과 ‘X에서 발신 성공을 확인한 시각’을 구분한다. 자동 확인이 불확실하면 `연락 기록 남기기`를 사용한다.
3. **번역·AI 키를 서버에서 관리한다.** 기존 구현은 확장 백그라운드에서 번역·AI 서비스에 직접 요청한다. 팀용 신규 확장은 서버가 외부 서비스 키와 사용량을 관리하고 확장은 개인별 서비스 로그인만 갖도록 제안한다. [기존 백그라운드 코드][E10]
4. **항상 실행 중인 백그라운드를 전제로 하지 않는다.** 기존 코드의 0.4분 반복 알람은 배포 환경의 30초 최소 간격보다 짧다. 브라우저는 알람을 지연할 수도 있으므로, 중단 후 다시 시작해도 요청 상태를 복원하도록 바꾼다. [Chrome 알람 설명](https://developer.chrome.com/docs/extensions/reference/api/alarms), [서비스 워커 수명](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

## 3 사용자에게 제공할 수 있는 정보

정보는 다음 네 출처를 구분해 보여준다.

- **현재 X 화면**: 사용자가 열어 본 화면에 실제 표시된 내용. 화면에서 사라진 과거 글이나 전체 대화가 포함되는 것은 아니다.
- **X 데이터 조회**: 서버가 외부 API로 가져온 정보. 현재 프로젝트는 GetXAPI를 사용하며, 공식 X API의 제공 항목과 항상 같지는 않다.
- **우리 팀 기록**: 명부·보관함·원고·캠페인 등 팀이 저장한 정보.
- **분석 결과**: 수집한 표본을 계산하거나 AI가 해석한 정보. 근거·표본 수·분석일을 함께 제공한다.

| 담당자와 다음 연락 예정일 | 누가 언제 다시 연락할지 | **신규 업무 필드 필요**. 최근 기록 작성자와 담당자는 다른 개념 |

현재 명부와 분석 데이터의 근거: [명부 데이터][D2], [계정 분석][D3], [분석 기간과 계산][D4], [현재 프로필 API 매핑][D5].

활동량과 콘텐츠 성향은 표본 범위가 다르다. 활동량은 최근 56일을 보고, 콘텐츠 성향·반응은 최대 6개월 안에서 직접 글 최근 60건을 모으는 구조다. 수집 상한이나 시간 제한에 걸리면 일부 표본만 있을 수 있으므로 실제 기간·건수·수집 완료 여부를 함께 표시한다.

팔로잉 수·계정 생성일·인증 여부도 추가 조회 후보가 될 수 있다. 공식 X API는 관련 프로필 필드를 제공하지만, 현재 `cb-x-deck`의 `UserInfo` 매핑에는 이 항목들이 없다. 채택할 데이터 제공사의 응답을 확인한 뒤 매핑·저장·표시를 추가해야 한다. [공식 사용자 조회 설명](https://docs.x.com/x-api/users/lookup/introduction)

### DM과 협업 진행 정보

| 제공 정보 | 사용자가 판단할 수 있는 것 | 출처와 구현 조건 |
| --- | --- | --- |
| 현재 보이는 메시지의 번역 | 상대의 문의·요청 내용 | 기존 번역 흐름 이식 가능 |
| 답장용 일본어 문구와 원문 | 보내려는 말이 의도와 맞는지 | 번역 미리보기·직접 수정 기능 추가 |
| 자주 쓰는 제안·안내 문구 | 매번 같은 말을 새로 쓰지 않아도 됨 | 기존 빠른 메시지 이식. 팀 공유 템플릿 관리 연동 필요 |
| 선택한 대화의 요약 | 지금까지 합의한 조건과 남은 질문 | **신규 AI 기능**. 읽은 메시지 범위·시점을 명시 |
| 대화에서 언급한 금액·일정·요청 | 협업 내용을 기록할 때 놓친 항목 | 기존 예약 파싱 참고. 콘텐츠 캠페인 필드에 맞춘 추출 추가 |
| 진행 중인 작업과 다음 마감 | 지금 안내해야 할 다음 행동 | 캠페인 작업을 계정 기준으로 요약 |
| 원고 준비 상태와 전달할 링크 | 어떤 자료를 보내야 하는지 | 원고·가이드 조회 연결 필요 |
| 최근 연락과 후속 연락 예정 | 누구에게 다시 연락할지 | 연락 기록 재사용 + 예정일·담당자 신규 |
| 협찬 예약·요청자료·업로드자료 | 방문·협찬 업무의 진행 상황 | 기존 `x_tracker` 기능. 별도 연결을 선택했을 때 제공 |
| 정산 진행 상태 | 지급 요청 여부나 지급 완료 여부 | 업무상 필요한 요약만 연결. 상세 수정은 기존 정산 화면에서 처리 |

대화 요약 예시: “선택한 메시지 12개에서 원고료 3만 엔과 10월 12일 게시 요청이 확인됐어요. 상대의 최종 수락은 아직 확인되지 않았어요.” 추출된 금액·일정은 사용자가 검토한 뒤 저장한다. 이 문장의 숫자와 날짜는 기능 설명용 가상 예시다.

### 추가 조건 없이는 제공할 수 없는 정보

| 항목 | 제한과 대안 |
| --- | --- |
| 다른 계정의 비공개 게시물이나 보이지 않는 대화 | 접근 권한을 가진 화면·API 범위만 사용. 확장 설치만으로 접근 범위가 넓어지지 않음 |
| 열지 않은 DM 전체 이력과 브라우저가 꺼진 동안의 새 DM | 화면 읽기 방식만으로 수집 불가. 별도의 지원 API·인증·운영 방식 검증이 필요한 후속 과제 |
| 다른 계정 게시물의 링크 클릭수·프로필 클릭수 | 공개 지표처럼 가져올 수 없음. 공식 API의 비공개 지표는 소유자 인증과 제공 기간 제약이 있음 |
| 팔로워의 정확한 나이·성별·구매력 | 현재 검토한 시스템으로 검증할 수 없음. 소개글·사진으로 추정해 사실처럼 표시하지 않음 |
| 가짜 팔로워 비율·협업 성공 확률 | 현재 데이터로 확정 불가. 이상 징후나 표본 기반 검토 의견만 제공 |
| 실제 매출·상담·예약 전환 | 게시물 조회수만으로 알 수 없음. 추적 링크·랜딩 이벤트·업무 시스템과의 연결 필요 |
| 과거 팔로워 추이·과거 게시물 반응 곡선 | 과거 측정 이력이 없으면 복원 불가. 측정 시작일 이후부터 제공 |
| 답장이 없다는 확정 판단 | 팀 연락 메모만으로 수신 여부를 알 수 없음. 확인된 메시지 범위 또는 사용자 기록을 명시 |

공식 API의 비공개·자연 유입·광고 지표는 계정 소유자의 사용자 인증을 요구하며, 문서상 게시 후 30일 범위 제한이 있다. 이는 현재 시스템에 해당 인증·연동이 구현되어 있다는 뜻은 아니다. [공식 지표 접근 조건](https://docs.x.com/x-api/fundamentals/metrics)

## 4 화면별 사용 방식

**화면에는 짧은 버튼과 상태만 두고, 자세한 정보는 오른쪽 업무 패널에 모으는 구성을 제안한다.** 버튼은 그 화면에서 바로 할 수 있는 행동을 설명해야 한다.

| X 화면 | 가까이 표시할 정보 | 주요 버튼과 도움말 |
| --- | --- | --- |
| 홈·검색·리스트 | 저장 여부, 명부 등록 여부 | `보관함에 저장` — 현재 워크스페이스에 이 게시물을 저장해요 |
| 게시물 상세 | 번역, 저장 메모, 지표 확인 시점 | `한국어로 읽기` — 원문 아래에 번역을 표시해요 |
| 프로필 | 팀 메모, 최근 연락, 단가, 진행 작업 | `협업 정보 보기` — 우리 팀이 남긴 기록을 확인해요 |
| DM | 상대 계정, 진행 작업, 번역, 빠른 문구 | `연락 기록 남기기` — 다른 팀원도 볼 수 있게 메모를 저장해요 |
| DM 입력창 | 원문과 번역 미리보기 | `일본어로 다듬기` — 번역을 확인하고 입력창에 넣을 수 있어요 |
| 게시물·프로필의 상세 패널 | 저장된 계정 분석과 근거 | `최근 활동 분석하기` — 최근 글의 주제와 반응을 분석해요. 추가 조회·AI 비용이 발생해요 |

브라우저의 Side Panel을 쓰면 팀 내부 정보를 X 페이지의 HTML에 직접 삽입하는 범위를 줄일 수 있다. 페이지에는 `협업 정보 보기`처럼 내용이 노출되지 않는 진입 버튼을 두고, 단가·메모·정산 요약은 패널 안에 표시하는 것을 권장한다. 패널 열기는 버튼 클릭 등 사용자 동작에 연결한다. [Chrome 콘텐츠 스크립트](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

### 첫 버전의 사용 흐름

1. 확장에 로그인하고 저장할 워크스페이스를 선택한다.
2. X에서 관심 게시물을 발견하면 `보관함에 저장`을 누른다.
3. “일본 콘텐츠 리서치에 저장했어요”라는 결과와 메모 입력을 보여준다. 이미 저장됐다면 저장한 팀원과 기존 메모를 보여준다.
4. 작성자 프로필이나 DM에서 `협업 정보 보기`를 열어 명부 기록을 확인한다.
5. 필요한 메시지만 번역하고, 연락 후 `연락 기록 남기기`로 다음 담당자가 볼 정보를 남긴다.

‘화면을 열기만 했는데 AI 분석이 실행됨’은 기본 동작으로 두지 않는다. 저장된 팀 기록은 자동 조회할 수 있지만, 유료 외부 조회·번역·분석·생성은 해당 행동을 요청하는 버튼에 연결한다.

## 5 추가 구현 기능과 우선순위

P0는 첫 배포에 필요한 기능, P1은 그다음 업무 확장, P2는 사용성과 데이터가 확인된 뒤의 고도화다. ‘재사용’ 항목도 확장 화면과 인증 연결은 새로 개발해야 한다.

### P0 첫 버전

| 기능 | 재사용할 부분 | 새로 구현할 부분 | 완료 기준 |
| --- | --- | --- | --- |
| X 전용 실행과 패널 | 기존 X 화면 감지 경험 | 타임라인·검색·상세·프로필·DM 구분, 패널, 화면 이동 감지 | 직접 진입·뒤로 가기·새로고침에서 올바른 대상을 표시 |
| 개인별 로그인과 연결 해제 | 현재 사용자·멤버 체계 | 확장 로그인, 만료·갱신·연결 해제, 서버 인가 | 로그인하지 않으면 내부 정보를 볼 수 없고 로그아웃 후 이전 정보 제거 |
| 워크스페이스 선택 | 현재 워크스페이스 목록 | 선택 저장, 현재 저장 대상 표시 | 모든 저장 결과가 선택한 보관함에 반영 |
| 계정 요약과 등록 | 명부·메모·태그·프로필 조회 | 핸들/사용자 ID로 요약 조회, 미등록 상태, 연결 확인 | 동명이인·핸들 변경·빠른 화면 전환에서 다른 사람 기록이 섞이지 않음 |
| 게시물 저장과 중복 표시 | 링크 저장·공유 메모·태그 | 게시물 버튼, 일괄 상태 조회, 메모·태그 저장 흐름 | 동일 글 반복 클릭 시 중복 카드가 생기지 않고 팀 메모 보존 |
| 게시물·DM 선택 번역 | 기존 번역 보호 로직, 게시물 번역·캐시 | 미저장 글/선택 메시지 입력 경로, 길이 제한, 비용 표시 | 원문·URL·핸들을 보존하고 실패 시 원문을 그대로 읽을 수 있음 |
| 연락 기록과 빠른 문구 | 현재 연락 로그, 기존 문구 UI | 기록 패널, X용 문구 연결, 발신 번역 미리보기 | 사용자가 확인한 내용만 기록·입력창에 반영 |
| 장애·비용·정보 보호 | 현재 사용량 기록 | 중복 요청 방지, 입력 보존, 최소 정보 반환, 재시도 | API 장애를 ‘미등록’이나 ‘게시물 삭제’로 오표시하지 않음 |

**P0에서의 분석은 이미 저장된 결과를 읽는 범위로 제한한다.** 새 분석 실행과 복잡한 업무 수정은 웹앱으로 이동하게 해도 첫 버전의 가치를 확인할 수 있다. 팀 내부 데이터는 화면 전환 때 작은 요약 요청으로 가져오고, 게시물마다 전체 명부를 반복 다운로드하지 않는다.

### P1 콘텐츠와 캠페인 업무 연결

| 기능 | 새로 제공하는 가치 | 구현해야 할 핵심 |
| --- | --- | --- |
| 계정 분석 실행 | 프로필을 보며 활동·주제·평소 반응 판단 | 기존 분석 호출 연결, 진행 상태, 중단 후 결과 복구, 표본·분석일 표시 |
| 게시물 요약과 참고 이유 | 저장한 글을 기획에 어떻게 쓸지 제안 | 게시물 단위 분석, 브랜드 맥락, 원문 근거, 결과 저장 |
| 원고 작업대로 보내기 | 발견한 글에서 바로 초안 작업 시작 | 레퍼런스 지정, 클라이언트·작업 선택, 기존 생성 화면으로 연결 |
| 캠페인 결과물 등록 | 게시물을 보며 해당 작업에 연결 | 작업 선택, 작성자·인용 대상 검증, 기존 연결 변경 안내 |
| 게시물 성과 보기 | 전후 측정치를 확인하고 최신 반응 조회 | 추적 등록·새로고침 연결, 측정일 표시, 조회 실패 구분 |
| DM에서 합의 내용 정리 | 금액·일정·할 일을 기록하는 시간 단축 | 선택 범위 요약, 필드 추출, 확인 후 저장, 원문 참조 |
| 담당자와 후속 연락 | 중복 연락과 누락 감소 | 담당자·예정일·완료 상태, 변경 이력, 팀 공유 |
| 방문협찬 연결 | 기존 예약·자료 기능을 함께 사용 | `x_tracker` 별도 어댑터, 계정 연결, 데이터 출처 표시 |

원고 생성 자체는 현재 웹앱에 구현되어 있다. 확장 안에서 편집·생성 화면을 모두 복제하기보다, 선택한 레퍼런스를 웹 원고 작업대로 넘기는 흐름부터 추가한다. [현재 원고 API][D11]

캠페인 연결도 단순히 링크를 저장하는 것 이상의 검증이 필요하다. 현재 추적 API는 이미 연결된 게시물을 다른 작업으로 연결하는 경로를 갖고 있다. 새 확장에서는 기존 연결을 먼저 보여주고 변경 의사를 받으며, 일반 리포스트는 원글의 성과와 수행자의 증빙을 구분한다. [게시물 추적 API][D9], [캠페인 작업 구조][D12]

### P2 사용 후 판단할 기능

- **팔로워 성장과 반응 추이**: 사용자가 추적 대상으로 선택한 계정만 일정에 따라 측정하고 누적 이력으로 비교한다.
- **여러 계정 비교**: 같은 기간·표본·협업 유형으로 비교하고 추천 이유를 보여준다.
- **브랜드에 맞는 계정 후보 추천**: 팀의 채택·거절 기록과 공개 주제를 이용한다. 점수 산정 근거가 필요하다.
- **이미지 속 글자 번역과 영상 요약**: 텍스트 번역과 별도의 이미지·영상 처리, 비용, 정확도 검증이 필요하다.
- **대량 게시물 선별과 저장**: 페이지 내 보이는 항목 선택부터 시작하고 일괄 실행 전에 건수·대상을 보여준다.
- **요청한 작업 알림**: 담당자·마감·사용자의 알림 설정을 기준으로 제공한다.
- **자동 번역과 예약 갱신**: 반복 버튼 조작이 실제로 불편하다는 피드백이 쌓이면 범위·예산을 정해 선택적으로 제공한다.

브라우저가 닫혀 있어도 계속되는 DM 수집, 자동 DM 발송, 자동 게시·리포스트는 위 기능들과 개발 범위가 다르다. 별도 제품 요구사항과 지원 API 검증을 거쳐 다룬다.

## 6 기존 서버 기능을 재사용할 때의 연결 작업

### 현재 API와 부족한 부분

아래 경로는 현재 존재하는 API다. 새 확장에서 호출하려면 인증·인가와 응답 형식 연결을 먼저 구현해야 한다.

| 현재 API | 재사용할 기능 | 추가 작업 |
| --- | --- | --- |
| `GET /api/workspaces`, `GET /api/me` | 워크스페이스·로그인 정보 | 확장 로그인 적용, 저장 대상 선택 |
| `POST /api/library/from-link` | URL로 게시물 저장 | 확장 버튼 연결, 메모·태그 처리, 중복 클릭 제어 |
| `GET /api/library`, `GET /api/references` | 보관함·레퍼런스 조회 | 현재 화면의 게시물 ID들만 조회하는 가벼운 요약 |
| `POST /api/tweets/translate` | 저장된 게시물 한국어 번역 | 현재는 DB에 있는 게시물 ID를 받음. 미저장 원문·DM 번역은 별도 입력 경로 필요 |
| `GET/POST /api/influencers` | 명부 목록·계정 등록 | 전체 목록 조회 대신 핸들/사용자 ID 단건 요약 |
| `GET/PATCH /api/influencers/[id]` | 상세·메모·태그·단가 | 필요한 필드만 반환. 기존 상세에 포함된 지급 정보까지 통째로 전달하지 않음 |
| `POST /api/influencers/[id]/logs` | 연락 기록 | 확장 패널 입력과 중복 저장 방지 |
| `POST /api/influencers/[id]/analyze` | 계정 분석 | 장시간 작업의 진행·복구, 비용 상한 |
| `POST /api/drafts` | 레퍼런스로 원고 생성 | P1에서 연결. 시안 수·제약 조건은 기존 계약 유지 |
| `POST /api/tracking`, `POST /api/tracking/[id]/refresh` | 성과 추적 등록·갱신 | 현재 게시물과 연결, 기존 작업 연결 충돌 처리 |
| `GET /api/campaigns/[id]` | 작업 목록을 포함한 캠페인 상세 | 계정에 해당하는 작업 요약과 캠페인 선택 |

현재 링크 저장 함수는 게시물 상세 조회를 먼저 수행한다. 따라서 ‘이미 저장된 링크이니 API 비용도 항상 0’이라고 안내하면 안 된다. 중복 상태 조회와 저장 결과 캐시를 추가하거나, 저장 버튼 주변에 데이터 조회가 포함됨을 안내한다. [현재 저장 순서][D7]

### 제안하는 확장용 서버 창구

다음은 **신규 API 설계 제안**이며 아직 존재하지 않는다. 기존 업무 로직을 서버 안에서 호출하고, 확장에는 필요한 결과만 돌려주는 얇은 연결 계층으로 만든다.

| 제안 경로 | 역할 |
| --- | --- |
| `/api/extension/session` | 개인별 연결·세션 갱신·연결 해제 |
| `/api/extension/context` | 현재 계정/게시물과 워크스페이스에 필요한 팀 정보 요약 |
| `/api/extension/posts/status` | 화면에 보이는 여러 게시물의 저장·추적 상태 일괄 조회 |
| `/api/extension/library` | 저장·메모·태그 처리와 재요청 시 결과 재사용 |
| `/api/extension/translate` | 게시물·선택 메시지 번역. 원문 종류별 저장·캐시 정책 적용 |
| `/api/extension/contact-logs` | 상대 계정에 연락 메모 기록 |
| `/api/extension/jobs` | P1의 긴 분석·요약 작업 상태와 결과 조회 |

게시물·DM 원문은 신뢰할 수 없는 입력으로 처리한다. 길이·형식을 검증하고, AI가 원문 속 지시를 업무 명령으로 실행하지 않게 한다. AI는 번역·요약 결과를 반환하며, 기록 수정은 사용자가 선택한 별도 저장 요청으로 수행한다.

### 데이터가 오가는 구조

권장 흐름은 **X 화면에서 선택한 대상 → 확장 패널과 백그라운드 → 확장용 서버 API → 기존 업무 로직과 DB**다. 외부 X 데이터 조회·번역·AI 호출은 서버가 담당한다.

콘텐츠 스크립트는 현재 게시물 ID·핸들·사용자가 선택한 원문 등 필요한 문맥을 전달한다. 백그라운드는 허용된 요청 종류만 처리하며, 웹페이지가 넘긴 임의 URL을 그대로 요청하지 않는다. 외부 서버 통신은 허용 호스트를 지정한 확장 백그라운드에서 수행하는 구성을 제안한다. 콘텐츠 스크립트의 직접 요청과 확장 백그라운드 요청은 교차 출처 제약이 다르며, 호스트 권한이 서버의 로그인·인가를 대신하지 않는다. [Chrome 교차 출처 요청](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

확장 로그인은 웹앱의 쿠키가 자동 공유된다고 가정하지 않는다. 짧은 수명의 개인별 토큰과 갱신·폐기 절차를 설계하고, 로그인 왕복에 일회용 코드와 요청 검증을 적용한다. 서버는 사용자 신원과 허용된 데이터 범위를 검증하며, 요청 본문의 `memberId`를 저장 주체로 믿지 않는다. 현재 워크스페이스 선택 UI가 곧 워크스페이스별 접근 통제라는 가정도 하지 않는다.

확장 패키지에는 X 화면 접근, 서비스 API 호스트, 저장소, 패널 등 사용하는 권한만 선언한다. LINE·Instagram·외부 AI 서비스의 직접 접근 권한은 X 전용 서버 경유 구성에 맞춰 제거하고, 인증 방식에 필요한 권한은 구현 방식 확정 후 추가한다.

## 7 두 서비스의 데이터를 다루는 원칙

**권장안은 콘텐츠·원고·캠페인·성과의 기준을 `cb-x-deck`에 두고, 방문협찬을 계속 쓸 때만 `x_tracker`를 별도 연결하는 방식이다.** 두 서비스의 데이터베이스를 처음부터 통합하는 작업은 첫 버전에 포함하지 않는다.

| 데이터 | 첫 버전의 제안 |
| --- | --- |
| 게시물·보관함·원고·콘텐츠 캠페인·성과 | `cb-x-deck`를 기준으로 읽고 저장 |
| 계정 메모·태그·콘텐츠 협업 단가·연락 기록 | `cb-x-deck`의 기록 사용. 기존 기록 이전이 필요하면 별도 가져오기 작업 |
| 방문협찬 예약·협찬 요청자료·업로드자료 | 계속 사용하는 경우 `x_tracker`를 출처로 명시 |
| 같은 계정의 서로 다른 단가·메모 | 자동 덮어쓰기 없이 출처를 구분. 업무별 기준을 결정한 뒤 이동 |
| 동일인 연결 | 확인한 X 사용자 ID 우선. 내부 ID는 서비스별로 따로 보존 |

기존 확장은 빠른 문구를 별도 Supabase 테이블에서 가져오는 경로도 갖고 있다. 인플루언서 API를 연결했다고 템플릿까지 함께 이전되는 것은 아니다. 문구 데이터의 소유 서버와 이전 방법을 별도로 정해야 한다. [빠른 문구 저장 구조][E6]

## 8 숫자와 분석을 이해하기 쉽게 보여주는 방법

다음은 신규 표시 규칙 제안이다. 현재 웹앱과 같은 정보라면 서버의 공통 계산 결과를 사용해 화면마다 판단이 달라지지 않게 한다.

| 항목 | 계산·표시 규칙 |
| --- | --- |
| 확인 시점 | `프로필 확인 10월 2일`, `게시물 반응 확인 14시 10분`처럼 종류별 시점을 표시 |
| 누락된 숫자 | `null`은 `확인 불가`. 실제 0과 구분 |
| 화면의 축약 숫자 | `1.2만`은 약 1만 2천으로 표시. 정확한 수치처럼 저장하지 않음 |
| 평소보다 높은 조회 | 현재 조회 ÷ 비교 표본의 조회 중앙값. 중앙값이 없거나 0이면 배수 계산 생략 |
| 비교 표본 | 같은 계정·직접 글·비교 기간·건수 표시. 대상 게시물 제외, 게시 후 경과 시간 차이도 안내 |
| 기간별 증가 | 최근 측정값 − 이전 측정값. 두 측정 시점과 기간 표시 |
| 반응 비율 | 도입 시 구성 항목과 분모를 먼저 정의. 예를 들어 좋아요·답글·리포스트·인용의 합 ÷ 조회수. 모두 같은 시점이며 값이 있을 때만 계산 |
| 주제 적합성 | `협업 추천 92점` 대신 관련 주제와 근거 글을 보여주고 검토 의견으로 표현 |
| 협찬 비중 | AI가 분류한 표본 중 표기·근거가 확인된 비중. 미분류 건수와 전체 표본 수 구분 |
| 연락 상태 | `마지막 연락 기록`과 `상대 답장 확인`을 구분. 기록이 없으면 ‘연락한 적 없음’으로 단정하지 않음 |

예를 들어 “최근 직접 글 40건의 조회 중앙값은 8천 회예요. 이 글은 2만 4천 회로 3배 높아요. 게시된 지 얼마나 지났는지도 함께 비교해 보세요”처럼 숫자와 해석을 함께 제공한다. 이 예시는 가상 수치이며, 높은 반응이 난 원인을 확정하거나 다음 캠페인의 성과를 보장하는 표현은 피한다.

## 9 개발 중 반드시 해결할 동작

### 계정과 게시물 인식

- 화면 이동 때 이전 계정의 요청·패널 상태를 정리한다. 늦게 도착한 응답을 다른 계정에 표시하지 않는다.
- X가 스크롤 중 같은 화면 요소를 다른 게시물·대화에 재사용하면 게시물 ID와 상대 계정을 다시 확인한다.
- 일반 글·답글·인용·리포스트를 구분한다. 인용한 사람, 인용 대상, 현재 저장 대상을 명확히 표시한다.
- DM에서 핸들을 확인할 수 없거나 그룹 대화이면 특정 인플루언서로 자동 연결하지 않는다.
- X 계정을 바꾸거나 브라우저 탭이 여러 개일 때도 문맥과 캐시가 섞이지 않게 한다.

### 저장과 비용

- 저장 요청에 중복 방지 식별자를 붙인다. 재시도·연속 클릭·화면 전환으로 중복 기록이나 중복 AI 작업을 만들지 않는다.
- 번역 캐시는 원문·목표 언어·번역 규칙 버전을 반영한다. DM은 공개 게시물과 같은 전역 캐시에 넣지 않는다.
- 원문 DM은 번역·요약에 필요한 범위만 전달하고, 영구 기록은 사용자가 저장한 메모를 중심으로 한다. 로그에 대화 원문과 토큰을 남기지 않는다.
- 오프라인·로그인 만료 때 작성한 메모를 보존하되 `저장됨`으로 표시하지 않는다. 다시 연결되면 사용자가 결과를 확인할 수 있게 한다.
- 긴 분석은 작업 ID로 상태를 다시 조회할 수 있어야 한다. 패널을 닫는 것과 서버 작업 취소를 구분한다.
- 기존 사용량 집계에 확장 요청임을 구분하는 값과 사용자·작업 식별자를 추가한다. 구체적인 비용 안내는 실제 적용 단가를 기준으로 계산한다.

### 실패 안내

| 상황 | 제안 문구와 다음 행동 |
| --- | --- |
| 계정을 특정하지 못함 | `이 대화의 계정을 확인하지 못했어요. 프로필 링크로 연결해 주세요.` |
| 같은 표시명의 후보가 여럿 | `같은 이름의 계정이 있어요. 연결할 프로필을 선택해 주세요.` |
| X 정보 조회 실패 | 이전 정보가 있으면 `지금 정보를 가져오지 못했어요. 마지막 확인 정보를 표시하고 있어요.` 없으면 재시도 안내 |
| 서버 조회 실패 | `팀 기록을 확인하지 못했어요. 잠시 후 다시 시도해 주세요.` |
| API에서 게시물을 확인할 수 없음 | `게시물을 확인할 수 없어요. 주소와 공개 상태를 확인해 주세요.` |
| 저장 중 연결 끊김 | `저장 결과를 확인 중이에요. 입력한 메모는 보관했어요.` |
| 로그인 만료 | `다시 로그인하면 이어서 저장할 수 있어요.` |
| 분석 표본 부족 | `비교할 글이 부족해요. 확인된 글의 반응만 보여드려요.` |

## 10 권장 개발 순서와 검증 기준

확정 일정은 인증 방식, X 화면의 현재 구조, `x_tracker` 유지 범위를 정한 뒤 산정한다. 아래는 개발 순서다.

| 단계 | 결과물 | 다음 단계로 넘어갈 기준 |
| --- | --- | --- |
| 1 연결 검증 | X 전용 기본 확장, 패널, 개인 로그인, 계정 인식 | 프로필·게시물·DM 이동과 동명이인 상황에서 올바른 계정 유지 |
| 2 첫 업무 흐름 | 게시물 저장, 명부 요약, 선택 번역, 연락 메모, 빠른 문구 | 실제 담당자가 X에서 저장·확인·번역·기록을 완료 |
| 3 콘텐츠 업무 | 계정 분석, 원고 작업대 연결, 캠페인 결과물·성과 연결 | 웹앱과 같은 데이터·상태를 표시하고 연결 충돌을 처리 |
| 4 협업 고도화 | 대화 요약·필드 추출, 담당자·후속 연락, 선택적 방문협찬 연동 | 사용자 검토 후 정확한 상대와 작업에 기록 |
| 5 누적 분석 | 성장 추이, 비교, 제한된 자동 갱신 | 충분한 누적 표본과 예산·중단 설정 확보 |

배포 전에는 다음을 확인한다.

- X의 밝은 화면·어두운 화면, 한국어·일본어 UI, 긴 글, 인용 글, 이미지 메시지에서 버튼과 패널이 깨지지 않는다.
- 직접 주소 진입, 뒤로 가기, 빠른 계정 전환, 가상 스크롤, 여러 탭에서도 표시 대상이 맞다.
- 로그인 만료·권한 없는 요청·네트워크 단절·서버 오류·호출 제한을 구분한다.
- 같은 글 저장·같은 메모 저장·같은 분석 실행을 반복해도 의도치 않은 중복이 생기지 않는다.
- 발신 번역 중 대화 상대가 바뀌면 반영을 중단한다. 입력만 바꾼 상태를 ‘전송 완료’로 기록하지 않는다.
- 등록 여부 조회는 외부 유료 조회를 암묵적으로 실행하지 않는다. 번역·분석의 비용과 처리 범위를 버튼 주변에서 설명한다.
- 패키지에 외부 서비스 비밀키가 없고, 내부 메모·단가·지급 정보가 X 페이지 DOM이나 콘솔 로그에 노출되지 않는다.
- 확장 백그라운드가 중단·재시작되어도 기록과 작업 상태를 복원한다.

파일럿에서는 ‘게시물 발견부터 저장까지 걸린 시간’, ‘협업 정보 확인까지의 조작 수’, ‘잘못 연결된 계정 수’, ‘저장 성공률’, ‘기능별 외부 API 비용’을 측정한다. 절감 목표와 비용 상한은 실제 기존 업무를 측정한 뒤 정한다.

## 11 착수 시 결정할 항목

| 결정할 항목 | 이 문서의 권장안 | 다른 선택을 하면 달라지는 부분 |
| --- | --- | --- |
| 첫 사용자와 배포 범위 | 사내 Chrome 사용자로 검증 | 외부 배포는 가입·조직 분리·권한·운영 지원 범위가 추가됨 |
| 주요 사용 화면 | 타임라인·프로필·게시물·DM | DM 전용이면 콘텐츠 탐색·저장 기능을 줄일 수 있음 |
| 데이터의 기준 서비스 | 콘텐츠 업무는 `cb-x-deck` | `x_tracker` 중심이면 캠페인·원고 데이터 연결 방향 재설계 |
| 방문협찬 기능 | P1에서 필요 여부 확인 | 첫 버전에 포함하면 서버 간 계정·필드 연결이 선행됨 |
| 발신 방식 | 번역 확인 후 입력창 반영, X에서 최종 전송 | 기존 자동 번역 후 전송을 유지하면 중복·오발신 검증 범위가 커짐 |
| 유료 기능 실행 | 버튼을 누를 때 실행 | 자동화는 계정·빈도·예산과 중단 조건이 추가됨 |
| 기존 확장과 함께 사용 | X에서 한 확장만 작동하도록 전환 안내 | 동시 사용을 지원하려면 버튼·단축키·번역 중복 방지 필요 |

발신 방식은 기존 확장의 사용 습관과 달라지는 제안이다. 새 확장의 첫 안내에 “번역을 확인한 뒤 X에서 직접 보내요”를 명시해야 한다. `cb-x-deck` 연동 변경을 main에 배포할 때는 QA 후 `src/content/updates.ts`에도 해당 작업의 변화와 사용 방식 변경을 기록한다.
