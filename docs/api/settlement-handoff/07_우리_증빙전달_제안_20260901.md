지급 전 확인 자료(증빙)를 API로 함께 보내드리려고 합니다. 추가만 하는 변경이라 그쪽 코드가 지금 그대로여도 아무것도 깨지지 않습니다.

*배경*
지급하기 전에 "그 작업이 실제로 이루어졌는지" 확인하실 자료가 필요하다고 이해했습니다. 유형별로 나눠 정리하면 이렇습니다.

• *투고 · 인용RT · 방문* — 이미 나가고 있습니다. 아이템의 `reference_url`이 **인플루언서 본인 게시물 링크**입니다. 이 링크로 확인해 주세요.
• *RT* — 여기만 빠져 있었습니다. 단순 RT는 새 게시물 URL이 없어서 `reference_url`에 **클리닉 원본 트윗**이 들어갑니다. 원본을 보여줄 뿐 그 인플루언서가 RT했다는 증거가 아닙니다. 그래서 저희는 RT 작업에 **인플루언서 피드 스크린샷**을 필수로 받고 있는데, 그 스크린샷이 그쪽으로 나가지 않고 있었습니다.

*아이템에 필드 하나가 늘어납니다*
```json
"proof": {
  "url": "https://cb-x-deck.vercel.app/api/external/settlement/requests/<request_id>/proof",
  "uploaded_at": "2026-08-31T10:12:00Z",
  "uploaded_by": "박구건"
}
```
`null`인 경우가 둘입니다.
1. RT가 아닌 유형 — 확인은 위 `reference_url`로 하시면 됩니다.
2. RT인데 아직 증빙이 없음 — 이 규칙 이전에 만든 요청도 포함됩니다.

아이템에 이미 있는 `task_type`으로 둘을 가릴 수 있습니다: `task_type == "rt"` 이고 `proof == null` 이면 **확인 자료가 없는 요청**입니다.

*증빙 보기*
```
GET /api/external/settlement/requests/{request_id}/proof
Authorization: Bearer <지금 쓰시는 그 운영 키>
```
• 200 — 이미지 바이트(`Content-Type: image/*`)
• 404 — 요청이 없거나 증빙이 없음
• 401 — 키 불일치(본문 없음)

주소는 **고정**입니다. 만료되는 서명 링크를 아이템에 담지 않은 이유이기도 합니다 — 목록을 캐시해 두셨다가 며칠 뒤 여셔도 그대로 열립니다. 열 때마다 저희 쪽에서 새로 서명합니다.

*부탁드리는 것*
• `task_type == "rt"` 인데 `proof == null` 이면 **보류(`on_hold`)로 돌려보내 주세요.** 사유에 "증빙 없음"처럼 적어 주시면 저희 화면에 그대로 보입니다.
• 저희가 증빙을 채우면 **다음 폴링에 `proof`가 채워져 내려갑니다.** 취소하고 새 요청을 만들 필요가 없습니다 — 증빙만은 예외적으로 최신값을 보내드립니다(금액·계좌·기한은 지금처럼 요청 시점 값 그대로입니다).

*적용 시점*
저희가 먼저 배포하고 알려드립니다. 그쪽은 편한 시점에 채택하시면 되고, 그때까지 기존 동작은 그대로입니다.
