# 서비스 튜토리얼 (인터랙티브 투어) 설계

- 작성일: 2026-07-21
- 개정: 2026-07-28 — 덱 UI 개편(헤더 2행 분리·컬럼 순서 손잡이·저장 시 인라인 메모) 반영해 스텝 9 → 12단계
- 대상 사용자: 처음 cb-x-deck를 쓰는 **비개발 콘텐츠 기획 담당자**
- 관련 원칙: 저장소 `AGENTS.md` UX/UI 원칙 (라벨은 이득으로·행동 전 기대 설정·결과에 판단 서술·비용 액션 opt-in)

## 1. 목표 & 범위

첫 사용자가 **직접 해보면서** 핵심 기능과 사용법을 익히게 한다. 수동적으로 읽고 닫는
나열형 투어가 아니라, 가장 값진 첫 행동(첫 컬럼 생성 → 새로고침 → 실제 트윗 등장)을
**실제로 수행하게 유도**하는 것이 핵심 설계 결정이다.

- **형태:** 실제 화면 위 코치마크(하이라이트 + 말풍선) 투어. `driver.js`(오픈소스, 앱 번들 내장, ~5KB, 데이터 외부 유출 없음) 사용.
- **범위 (1차):**
  - **덱 투어** — 행동 유도형. 첫 방문 자동 실행.
  - **브리핑 투어** — 짧은 안내형. **자동 실행 없음**, `?` 버튼으로만.
- **범위 밖 (백로그):** 리서치·보관함 투어, 멤버별(DB) 본 여부 추적.

## 2. 아키텍처 (파일 구성)

```
src/lib/tour/
  tourSteps.ts     # 덱·브리핑 스텝 정의(한글 문구 + data-tour 앵커) — 순수 데이터
  tourState.ts     # '본 여부' 저장/조회 (localStorage 래퍼) — 순수 함수, 유닛 테스트 대상
  useTour.ts       # driver.js 구동 훅: start(tourId), 자동시작 판정, 액션 기반 진행(moveNext)
src/components/
  HelpButton.tsx   # 각 영역 상단 우측의 '?' 재실행 버튼
src/app/globals.css  # driver.js 팝오버를 X 테마에 맞추는 커스텀 CSS (색·라운드)
```

- **앵커 규칙:** 대상 요소에 `data-tour="..."` 속성을 부여해 지정한다. 클래스명·텍스트에 의존하지 않는다.
- **얇은 통합:** `DeckPage`/`BriefingPage`가 `useTour`를 호출해 자동시작 판정·액션 감지를 연결한다. driver.js 구동 세부는 훅 안에 숨긴다.

### 앵커 지점 (data-tour 부여 대상)
- 사이드바: `sidebar`(`<aside>` 전체 — 영역 네비 + 워크스페이스 셀렉터 포함, `src/components/Sidebar.tsx`)
- 덱: `add-column`(`+ 컬럼` 버튼, `DeckPage`), `column-modal`(`src/components/ColumnSettings.tsx`)
- 컬럼(`src/components/Column.tsx`) — **첫 컬럼**에만(`tourAnchor={i === 0}`):
  - `col-reorder`(순서 손잡이, `ColumnGrip.tsx` — 컬럼 2개 이상일 때만 렌더)
  - `col-refresh`(새로고침 아이콘)
  - 헤더 1행 = 목록 제어: `col-sort`(정렬 줄 전체)·`col-view`(보기 드롭다운)
  - 헤더 2행 = 분석 액션: `col-analyze`(줄 전체)·`col-translate`(전체 번역 버튼)
- 트윗 카드(`src/components/TweetCard.tsx`): `col-save`(첫 컬럼의 첫 카드에만)
  - 카드 안 `🌐 번역` 버튼에는 앵커를 두지 않는다 — 같은 키가 두 곳에 있으면 어느 쪽이 잡힐지 DOM 순서에 의존한다. 카드 단위 번역은 `col-translate` 스텝 **문구로** 안내한다.
- 브리핑: `bf-column`(컬럼 선택)·`bf-period`(기간)·`bf-generate`(생성 버튼)·`bf-result`(생성된 보고서 영역)·`bf-history`(지난 브리핑) (`src/components/BriefingSection.tsx`)
- 각 페이지 상단 우측: `help-button`
- 미사용(향후용): `nav-deck`·`nav-briefing`(개별 네비 링크) — 현재 스텝은 `sidebar` 전체를 강조하므로 직접 참조 안 함

## 3. 덱 투어 (행동 유도형, 항상 생성부터 — 12단계)

driver.js는 기본적으로 "다음" 버튼으로 진행하되, 사용자가 **실제 행동**을 하면 그 순간 자동으로
다음 단계로 넘어간다(관대한 진행 — 행동/버튼 둘 다 허용). **컬럼 유무와 무관하게 항상 하나의
시나리오(생성부터)를 실행**한다. 컬럼이 이미 있는 사용자가 생성 단계를 넘기면(모달을 열지 않으면)
해당 스텝은 대상 요소가 없어 `skipMissingElement`로 자동 건너뛰어진다.

1. **(중앙)** "여기 **덱**은 관심 주제·계정의 X 글을 컬럼으로 모아 한눈에 보는 곳이에요. 컬럼을 만들며 하나씩 익혀볼게요."
2. **(`add-column` 강조)** "여기를 눌러 **키워드**(관심 주제)나 **인플루언서**(특정 계정) 컬럼을 만들어요." → 클릭해 모달이 열리면 자동 진행.
3. **(`column-modal` 강조)** "주제나 계정을 넣고 만들면 돼요. 입력창 옆 도움말이 어떤 값을 넣을지 알려줘요." → 컬럼이 생성(목록 +1)되면 자동 진행. (모달을 열지 않으면 자동 건너뜀)
4. **(`col-refresh` 강조)** "컬럼은 **새로고침을 눌러야** 최신 글을 가져와요. **팀 공용이고, 누를 때만, 아주 소액**이라 부담 없이 눌러도 돼요. (새 글엔 파란 **NEW** 배지)"
5. **(`col-sort` 강조)** "**날짜·조회수·북마크·RT** 기준으로 순서를 바꿔요. 같은 기준을 한 번 더 누르면 오름/내림 반전."
6. **(`col-view` 강조)** "**'보기'**로 **버림** 목록도 봐요. 카드 아래 **✕ 버림**으로 치운 글이 거기 모이고 **되돌리기**도 된다"까지 한 문장으로 — 목록만 알려주고 버리는 방법을 빼면 반쪽이다.
7. **(`col-analyze` 강조)** 분석 줄 전체. "쌓인 글을 재료로 새 결과를 만드는 줄 — **주간 추이**(무료), 인플루언서 컬럼엔 **주제별로 묶기**. **돈이 드는 버튼엔 금액이 적혀 있고, 없으면 공짜**"라는 **판단 기준**을 준다(버튼마다 비용을 설명하는 대신).
8. **(`col-translate` 강조)** 2행의 **전체 번역** 버튼. "누르면 위에서부터 한국어로. 한 건만 보려면 카드 안 **🌐 번역**. **AI 자동 번역**이라 중요한 내용은 원문도 확인. 한 번 번역하면 저장돼 다시 볼 땐 비용 없음."
9. **(`col-save` 강조)** "**저장**하면 보관함에 모여요. 저장하는 순간 **메모 한 줄** 칸이 열려요(비워둬도 됨)." — 저장 직후 뜨는 입력칸을 설명 없이 만나지 않게 한다.
10. **(`col-reorder` 강조)** "컬럼이 **2개 이상**이면 제목 왼쪽에 **손잡이**. 끌거나 클릭 후 **← →** 키로 이동. 순서는 팀 전체에 저장." — 상시 노출로 만든 어포던스라 안내가 없으면 '왜 있는지 모를 아이콘'으로 남는다.
11. **(`sidebar` 강조)** "왼쪽에서 **리서치·덱·브리핑·보관함**을 오가고, 맨 위에서 **워크스페이스**(클라이언트별 작업 공간)를 바꿔요."
12. **(`help-button` 강조, 마무리)** "**덱과 브리핑 화면에는** 이렇게 **?** 가 있어서 그 화면 안내를 다시 볼 수 있어요. 글이 며칠 쌓이면 **브리핑**에서 흐름을 보고서로." — 재실행 버튼을 **말로만 안내하지 않고 실제로 하이라이트**해 위치를 각인시킨다. 리서치·보관함엔 `?`가 없으므로(§10 백로그) **"언제든 어디서든"이라고 말하지 않는다**.

> 4~10은 대상 컬럼/트윗이 있을 때 표시. 없으면(새 사용자가 생성/새로고침을 건너뜀) 각 스텝은 자동 건너뜀.
> 10(`col-reorder`)은 컬럼이 1개면 손잡이가 렌더되지 않아 건너뛴다 — 첫 사용자는 자연히 보지 않고, 두 번째 컬럼을 만든 뒤 `?`로 다시 보면 나온다.

## 4. 브리핑 투어 (안내형, 자동 없음 — 7단계)

`?` 버튼으로만 실행. 첫 사용자에겐 브리핑이 아직 쓸모없으므로(표본 0건 → 생성 불가) 자동 실행하지 않는다.

1. **(중앙)** "**브리핑**은 컬럼 하나의 최근 몇 주를 AI가 읽고 보고서로 정리해줘요. 컬럼에 글이 며칠~몇 주 쌓인 뒤에 유용해요."
2. **(`bf-column` 강조)** "먼저 정리할 **컬럼을 하나** 고르세요."
3. **(`bf-period` 강조)** "**몇 주간**을 볼지 정해요. 중간에 빈 주가 있으면 **빈 주 채우기** 안내로 과거 글을 더 모아 정확도를 높여요."
4. **(`bf-generate` 강조)** "**브리핑 생성**을 누르면 보고서가 만들어져요. **누를 때만, 아주 소액**(약 $0.1 이하)이고 **팀 공용**이에요. 표본이 적으면 **참고용** 표시가 함께 떠요."
5. **(`bf-result` 강조)** "완성된 보고서는 여기 열려요. 문단 사이에 **근거가 된 실제 트윗**이 함께 실려요." (생성 전엔 요소가 없어 자동 건너뜀)
6. **(`bf-history` 강조)** "만든 보고서는 여기 **지난 브리핑**에 쌓여 언제든 다시 봐요." (이력 없으면 자동 건너뜀)
7. **(`help-button` 강조, 마무리)** "브리핑 끝! **바로 여기 ?** 를 누르면 언제든 다시. 덱에서 컬럼에 글을 며칠 쌓은 뒤 만들면 가장 잘 나와요."

## 5. 트리거 · 재실행 · 본 여부 저장

- **덱 자동 시작:** 덱 페이지 첫 진입 시 `tour-seen:deck`가 없으면 렌더 안정화 후 1회 자동 실행.
- **브리핑:** 자동 없음. `?` 버튼으로만.
- **재실행:** 각 영역 상단 우측 **`?`** 버튼 → 그 영역 투어 재생(본 여부와 무관, 항상 가능).
- **본 여부 저장:** `localStorage` 키 `tour-seen:deck`. 브라우저=실사용자(도메인 게이팅 OAuth) 기준이라 충분. 멤버별 DB 추적은 마이그레이션 필요해 범위 밖.
- **건너뛰기/종료:** 말풍선 ✕·Esc·바깥 클릭으로 즉시 종료. 종료해도 '본 것'으로 저장(덱).

## 6. 문구 톤 규칙 (AGENTS.md 준수)

- 내부 개념어(density·probe 등) 노출 금지. 이득을 사용자 언어로.
- 비용 액션은 "팀 공용·누를 때만·아주 소액"으로 안심 맥락과 함께. 숫자만 던지지 않는다.
- 각 스텝은 "무엇을 하면 무엇이 나오는지"를 한 문장으로.

## 7. 엣지 케이스

- **요소 없는 스텝:** `useTour`의 driver 설정에 `skipMissingElement: true` — 앵커 요소가 DOM에 없으면 그 스텝은 **자동 건너뜀**(중앙에 덩그러니 뜨지 않음). 예: 컬럼 0개일 때의 `col-*`, 이력 0건일 때의 `bf-history`, 생성 전의 `bf-result`.
- **모달 상태:** 모달이 열리면 자동 진행("다음"도 허용). 열지 않으면 `column-modal` 스텝은 건너뜀.
- **스크롤/리사이즈:** driver.js가 위치 재계산. 브리핑은 세로 스크롤 → 스텝 이동 시 대상으로 스크롤.
- **컬럼 순서:** 앵커는 항상 첫 번째 컬럼 요소를 기준으로(`tourAnchor={i === 0}`). 사용자가 순서를 바꾸면 '첫 번째'가 달라질 뿐, 앵커는 언제나 화면 왼쪽 컬럼에 붙는다.
- **컬럼 1개:** 순서 손잡이가 렌더되지 않아 `col-reorder` 스텝은 건너뜀(거짓 어포던스 금지 규칙과 자동으로 맞물린다).
- **앵커 중복 금지:** 같은 `data-tour` 키를 두 곳에 두지 않는다. driver.js는 `querySelector`로 **DOM 순서상 첫 요소**를 잡으므로, 중복이 있으면 어디가 강조될지 렌더 구조에 의존하게 된다.

## 8. 테스트

- **유닛 테스트(순수 로직):**
  - `tourState`: 본 여부 저장/조회/초기화 (localStorage 모킹).
  - `tourSteps`: 스텝 정의 무결성 — 덱 12단계·브리핑 7단계, 각 스텝에 문구가 있고, 앵커 스텝의 `data-tour` 키가 정해진 집합에 속하며, 마지막 스텝이 `help-button`을 강조하는지, 비용 액션 스텝이 금액·과금 조건을 말하는지, 스텝 순서(생성 → 사용 → 마무리)가 유지되는지.
  - `tourAnchors`: **앵커 회귀 방지** — 스텝이 가리키는 `data-tour` 키가 실제 컴포넌트 소스에 존재하는지, 반대로 투어가 가리키지 않는 앵커가 남아 있지 않은지(`nav-deck`·`nav-briefing`은 향후용으로 허용). 스텝 정의만 검사하면 컴포넌트에서 속성이 사라져도 통과하고, 런타임에는 `skipMissingElement`가 **조용히** 건너뛰어 신호가 남지 않는다.
- **수동(브라우저) 확인:** 첫 방문 자동 실행, 컬럼 생성 시 자동 진행, 정렬·보기·분석 줄·순서 손잡이·사이드바 강조, `?` 재실행, 브리핑 `?` 실행, 컬럼 1개일 때 `col-reorder` 자동 건너뜀, 컬럼/이력 0개일 때 해당 스텝 자동 건너뜀.

## 9. 의존성

- `driver.js` (npm, 클라이언트 전용). `'use client'` 컴포넌트에서만 사용.

## 10. 범위 밖 (백로그)

- **리서치·보관함 투어** — 두 화면에는 `HelpButton`도 없다. 투어 없이 `?`만 두면 거짓 어포던스이므로 **버튼도 함께** 넣어야 한다. 그때까지 덱 마무리 문구는 "덱과 브리핑 화면에는"으로 범위를 좁혀 말한다(§3-12).
- **덱 투어 길이(12단계)** — 첫 방문에 자동 실행되기엔 길어졌다. 다음 후보: 필수(생성·새로고침·저장)만 자동 실행하고 나머지는 `?`의 '자세히' 갈래로 분리.
- 멤버별(DB) 본 여부 추적.
- 온보딩 체크리스트(지속형 진행률).
