# 인플루언서를 교체해도 작업 ID는 그대로다

거절·무응답으로 다른 인플루언서에게 같은 일을 넘길 때, 옛 작업을 취소하고 새 작업을 만드는 대신 **같은 작업 행에서 인플루언서만 바꾼다.** 작업 ID를 `payment_request.task_id`·`tracked_post.task_id`·다른 RT의 `target_task_id`가 참조하므로, 행을 갈아타면 그 연결을 옮기는 규칙이 전부 필요해진다. 같은 ID를 유지하면 유형·대상·예정일·원고가 그대로 따라오고 취소 섹션도 늘지 않는다.

## 교체 규칙

- **게시 전에만.** 방문협찬은 **방문일 전에만** — 방문한 사람이 게시해야 한다(koo 09-15). 그 뒤 진행이 안 되면 취소.
- **비용**: 비어 있으면 새 인플루언서의 명부 단가로 채운다(기존 동작). 값이 있으면 **항상 묻는다** — "지금 ¥3,000 유지 / 새 단가 ¥2,500로". 새 단가가 없으면 유지만 가능 + "명부에 RT 단가 없음" 안내. 통화가 다르면 둘을 나란히. 0원도 값이다. (비용의 출처를 저장하지 않으므로 손입력 여부를 판별하지 않는다 — 묻는 것이 컬럼 하나보다 싸다.)
- **원고**: 붙은 채로 따라간다. 상태가 '전달됨'이면 **'사용 확정'으로 되돌리고** "새 인플루언서에게 다시 전달하세요" — 옛 사람에게 전달한 사실이 새 사람에게 전달한 것으로 읽히지 않게.
- **증빙**: 게시 전 올린 RT 증빙은 옛 사람의 것이므로 **제거**한다.
- **사유(선택)**: 취소와 같은 칩(거절·무응답·기타). `declined`·`no_response`면 옛 인플루언서 타임라인에 `task_declined` 이벤트(payload: taskId·campaignId·campaignName·taskType·reason·action `'replace'`). 취소도 같은 이벤트에 action `'cancel'`. 되돌리기 정정 이벤트는 만들지 않는다(한계).
- 기존 화면의 인플루언서 셀 변경도 이 동작을 쓴다(ADR 0003).

## Considered Options

- 옛 행 취소 + 새 행 복제 — 참조 이관 규칙 필요, 취소 섹션이 늘어남.
- 같은 행 교체(채택).
