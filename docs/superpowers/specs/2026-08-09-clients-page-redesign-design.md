# 클라이언트 페이지 개편 (B안 — 2단 분할) 설계

2026-08-09 · 시안: `~/claude-outputs/20260809-clients-page-ab-mockup.html` (A/B 비교 후 B안 확정)

## 목적과 배경

`/clients`는 원고 생성의 재료(클리닉 정보·시술·금지 표현)를 등록·점검하는 페이지다.
여기 채운 내용이 원고 품질과 검수 기준을 결정하는데, 현행 UI는:

1. 알약 버튼에 이름만 보여 어느 클라이언트가 정보 미입력인지 밖에서 알 수 없다
2. 저장 피드백이 없고, 편집 중 다른 클라이언트를 클릭하면 변경이 경고 없이 사라진다
3. 시술이 접힌 아코디언이라 펼치기 전엔 채움 상태를 알 수 없다 (시술 5~10개 전제에서 치명적)
4. 시술 삭제가 원클릭이다
5. 로딩·실패 상태가 없다 (실패가 "클라이언트 없음"처럼 보임)

규모 전제: 클라이언트 4개(계속 증가), 클라이언트당 시술 5~10개.

## 구조

**단일 라우트 `/clients` 유지 + 2단 분할.** 좌측 클라이언트 목록(236px 고정) + 우측 상세(나머지 폭).
데스크톱 도구 전제로 2단을 항상 유지한다(모바일 대응 범위 밖).

**선택 상태는 `?client=<id>` 쿼리.** 새로고침·뒤로가기·링크 공유가 자연스럽다.

- 쿼리 없이 진입 → 첫 번째 클라이언트 자동 선택 (URL replace)
- 쿼리가 존재하지 않는 클라이언트를 가리킴(삭제된 딥링크 등) → 첫 번째로 폴백 + 정직한 안내
  ("링크가 가리키는 클라이언트를 찾을 수 없어 첫 번째를 표시했어요" — 워크스페이스 딥링크 처리 87f8353과 동일 원칙)

## 좌측 목록 (rail)

- 항목: 이름 + 요약 캡션 "시술 6 · 금지 5". 선택된 항목은 파란 배경 강조.
- **정보 미입력 경고**: `info`가 비어 있으면 이름 옆 ⚠️ + 캡션에 "정보 미입력".
- 요약 수치는 `/api/clients` 응답(클라이언트+시술 전체)에서 클라이언트 사이드 계산.
  금지 표현 수 = 공통 + 시술별 합산. **API·DB 변경 없음.**
- "+ 추가": 목록 상단 인라인 입력(워크스페이스 페이지 패턴 — IME Enter 이중 발화 방지 ref 포함).
  생성 성공 시 새 클라이언트를 즉시 선택.
- 순서는 기존 `position` 순 그대로 (재정렬 UI는 범위 밖).

## 우측 상세 (pane)

**헤더**: 클라이언트 이름 + "이름 변경"(인라인 편집, 기존 PATCH가 name 지원) + "삭제".

**기본 정보 섹션**:
- 클리닉·의사 정보 textarea — 라벨을 제목(bold)+도움말(캡션) 구조로 승격 (현행: 캡션 한 줄에 전부)
- 금지 표현 textarea — 동일 구조
- 저장 버튼 + 성공 시 "저장됨 ✓" 2~3초 표시

**시술 섹션**:
- 시술 카드: 접힘 시 이름 + 요약 줄
  - 채워짐: "설명·효과 표현 입력됨 · 금지 2건" (입력된 필드만 나열)
  - 빈 시술: "아직 비어 있어요 — 원고에 반영할 내용이 없어요" (주황)
- 펼치면 현행과 같은 3필드 편집 + "시술 저장"
- **시술 삭제 2단계**: "삭제" → "삭제 확정 / 취소" (현행 클라이언트 삭제의 인라인 확인 방식)
- 하단에 새 시술 추가 입력 (현행 유지)

**클라이언트 삭제**: 이름 입력 확인 모달로 승격 (워크스페이스 삭제와 동일 격).
문구에 파급 명시: "시술 N개가 함께 삭제됩니다. 이 클라이언트로 만든 초안은 스냅샷으로 남아요."

## 편집 유실 방지

- 편집기(기본 정보 / 펼친 시술)별 dirty 추적.
- dirty 상태에서 다른 클라이언트 클릭 → 모달: **"저장하고 이동"(기본) / 저장 안 하고 이동 / 취소**.
- dirty 상태에서 탭 닫기/새로고침 → 브라우저 기본 beforeunload 경고.
- 범위 명시: 사이드바로 다른 페이지 이동(클라이언트 사이드 라우팅)은 beforeunload가 걸리지 않는다.
  Next.js 라우터 차단은 별도 장치가 필요해 이번 범위 밖 — 페이지 내 클라이언트 전환 유실(실사용 빈도 최고)만 막는다.

## 상태 처리

- 로딩: "불러오는 중…" / 실패: "목록을 불러오지 못했습니다" + 다시 시도 버튼 (실패를 빈 상태로 위장하지 않음)
- 클라이언트 0개: 중앙 빈 상태 — 목적 설명("클리닉 정보와 금지 표현을 등록해두면 원고를 만들 때마다 자동으로 반영돼요") + "+ 새 클라이언트" CTA.
  생성 페이지의 "등록하러 가기" 링크 도착점이므로 목적 설명 필수.

## 구현 노트

- 파일: `src/app/clients/page.tsx` 전면 개편 (layout.tsx의 GlobalShell 유지).
- 요약 계산(채움 판정·금지 합산·요약 문구)은 순수 함수로 분리 — `src/lib/clientSummary.ts` (tsx 단독 테스트 가능).
- 스타일: 기존 토큰만 사용 (x-* 팔레트, text-content/ui/caption 3단계). 새 토큰 없음.
  미입력 경고 주황은 인라인 amber(#b45309 / #fef3c7) — 앱에 경고색 토큰이 없어 이 페이지 한정.
- API 변경 없음. "마지막 수정" 표기는 데이터에 수정 시각이 없어 제외(원하면 별도 개발).
