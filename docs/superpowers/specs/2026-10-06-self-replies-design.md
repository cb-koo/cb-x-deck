# 인플 본인 댓글(추가 콘텐츠)을 작업에 붙이기 — 설계

- 날짜: 2026-10-06 · 브랜치 `cb-koo/self-replies`(origin/main `b5b8cf2`에서)
- DB 변경 없음(마이그레이션 0) — 기존 `tracked_post`(task_id·role)·`post_metric_snapshot`을 쓴다

## 1. 왜 (koo 10-06, 요청 사례)

인플이 협찬 게시물에 **본인 댓글로 추가 콘텐츠**(클리닉 홍보 문구 + 트래킹 링크)를 다는 경우가 있다. 실례: @nasu_seikei 더스퀘어치과_10월2주차 인용RT — 본 게시물 2107390523338313767(조회 1,027)에 1시간 24분 뒤 본인 댓글 2107411769601962491(`pages.s.gy/thesquaredc_jp` 링크, 조회 42). 지금은 본 게시물만 작업에 붙어 댓글이 패널·성과 어디에도 안 보인다.

## 2. 결정 (koo 10-06 "추천안으로")

1. **자동으로 찾아 붙인다.** 게시 확인할 때와 캠페인 성과 업데이트(↻) 때 본 게시물의 **본인 스레드**(같은 작성자의 이어지는 댓글)를 조회해, 아직 안 붙은 본인 댓글을 그 작업에 붙인다. 인플이 몇 시간 뒤 댓글을 다는 경우가 많아 ↻ 때 다시 찾는 게 핵심.
2. **성과 숫자는 본 게시물 기준.** 조회·좋아요 등 작업 지표 = 작업의 게시물 링크(`campaign_task.post_url`)가 가리키는 게시물 하나. 댓글 지표는 합산하지 않는다(댓글을 보는 사람은 대부분 본 게시물을 본 사람 — 두 번 세짐). 댓글의 링크 클릭은 트래킹 링크가 따로 센다.
3. **패널엔 따로 보여준다.** 본 게시물 카드 아래 `인플 댓글 N개`(접힘) → 펼치면 댓글마다 본문·링크·게시 시각·조회.

## 3. 찾기 규칙

- 대상: 게시물 링크가 있는 작업(투고·인용RT·방문협찬). RT는 자기 게시물이 없어 제외. 취소 작업 제외.
- 조회: getxapi `getTweetThread(본 게시물 id)` 한 번 — 같은 작성자의 연속 스레드가 온다. **작성자 고유번호가 본 게시물 작성자와 같은 트윗만**, 본 게시물 자신 제외, 본 게시물보다 먼저 쓴 글 제외. **본 게시물에서 이어지는 본인 댓글 사슬만** — 답글 대상(`inReplyToId`)이 본 게시물이거나 이미 사슬에 든 본인 댓글이어야 한다(아래쪽 팬 댓글에 단 답글·답글 대상을 모르는 글은 붙이지 않는다).
- 붙이기: 아직 `tracked_post`에 없는 트윗은 등록(첫 스냅샷은 그 댓글의 상세 조회 값 — §4) 후 그 작업에 연결. 이미 있으면 연결만 확인(다른 작업이나 원고에 붙어 있으면 건드리지 않는다 — 원고 연결을 덮어쓰지 않는다). 작성자 검사(post-author-guard)는 같은 작성자라 통과하지만, 연결은 기존 가드 경로를 그대로 거친다.
- 역할(role)은 저장하지 않는다(null) — 기존 `assignRoles`가 읽을 때 트래킹 링크가 든 댓글은 `link`, 아니면 `thread`로 판정.
- 실패(조회 오류·한도)는 게시 확인·↻를 막지 않는다 — 조용히 건너뛰고 다음 ↻에서 다시 찾는다. 댓글 찾기 조회는 재시도를 1회로 줄인 클라이언트로 하고(429 대기 누적 방지), 게시 확인 때는 전체 대기도 8초에서 끊는다(응답을 오래 붙잡지 않게).

## 4. 성과 업데이트(↻)

- 게시물마다 상세 조회 1회(기존과 같음) + **작업당 스레드 조회 1회**로 새 댓글을 찾아 붙인다. 스레드 조회는 새 댓글 찾기에만 쓰고, 지표 기록은 게시물별 상세 조회로 한다(스레드 응답엔 링크 정보 칸이 없어 링크 댓글 판정이 깨지므로). 그래서 ↻ 한 번에 작업당 조회가 1회 늘어난다(정확성 우선). 스레드 조회가 실패해도 ↻는 그대로 끝난다. 본 게시물이 이번 ↻에서 '없음'(삭제·비공개)으로 나온 작업은 스레드를 보지 않는다(헛조회 비용). 결과 숫자에 `새 댓글 N개` 추가.
- 삭제·비공개 판정(markUnavailable)은 기존과 같게 유지.

## 5. 작업 지표 = 본 게시물만

- `campaignStore`(캠페인 화면 성과)·`influencerPerformanceStore`(인플루언서 성과)의 작업 지표 합산을 **post_url 트윗 id와 같은 tracked_post 하나**로 바꾼다. post_url이 없거나 그 트윗이 트래킹에 없으면 지금처럼(붙은 게시물 중 가장 이른 본 게시물) 대신한다.
- 콘텐츠 성과(`/performance`)는 main 역할만 조회로 쓴다. 그 main도 **작업의 post_url 트윗으로 고정**한다(`assignRoles`의 `mainTweetId`) — 본 게시물에 트래킹 링크가 있고 댓글엔 없으면 예전 규칙으론 본 게시물이 `link`, 댓글이 `main`이 돼 캠페인 화면과 다른 게시물을 셌다. 사람이 고친 역할(role)은 여전히 이긴다. 트래킹 화면의 역할 표시도 같은 판정.
- 09-30 기준 작업 대부분은 게시물이 1개라 숫자 변화는 거의 없다(변하는 작업 목록을 배포 전 확인).

## 6. 패널 표시 (캠페인 v2 작업 패널 `PostedBox`, 게시된 투고·인용RT·방문협찬)

- 본 게시물 카드 아래: `인플 댓글 N개 ▸`(0개면 안 보임). 펼치면 댓글마다 한 줄 카드: 본문 2줄 말줄임 · 링크가 있으면 링크 칩 · `본 게시물 1시간 24분 뒤` · `조회 42` · `↗`(X에서 열기).
- 도움말 한 줄(펼친 안쪽 아래): `인플이 단 댓글은 게시 확인·성과 업데이트 때 자동으로 찾아요 · 성과 숫자엔 더하지 않아요`.
- 모양은 기존 패널 카드·글자 크기 체계(14~15px, 흐린 보조 글자)를 따른다.

## 7. 테스트

- 순수: 스레드 응답 → "붙일 본인 댓글" 고르기(작성자 고유번호 일치·본 게시물 제외·이미 붙은 것 제외), 작업 지표가 post_url 트윗만 쓰는지.
- DB(연습용, getxapi는 대역): 게시 확인 시 댓글 자동 연결, ↻ 시 새 댓글 추가·기존 댓글 스냅샷, 다른 작업에 붙은 트윗은 건드리지 않음, 캠페인·인플 성과가 댓글을 합산하지 않음.

## 8. 업데이트 소식

`개선`: `인플이 댓글로 단 추가 콘텐츠도 작업에서 볼 수 있어요` — 자동으로 찾고, 패널에 따로 보이고, 성과 숫자는 본 게시물 기준.

## 9. 패널 모양 다시 (koo 10-06 시안 A) — §6 대체

koo: 접힌 UI가 별로, X와 다른 레이아웃, `본 게시물 1시간 24분 뒤` 문구는 불필요.
- **접지 않는다.** 본 게시물 카드(`QuotedCard`)와 같은 카드 안에서 **X 본인 스레드 모양**으로 잇는다: 글마다 `프로필 사진 | 이름 @핸들 · M월 D일 HH:mm / 본문 / (첫 글은 미디어) / 조회 N · 좋아요 N`, 프로필 사진 아래 세로선이 다음 글 사진까지 이어진다. 마지막 글엔 세로선 없음. 댓글 글엔 X에서 열기 `↗`(32px 이상 터치 영역).
- 시각은 X처럼 실제 게시 시각(서울). 상대 시간 문구(`…뒤`) 없음.
- 댓글 본문은 줄바꿈 유지, 링크는 파란 글자 링크(새 창, noopener noreferrer). 길면 3줄 말줄임.
- 카드 아래 한 줄 도움말(댓글이 있을 때만): `인플이 이어 단 글은 자동으로 찾아요 · 성과 숫자는 첫 글만 세요`.
- 댓글이 없으면 지금 본 게시물 카드 그대로(변화 없음).
