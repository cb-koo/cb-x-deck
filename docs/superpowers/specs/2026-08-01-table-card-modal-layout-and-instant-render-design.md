# 표 보기 카드 팝업 — X 모달 레이아웃 · 즉시 렌더 (설계)

2026-08-01. 앞선 설계(`2026-08-01-table-row-tweet-card-modal-design.md`)로 만든 팝업을 사용자가 실제로 써보고 나온 세 가지 요청을 다룬다.

**요청.**
1. X의 '게시하기' 모달 레이아웃을 참고해 팝업 디자인을 고쳐달라 — 폰트·배치·구성 요소 비율까지.
2. 상단에 컬럼명을 넣고, 수집·갱신 정보도 상단으로 올려달라.
3. 행을 클릭한 뒤 내용이 뜨기까지 걸리는 시간을 줄여달라.

## 사용자가 확정한 것

| 질문 | 결정 |
|---|---|
| 모달 크롬을 어디까지 X식으로 | **상단만**(B). ✕는 왼쪽, 오른쪽에 파란 텍스트 액션, 그 아래 컬럼명·수집 정보 줄. 카드 안 회색 툴바(답글·스레드·리포스터 + 저장)는 지금 자리 그대로 — 저장을 모달 푸터의 파란 알약으로 승격하는 A안은 채택하지 않음 |
| 수집·갱신 중복 | **B-2.** 회색 툴바는 유지하고 그 아래 수집·갱신 **한 줄만** 끈다. 위아래 두 번 나오면 "위로 이동"이 "위에도 추가"가 되기 때문 |
| 지표 아이콘 | 이미 X 원본 SVG였다(`XIcons.tsx`) — **손대지 않는다.** 시안이 이모지라 달라 보였을 뿐 |
| 성능 | **즉시 렌더 + 캐시.** 행 hover 선반입은 넣지 않는다 |
| `TableRow`에 `firstSeenAt` 추가 | **한다** |

## 측정 — 무엇이 느렸나

로컬(한국) → 싱가포르 DB 기준.

| 구간 | 값 | 비고 |
|---|---|---|
| 라우트 자체 | 8ms | 무시 가능 |
| 인증 확인 `supabase.auth.getUser()` | 30~45ms | 매 API 호출마다 인증 서버로 네트워크 요청 |
| `getWorkspaceTweet` | 150ms | 이 중 74ms가 순수 왕복. 프로덕션은 앱이 sin1이라 왕복이 거의 0 → 실제 쿼리 비용 ~76ms |

서버 쪽 합계 약 200ms. 나머지 체감은 카드가 뜬 뒤 X CDN에서 받는 이미지(아바타 + 미디어)다.

**그래서 쿼리를 더 깎지 않는다.** 200ms를 100ms로 줄이는 것보다 **기다림을 없애는 쪽**이 크다 — 표 행이 이미 카드 내용의 대부분을 들고 있으므로 클릭 즉시 그걸로 그리고 나머지만 채운다. 앞 설계 §D에서 "렌더 경로가 둘이 된다"며 배제했던 방법이고, 이번 실사용 피드백으로 뒤집는다.

## 원칙

- **표와 팝업이 같은 말을 쓰고 같은 시간대로 찍는다.** 팝업은 표 바로 위에 뜬다 — 같은 값을 다르게 부르거나 다른 시간대로 찍으면 사용자는 서로 다른 값이라고 읽는다(§B-2).
- **카드는 여전히 X 미러링 그대로.** 이번에도 카드 안쪽 배치는 바꾸지 않는다. 바뀌는 것은 모달 크롬과, 카드 맨 아래 한 줄을 끄는 옵션뿐이다.
- **즉시 렌더가 실패 처리를 단순하게 만든다.** 본문이 이미 화면에 있으므로 실패는 "일부를 못 불러왔다"로 줄어든다 — 지금처럼 카드 전체가 안 뜨는 상태가 사라진다.

## A. 팝업 레이아웃

```
┌───────────────────────────────────────┐
│ ✕                             원문 ↗  │  모달 상단 바 (X 게시 모달과 같은 배치)
│ [피부타입] [항노화]   수집 '26.07.28 · 최종 수집 '26.08.01 14:20 │
├───────────────────────────────────────┤
│ (TweetCard 그대로 — 흰 카드)           │
│  아바타 / 계정 / 본문 / 미디어 / 지표   │
├───────────────────────────────────────┤
│ 답글 스레드 리포스터        ☆ 저장     │  카드의 회색 툴바 (그대로)
└───────────────────────────────────────┘
```

**A-1. 상단 바.** `✕`는 **왼쪽**(지금은 오른쪽), 오른쪽에는 `원문 ↗`을 X 파랑 텍스트로. X 게시 모달의 `✕ … 초안` 배치를 그대로 옮긴 것이다. 높이 53px, 좌우 여백 8px, ✕는 34px 원형 히트 영역.

**A-2. 메타 줄.** 상단 바 아래 한 줄. 왼쪽은 **컬럼명 알약**(`TableRow.columnTitles`), 오른쪽은 **수집·최종 수집**. 좌우 여백 16px, 아래 여백 12px.

- 컬럼명 알약: 테두리 `x-border-strong`, 둥근 알약, 13px bold, 보조색. 여러 개면 줄바꿈.
- 컬럼이 없을 수는 없다(표에 뜬 행은 반드시 어떤 컬럼에 걸려 있다) — 빈 배열 방어만 하고 별도 빈 상태 문구는 두지 않는다.

**A-3. 카드.** `TweetCard`를 그대로 렌더한다. 회색 툴바도 그대로. 유일한 변화는 A-4.

**A-4. `TweetCard`에 `showCollectedAt?: boolean` 추가(기본 `true`).** `false`면 풋터 존 맨 아래 `수집 … · 갱신 …` 한 줄을 렌더하지 않는다. 팝업만 `false`를 넘긴다 — 덱 카드는 기본값이라 지금 그대로다. 이 프롭 하나가 이번 변경에서 `TweetCard`를 건드리는 전부다.

**A-5. 타이포.** 카드 안쪽은 기존 값 그대로(이름 15px bold, 핸들·본문 15px, 지표 13px, 아이콘 18px). 새로 만드는 것은 상단 바(액션 15px bold)와 메타 줄(13px)뿐이다.

## B. 표기 — 표와 어긋나지 않게

### B-1. 발견한 문제

같은 값이 두 이름으로 불리고, 두 시간대로 찍히고 있다.

| 값 | 표 | 카드 하단 |
|---|---|---|
| `lastFetchedAt` | `최종 수집 시간` 칸, **한국 시간**, `YYYY-MM-DD HH:MM` | `갱신`, **UTC**, `'26.08.01` |
| `firstSeenAt` | (없음) | `수집`, **UTC** |

팝업 헤더는 표 바로 위에 뜬다. 여기에 카드 어휘("수집 · 갱신")를 그대로 옮기면 아래 칸의 "최종 수집 시간"과 다른 값처럼 보이고, UTC로 찍으면 같은 트윗의 날짜가 표와 하루 다르게 보일 수 있다.

### B-2. 결정

**팝업 헤더는 표의 어휘와 시간대를 따른다.**

- `firstSeenAt` → **`수집`**, `ymd` (한국 시간, 날짜만)
- `lastFetchedAt` → **`최종 수집`**, `ymdHm` (한국 시간, 분까지 — 같은 날 09시와 22시 새로고침이 같은 값으로 보이면 안 된다는 표의 판단을 그대로 따른다)

`tableColumns.ts`의 `ymd`·`ymdHm`은 지금 모듈 안에만 있다 — **export 해서 팝업이 같은 함수를 쓴다.** 같은 규칙을 두 번 구현하면 언젠가 갈라진다.

덱 카드 하단의 `수집 · 갱신`(UTC)은 이번 범위가 아니다 — 카드 보기 화면엔 표 칸이 함께 보이지 않아 화면 위에서 모순이 드러나지 않는다. 백로그로 남긴다.

## C. 즉시 렌더

### C-1. `TableRow`에 `firstSeenAt` 추가

`getWorkspaceTableRows`의 select에 `t.first_seen_at`을 더하고 `TableRow`에 `firstSeenAt: string`(ISO)을 추가한다.

앞 설계의 "표 API를 건드리지 않는다"를 **의도적으로 좁혀 되돌린다.** 그 제약의 취지는 *미디어·인용RT JSON으로 CSV 페이로드(최대 5,000행)를 부풀리지 말자*였다. 날짜 문자열 하나는 그 취지를 어기지 않고, 없으면 헤더가 "최종 수집 …"으로 떴다가 200ms 뒤 "수집 … · 최종 수집 …"으로 바뀌는 깜빡임이 생긴다. CSV 출력 자체는 `TABLE_COLUMNS` 기준이라 변하지 않는다(새 칸을 추가하지 않는다).

### C-2. 잠정 카드

행을 누르면 그 행(`TableRow`)으로 `StoredTweet` 모양을 만들어 **즉시** 렌더한다.

| 필드 | 잠정값 | 도착 후 |
|---|---|---|
| `tweetId` `authorHandle` `authorName` `authorFollowers` `text` `metrics` `tweetCreatedAt` `savedBy` `firstSeenAt` `lastFetchedAt` | 행 값 그대로 | 동일(서버 값으로 교체) |
| `authorAvatarUrl` | `null` — `TweetCard`가 이미 회색 원으로 그린다 | 실제 이미지 |
| `media` | `[]` | 실제 미디어 |
| `quoted` | `null` | 인용RT(+캐시된 원문) |
| `tweetUrl` | `null` — `TweetCard`가 시각을 링크 없는 텍스트로 그린다 | 실제 URL |
| `isNew` | `false` | `false`(표에는 NEW 개념이 없다) |

도착하면 통째로 교체한다. 미디어가 있으면 그때 나타나면서 아래 내용이 밀리는데, 이는 이미지 지연 로딩과 같은 성질이라 감수한다.

### C-3. 캐시

`TweetTableView`가 `useRef<Map<string, StoredTweet>>`을 들고, 조회에 성공하면 넣는다. 이미 있는 트윗을 다시 열면 잠정 카드 없이 곧바로 완성본으로 뜨고 네트워크를 타지 않는다.

캐시를 비우는 시점은 **워크스페이스 전환과 표 재조회**다 — 지표가 갱신됐는데 캐시가 옛 숫자를 보여주면 표와 팝업이 어긋난다.

### C-4. 행이 없을 때

캐시에도 없고 표 행도 찾을 수 없는 경우(팝업이 열린 사이 목록이 다시 로드돼 그 행이 빠진 경우)는 지금처럼 "불러오는 중…"으로 시작해 조회 결과를 기다린다. 즉시 렌더는 행이 있을 때의 최적화이지 대체가 아니다.

### C-5. 즉시 렌더가 만드는 경합 — 저장이 되돌아가지 않게

**구현 중 리뷰에서 발견해 설계에 되먹인 항목이다.** 잠정 카드는 조회가 끝나기 전부터 눌린다 — 그게 이 기능의 목적이다. 그래서 조회를 기다리는 사이 사용자가 저장할 수 있고, 마운트 시점에 나간 조회는 그 저장 **이전**의 저장자 목록을 들고 돌아온다. 그대로 받아들이면 방금 한 저장이 화면에서 되돌아가고, 그 상태가 캐시에 들어가 닫았다 열어도 계속 틀린다.

규칙은 두 방향 모두 정한다:

- **이 팝업 안에서 저장 상태를 직접 바꿨으면**(저장·취소·실패 롤백) 그 값이 도착한 조회 결과를 이긴다. 세 경우가 한 함수(`applySavedBy`)를 지나므로 그 지점에서 한 번만 기록하면 된다.
- **손대지 않았으면** 조회 결과가 맞다 — 그 사이 다른 멤버가 저장했을 수 있고 그건 서버가 안다. 이때는 **표 행에도 전파한다.** 팝업과 캐시만 갱신하고 표를 놔두면, 팝업을 닫는 순간 표의 '저장' 칸이 옛 이름을 보여주는 모순이 남는다.

### C-6. 남는 불일치 하나 — 받아온 카드가 표 행보다 새로울 수 있다

표를 불러온 뒤 컬럼 새로고침이 돌면, 팝업은 새 지표와 새 '최종 수집'을 보여주는데 뒤의 행은 옛 값을 들고 있다. **팝업이 맞고 행이 낡은 것**이라 위험하지는 않지만, 두 값이 나란히 보이면 어긋나 보인다. 조회해서 교체하는 방식에 딸린 성질이라 없애려면 표 전체를 다시 부르는 수밖에 없고 그건 이 기능의 취지에 반한다 — 감수하고, 버그로 다시 발견되지 않게 여기 적어둔다.

## F. 하지 않는 것

- **행 hover 선반입** — 사용자가 뺐다. 즉시 렌더 + 캐시로 충분한지 먼저 본다.
- **저장을 모달 푸터로 승격(A안)** — 사용자가 B를 골랐다. 카드의 회색 툴바는 그대로.
- **지표 아이콘 교체** — 이미 X 원본이다.
- **인증 확인 방식 변경** — `supabase.auth.getUser()`가 호출마다 30~45ms를 쓰지만, 이건 앱의 모든 라우트에 걸린 문제라 이 기능의 범위가 아니다. 백로그(§G).
- **덱 카드 하단 '갱신' 표기·시간대 통일** — 백로그(§G).

## G. 백로그로 남기는 것

- **`supabase.auth.getUser()` 호출당 왕복.** 매 API 호출이 인증 서버로 네트워크 요청을 한다(측정 30~45ms). supabase-js 2.110에는 JWT를 로컬에서 검증하는 `getClaims()`가 있다 — 전 라우트에 걸린 개선이라 별도 과제로 다룰 값어치가 있다.
- **앱 전체 날짜 표기·시간대를 서울로 통일** — 2026-08-01에 범위만 조사하고 착수는 미뤘다(사용자 결정: "다음에"). 아래가 그 조사 결과다. 다시 조사하지 말 것.

  | UTC로 표시 | `format.ts`의 `formatDate`(`getUTC*`) → 덱 카드 `수집·갱신`, `research/page.tsx`의 발행일 | 한국 오전 9시 이전 값이 하루 전으로 보인다 |
  | '오늘'을 UTC로 계산 | `TweetTableView.tsx`(CSV 파일명), `BriefingSection.tsx`(`untilDate` 기본값), `TrendPanel.tsx`(같음), `api/research/density/route.ts`(`since`) | 한국 새벽 0~9시에 **하루 밀린다** — 표시가 아니라 동작 버그 |
  | 브라우저 로컬 | `TweetCard.timeAgo`의 날짜 폴백, `CandidateCard`의 저장일(`toLocaleDateString('ko-KR')`) | 한국에서 보면 맞지만 고정돼 있지 않다 |
  | 이름만 어긋남 | `usageStore.ts`의 `at time zone 'Asia/Tokyo'` | 오프셋이 같아 숫자는 동일. 이름만 정리 |

  **★ 건드리면 안 되는 곳** — `getUTC*`가 보인다고 전부 바꾸면 오히려 깨진다. **날짜 전용 문자열**(`YYYY-MM-DD`)을 `'T00:00:00Z'`로 파싱해 `getUTC*`로 읽는 것은 **정확한 왕복**이다: `briefing.ts`의 주차 라벨, `trend.ts`의 `weekStart` 계산, `tableFilter.ts`의 날짜 유효성 검사, `actualCost.ts`의 `ymd(Date)`(Exa API 파라미터), `BriefingSection`의 `fmtDay`·`fmtWeekRange`. 여기에 +9를 먹이면 날짜가 밀린다. 계획에 "바꾸지 않는 것"으로 명시해야 한다.

  **구조 정리**: KST 변환(`toKstIso`)이 지금 `tableColumns.ts`에 있다 — 표 전용 파일에 앱 전체 관심사가 들어가 있다. `format.ts`(또는 새 `datetime.ts`)로 옮겨 `formatDate`·`ymd`·`ymdHm`·`today()`가 한 곳에서 나오게 한다. 그래야 다음에 또 갈라지지 않는다.

  **규모**: 파일 9개 · 호출부 10곳 · 작업 5개 안팎, 한 세션. 순수 함수가 많아 실 DB 없이 검증되는 비중이 크다.

  **착수 전 정할 것 둘**: ①브리핑의 `fmtDayJst`가 JST인 게 의도인가(일본 트윗 제품이라 의도일 수 있다. 오프셋이 같아 서울로 통일해도 화면은 안 바뀐다) ②`timeAgo`·저장일처럼 브라우저 로컬을 쓰는 곳도 서울로 고정할 것인가(고정하면 해외에서도 같은 값이 보인다).
