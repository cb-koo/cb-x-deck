# 보관함 공유 코멘트 뷰 (Option A) — 설계

2026-07-13. 배경: v1.5에서 candidate가 트윗×워크스페이스×멤버당 1행이 되어, 같은 트윗을 여러 멤버가 각자 메모와 함께 저장할 수 있다. 현재 보관함 UI는 이를 멤버별로 격리된 카드로 보여준다. 이를 **콘텐츠당 카드 1장 + 멤버별 코멘트 나열**로 병합해, 한 콘텐츠에 대한 팀 의견을 한눈에 보게 한다.

**Option B(공유 candidate + candidate_comment 테이블, 멀티 코멘트 스레드)는 이연** — 실사용에서 "코멘트에 답글" 요구가 생기면 승격. A의 memo 데이터는 B의 첫 코멘트로 무손실 이관 가능.

## 원칙

- **스키마·API 무변경.** candidate 유니크(tweet×ws×member)와 기존 라우트를 그대로 쓰고, 그룹핑은 클라이언트에서 한다. 팀 규모(수 명)·후보 수(수백)에서 전량 fetch 후 클라이언트 필터는 충분하다.
- **코멘트 = 멤버의 candidate.memo.** 멤버당 콘텐츠당 코멘트 1개(덮어쓰기 편집). 별도 코멘트 엔티티를 만들지 않는다.

## 동작 정의

1. **그룹핑**: 보관함은 워크스페이스 전체 후보를 받아 `tweet_id`로 그룹핑, 그룹당 카드 1장. 정렬은 그룹 내 최신 `saved_at` 내림차순.
2. **코멘트 표시**: 카드 하단에 멤버별 행 — 아바타 점·이름·저장일·memo·그 멤버의 태그. 내(현재 선택 멤버) 행만 편집 가능(memo textarea, 태그 추가/삭제, 저장 취소). 타인 행은 읽기 전용.
3. **미저장 멤버의 코멘트**: 내 행이 없으면 "코멘트 달기" 입력 노출. 제출 시 `POST /api/candidates`(저장) → `PATCH memo`. 즉 코멘트를 달면 내 저장으로 계산된다(A 모델의 의미론).
4. **저장 취소**: 내 candidate 행만 삭제(내 코멘트·태그 소멸). 다른 멤버 행이 남아 있으면 카드 유지, 마지막이면 카드 소멸.
5. **멤버 필터**: "이 멤버가 저장(코멘트)한 콘텐츠"로 그룹을 선별. 선별된 카드에는 여전히 전원 코멘트 표시(공유 가시성이 목적).
6. **태그 필터**: 그룹 내 어느 멤버든 해당 태그를 붙였으면 매칭.
7. **태그 카운트**(`listAllTags`): candidate 행 수 → **distinct tweet 수**로 보정(두 멤버가 같은 콘텐츠에 같은 태그 = 1).
8. **건수 표시**: 보관함 헤더 카운트는 그룹(콘텐츠) 수.

## 구현 구조

- `src/lib/candidateGroups.ts` (신규): `groupCandidates(rows) → CandidateGroup[]`, `filterGroups(groups, {memberId, tag})` — 순수 함수, 단위 테스트 동반.
- `src/app/w/[wsId]/library/page.tsx`: 전량 fetch(쿼리 파라미터 제거) → 그룹핑 → 클라이언트 필터. 서버 필터 파라미터는 API에 남겨두되 보관함에선 미사용.
- `src/components/CandidateCard.tsx`: 그룹 단위 카드로 개편 — TweetCard 1회 + 코멘트 리스트 + 내 행 편집 UI + 미저장 시 코멘트 달기.
- `candidateStore.listAllTags`: `count(c.id)` → `count(distinct c.tweet_id)`.

## 변경하지 않는 것

- 덱의 저장 토글·savedBy 배지, `/api/candidates` CRUD 의미론, DB 스키마, 태그 전역 네임스페이스.

## 검증

- 단위: candidateGroups 그룹핑·정렬·멤버/태그 필터, listAllTags distinct 카운트(기존 통합 테스트 보강).
- 수동: 멤버 2명으로 같은 트윗 저장→카드 1장에 코멘트 2개, 타인 행 편집 불가, 코멘트 달기→저장 계산, 내 행 삭제→카드 유지/최후 삭제→카드 소멸, 필터 조합.
