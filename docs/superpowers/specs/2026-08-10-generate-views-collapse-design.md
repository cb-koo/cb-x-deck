# /generate 뷰 다양화 + 생성 패널 접기 설계 (2026-08-10, 워크벤치 2차)

## 배경과 목표

1차 개편(2단 워크벤치, `2026-08-10-generate-workbench-design.md`)으로 생성 루프는 해결됐으나, 초안이 20건 이상 쌓이자 두 가지 피드백이 나왔다:

1. 카드의 상태 변경 칩(초안→검수 대기→사용 확정→전달됨/미사용)이 캡션 크기라 **행동 컨트롤인데 메타 정보처럼 보인다**
2. 카드 피드로는 **파이프라인 관리가 안 된다** — "전체가 어느 단계에 얼마나 쌓여 있고 뭐부터 처리하나"에 답을 못 함 → 노션식 테이블·칸반 요청

근본 진단: 페이지가 상태를 "속성"으로 다루는데 사용자는 "파이프라인"으로 쓴다. 시안 비교(A: 뷰 전환 통합 / B: 검수 데스크 분리)에서 **A안 채택** + A의 약점(관리 중 좌패널이 자리만 차지)을 **생성 패널 접기**로 보완하기로 확정.

**목표**: 우측 결과 영역에 카드/테이블/칸반 뷰 전환을 추가하고(카드=정독, 테이블=트리아지, 칸반=파이프라인), 좌 생성 패널을 레일형으로 접을 수 있게 한다(뷰 연동 자동 + 수동 우선). 서버·API·DB 변경 없음.

## 확정 결정

- **뷰 3종**: 카드(현행 유지) / 테이블 / 칸반. 토글은 필터 헤더 행에 배치, 선택은 localStorage `cbx-generate-view`에 저장(뷰는 렌즈가 아니라 작업 방식 선호 — 필터와 달리 유지).
- **칸반 = 상태 5열**(DRAFT_STATUSES 순서). 열 위치가 곧 상태이므로 상태 시인성 문제를 구조로 해소. 칸반에서는 상태 탭 숨김(중복), 클라이언트 필터만 유지.
- **생성 패널 접기**: 접으면 ~48px 레일(펼치기 화살표 + 새 원고 아이콘). 테이블/칸반 전환 시 자동 접힘, 카드 뷰 복귀 시 자동 펼침. **수동 토글이 자동 규칙에 우선**(세션 내 기억). 전역 사이드바 접기는 별도 백로그.
- **일괄 처리(일괄 승인 등)는 이번 범위 제외** — B안 요소는 마찰 확인 후.

## 데이터·상태 모델 (page.tsx 로컬 상태만)

```ts
type ResultView = 'cards' | 'table' | 'kanban';
const VIEW_KEY = 'cbx-generate-view';           // 복원 시 미지원 값은 'cards'로
const [view, setView] = useState<ResultView>('cards');
// 패널 접힘: null=자동(뷰 연동), 'open'|'closed'=수동 고정(세션 한정 — 저장 안 함)
const [panelPref, setPanelPref] = useState<'open' | 'closed' | null>(null);
const panelOpen = panelPref !== null ? panelPref === 'open' : view === 'cards';
```

- 뷰 전환은 `setView`만 — `panelPref`를 건드리지 않는다(수동 우선의 구현).
- 필터(`DraftListFilter`)는 현행대로 세션 렌즈(저장 안 함). 칸반에서는 `filter.status`를 **무시**하고 전 상태를 열로 표시(탭 숨김과 일관), 클라이언트 필터만 적용.
- 기존 T11 로직(생성 결과가 필터에 가려지면 필터 리셋)은 카드·테이블 뷰에서 유지. 칸반은 상태 필터가 없으므로 새 초안(초안 열)이 항상 보인다 — 리셋 불필요하지만 로직을 뷰별로 분기하지 않고 그대로 둔다(무해: status 'all' 리셋은 칸반 표시에 영향 없음).

## 레이아웃 변경 (page.tsx)

```
좌 컬럼 (bg-x-surface):
  panelOpen  → 현행 그대로(스크롤 영역 + ComposerFooter), lg:w-[var(--panel-w)]
  !panelOpen → w-12 레일: [»] 펼치기 버튼(aria-label "생성 패널 펼치기")
               + [✚] 새 원고 버튼(누르면 패널 펼침 — 비용 액션은 조건이 보이는 상태에서만, 원칙 2·6)
               + generating 중이면 스피너 점(레일에서도 진행 중임이 보이게)
  패널 우상단(펼침 상태)에 [«] 접기 버튼 추가
구분선(리사이즈 핸들): panelOpen일 때만 렌더 (접힘 상태에선 숨김)
우 컬럼:
  필터 헤더 행: [뷰 토글 카드|테이블|칸반] + (view !== 'kanban'일 때) 상태 탭 + 클라이언트 필터
  본문: view에 따라 카드 피드(현행) / <DraftTable> / <DraftKanban>
```

- 접기/펼치기 버튼은 텍스트 없는 아이콘이므로 `aria-label` + `title` 필수.
- `<lg`(스택 폴백)에서는 접기 개념 없음 — 레일·접기 버튼 숨기고 항상 펼침(현행 스택 그대로). 뷰 토글은 좁은 화면에서도 동작(칸반은 열 가로 스크롤).
- 스켈레톤·빈 상태 2종·모달·토스트는 뷰와 무관하게 현행 유지. 단 스켈레톤·빈 상태는 카드 뷰 전용 표현이므로: 테이블/칸반 뷰에서 `generating`이면 해당 뷰 상단에 한 줄 진행 배너("원고 작성 중… 완성되면 초안으로 나타나요")로 대체, 빈 상태(0건)는 뷰 공통 문구 그대로 중앙 표시.

## 신규 컴포넌트

### `src/components/DraftTable.tsx` — 트리아지용 테이블
- 컬럼: 원고(첫 포스트 첫 줄, 1줄 말줄임) · 클라이언트 · 시술 · 형식(단문/스레드) · 상태(DraftStatusChip 재사용 — 행에서 바로 변경) · 생성일(상대 시간).
- 정렬: 헤더 클릭으로 생성일(기본, 최신순)·클라이언트·상태 3개 컬럼 토글 정렬. 정렬 상태는 저장 안 함.
- 행 클릭 → `onOpenCard(draftId)`: 카드 뷰로 전환 + 해당 카드로 스크롤 + 1.5초 하이라이트(테이블=찾기, 카드=정독의 연결). 행 안의 상태 칩 클릭은 행 클릭으로 전파되지 않게 stopPropagation.
- 클라이언트명은 page가 내려주는 `clientNameOf(clientId)`로 표시(없으면 "—").
- 표면: 도구층(Reading 스케일). `w-full` 테이블, 헤더 행 `bg-x-surface` 고정 없음(컨테이너가 이미 스크롤).

### `src/components/DraftKanban.tsx` — 파이프라인용 칸반
- 5열 = `DRAFT_STATUSES` 순서, 열 헤더 = `STATUS_LABEL` + 건수 배지 + 상태색 점(기존 DraftStatusChip의 색 체계 재사용).
- 미니 카드: 첫 줄 훅(2줄 말줄임) + 메타(클라이언트 · 시술 · 형식) + 상대 시간. 클릭 → `onOpenCard(draftId)`(테이블과 동일한 카드 뷰 점프).
- **드래그 앤 드롭**: HTML5 네이티브 DnD(라이브러리 추가 없음). 카드 `draggable`, 열이 dropzone. 드롭 시 `onChangeStatus(draft, 열 상태)` — 기존 낙관적 갱신·실패 롤백 로직 그대로 사용. 드래그 오버 중인 열은 배경 강조. 키보드 대안: 미니 카드에도 DraftStatusChip을 넣지 않는 대신, 카드 클릭→카드 뷰의 칩으로 변경 가능함을 유지(드래그 불가 사용자의 경로 확보).
- 빈 열: 점선 테두리 + "여기로 끌어다 놓으면 상태가 바뀝니다" 캡션(첫 드래그 학습용).
- 폭: 열 최소 190px, 컨테이너 `overflow-x-auto` — 좁은 화면에서 가로 스크롤.

### `src/lib/draftViews.ts` — 뷰 공용 파생(순수 함수, 테스트 대상)
- `draftPreviewLine(d: DraftRow): string` — 편집본 우선(`edited ?? content`) 첫 포스트 첫 줄.
- `sortDrafts(list, key: 'createdAt'|'client'|'status', dir): DraftRow[]` — 테이블 정렬(안정 정렬, 원본 불변).
- `groupByStatus(list): Record<DraftStatus, DraftRow[]>` — 칸반 열 데이터(각 열 내부는 최신순).

## 기존 컴포넌트 변경

- **DraftFilterBar**: prop `showStatusTabs?: boolean`(기본 true) 추가 — 칸반에서 false. 그 외 불변.
- **뷰 토글**: DraftFilterBar 안이 아니라 page의 헤더 행에서 별도 세그먼트로 렌더(필터와 뷰는 다른 축 — 컴포넌트 책임 분리). 라벨은 "카드 · 테이블 · 칸반"(사용자 언어, 아이콘은 보조).
- **DraftCard**: 변경 없음. 카드 뷰 점프 하이라이트는 page가 카드 래퍼에 `data-draft-id` + 일시적 ring 클래스로 처리.

## 경계 조건

- **뷰 복원**: localStorage 값이 'table'/'kanban'이면 마운트 시 그 뷰로 시작 → 자동 접힘도 함께 적용(panelPref 초기값 null이므로 자연 성립).
- **생성 흐름과 접힘**: 레일 상태에서는 생성 버튼이 없다(의도 — 조건 안 보이는 생성 방지). 레일의 [✚]는 패널을 펼칠 뿐이다. 생성 중 접어도 진행은 계속되고 레일에 스피너 표시.
- **카드 뷰 점프**: 대상 초안이 현재 필터에 가려 있으면 필터를 전체로 리셋 후 스크롤(T11과 같은 계열 — 점프가 소리 없이 실패하지 않게).
- **다시 쓰기·편집·삭제 등 카드 전용 액션**: 테이블·칸반에서는 노출하지 않는다(YAGNI — 두 뷰는 트리아지·상태 이동용, 정독 액션은 카드 뷰로 점프해서).
- **드롭 실패(PATCH 오류)**: 기존 changeStatus 롤백이 카드를 원래 열로 되돌린다 — 칸반 전용 처리 불필요.
- **`/generate?ref=` 진입**: 뷰와 무관 — 레퍼런스는 좌패널 소관. 단 패널이 접혀 있으면(저장된 뷰가 테이블/칸반) ref 연결 시 패널을 자동 펼침(연결 결과가 보여야 함).

## 접근성

- 뷰 토글: `role="tablist"` 대신 단순 버튼 그룹 + `aria-pressed`. 접기/펼치기·[✚] 버튼: `aria-label`.
- 칸반 DnD는 마우스 전용 — 키보드 사용자는 카드 클릭→카드 뷰 칩 경로가 등가 기능(스펙 명시로 의도된 대안).

## 검증

- `draftViews.ts` 3개 함수는 node:test 단위 테스트(관례: tsx, `.ts` import).
- tsc 0건 / lint 기준선(24) 유지 / 기존 npm test 회귀 없음.
- DnD·접힘·뷰 전환의 화면 동작은 사용자 dev 검수(OAuth 게이팅).

## 범위 제외 (백로그)

- 전역 사이드바(앱 메뉴) 접기 — GlobalShell 소관, 전 페이지 파급
- 일괄 처리(검수 대기 모두 확정 등) — 관리 마찰 확인 후 opt-in
- 테이블 다중 선택·일괄 상태 변경, 칸반 열 내 수동 정렬(순서 저장), 뷰별 저장 필터 조합(Planable Custom Views류)
