# "한 화면에서 전체 플로우"의 예외 — 정산 요청(⑧)은 정산 페이지에 남긴다

캠페인 v2의 방향은 ①캠페인 생성부터 ⑧정산 요청까지 한 화면에서 처리하는 것이지만, 정산 요청 생성에는 분류·환율·수수료·마감일·신호등 검토가 붙어 있고 그 화면(`/settlement`)이 이미 그쪽 정산 프로덕트와의 계약을 진다. 이번에는 캠페인 v2가 **정산 대기 건수와 정산 페이지 링크(캠페인 미리 선택)** 까지만 제공하고, 요청 생성은 정산 페이지에서 한다. 통합은 이 화면이 자리 잡은 뒤 다시 본다.

## Considered Options

- 요청 생성까지 v2에서 — 검토 줄 UI를 공용 컴포넌트로 빼야 하고, 정산 계약을 지는 화면이 둘이 된다.
- "정산으로 보내기" 링크만(채택) — 손이 한 번 끊기는 타협.
- v2는 ⑥까지, 정산은 완전히 별개 — 완료 뒤 무엇을 해야 하는지 화면이 말해주지 않는다.

## Consequences

- **정산 대기 n건**은 정산 페이지와 같은 조건(게시 확인 + 비용 + 인플루언서 + 활성 요청 없음)으로 센다. 완료 건수와 다르다 — 완료 2건 중 1건이 이미 요청됐으면 대기는 1건.
- 링크는 대기 ≥ 1일 때만 보인다. 정산 페이지 검토 대기 탭은 `?tab=candidates&campaign=`으로 캠페인 필터 초기값을 받는다(정산 로직·연동 무변경). 들어갔을 때 후보가 0건이면 "이 캠페인엔 검토 대기 작업이 없어요 [전체 보기]". 탭을 바꾸면 `task`·`request`처럼 `campaign`도 URL에서 지운다.
- 정산 상태 배지(대기·요청됨·지급 완료)는 기존 작업 배지를 완료 섹션에 그대로 쓴다.
