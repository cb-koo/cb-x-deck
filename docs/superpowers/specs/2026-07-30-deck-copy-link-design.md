# 덱 카드 링크 복사 — X 공유 버튼 미러링 (설계)

2026-07-30.

**배경.** 덱에서 괜찮은 트윗을 찾아도 그 링크를 남에게 전달할 방법이 없다. 트윗 본문으로 가는 링크는 카드 안에 딱 하나, 타임스탬프(`src/components/TweetCard.tsx:105-108`)뿐이다. 링크를 얻으려면 그걸 눌러 X를 새 탭으로 열고, 주소창을 복사하고, 탭을 닫고 덱으로 돌아와야 한다. 콘텐츠 기획 담당자가 하루에 여러 번 하는 동작인데 pogosticking(체크리스트 §L-2 위반)이 매번 발생한다.

**해결.** 실제 X와 같은 자리·같은 아이콘의 공유 버튼을 카드에 두고, 누르면 링크를 클립보드에 복사한다. 덱을 벗어나지 않는다.

## 원칙

- **Jakob's Law를 최우선으로 적용한다**(체크리스트 §C). 이 앱은 X를 미러링하는 것이 제품 가치다. 사용자는 이미 X에서 "공유 아이콘 = 링크 얻기"를 학습했으므로 새로 학습시키지 않는다.
- **어포던스는 정직해야 한다.** 지표 5개는 누를 수 없고 공유만 누를 수 있다. 그 차이를 사용자가 보게 만든다.
- **한 동작에 신호는 하나.** 복사 확인은 X와 같이 하단 토스트 하나로만 준다.
- **토스트 호스트는 하나여야 한다.** `Toast`는 `fixed bottom-6 left-1/2`이므로 둘이 동시에 뜨면 겹쳐서 읽을 수 없다.

## A. 사용자가 보는 동작

```
[흰 영역 · 지표 줄]
  💬 3   ⟲ 12   ♡ 340   👁 12K   🔖 8   ↗
  └────── 읽기 전용 span ──────┘   └─ button
                                        │
                       클릭 → 클립보드 복사 → 하단 토스트
                              "링크를 복사했어요" (2.5초)
```

- 메뉴를 열지 않고 **원클릭 복사**한다. 실제 X는 공유 아이콘이 메뉴(링크 복사·DM 전송·북마크…)를 열지만, 이 덱에서 의미 있는 항목은 링크 복사 하나뿐이다. 항목 1개인 메뉴는 클릭 1회가 순수 헛수고고 Hick's Law상 이득도 없다. **아이콘의 자리와 모양은 X와 동일하게, 상호작용만 한 단계 줄인다.**
- 덱과 보관함 카드 모두에 나온다. `TweetCard`는 두 화면이 공유하는 컴포넌트이므로(`src/components/CandidateCard.tsx:32`) 이것이 기본 동작이고, 덱에만 넣으려면 오히려 분기 코드가 필요하다. 같은 카드가 화면에 따라 다르게 보이는 것도 피한다.

## B. 복사되는 링크

`https://x.com/{authorHandle}/status/{tweetId}` 를 직접 조립한다. `src/lib/tweetLink.ts`의 순수 함수로 분리한다.

기존 `tweet.tweetUrl` 필드를 쓰지 않는 이유:

- 타입상 `string | null`이다(`src/lib/types.ts:66`). 카드도 그 null을 실제로 분기 처리하고 있다(`TweetCard.tsx:105-108`). null이면 버튼이 죽는다.
- 상위 API 원본이 `twitter.com/...` 형태를 줄 수 있다. 매퍼는 `raw.url ?? raw.twitterUrl ?? 조립형` 순으로 채운다(`src/lib/mappers.ts:54`). 실제 X가 복사해주는 정규형은 `x.com`이므로 원본을 그대로 흘리면 사용자에게 도메인이 섞여 나간다.

핸들과 트윗 ID는 항상 존재하므로 조립형은 언제나 유효한 x.com 정규 링크가 된다. 브리핑 API도 이미 같은 조립 방식을 쓴다(`src/app/api/briefings/route.ts:39`).

## C. 아이콘과 버튼

- `src/components/XIcons.tsx`에 `ShareIcon`을 추가한다. X의 공유 아이콘(트레이에서 위로 나가는 화살표), 기존 아이콘과 같은 규격 — 24×24 viewBox, `currentColor`, 내부 `Icon` 래퍼 사용.
- 지표 5개는 그대로 읽기 전용 `<span>`으로 둔다. 공유만 `<button>`이다. **구분 신호:**
  - 지표는 호버 시 글자색만 바뀐다(기존 `metricBase`, `TweetCard.tsx:41`).
  - 공유 버튼은 X와 같이 **원형 배경 하이라이트**가 생긴다(파란 틴트 `x-blue/10` + `text-x-blue-text`). 이것이 "이건 누르는 것"의 신호다. §4의 "파랑은 3가지 용도로만"은 요소에 상시 붙는 의미 색을 제한하는 규칙이고 이것은 호버 상태이므로 충돌하지 않는다.
  - 공유 버튼만 옆에 숫자가 없다.
- 클릭 영역은 패딩으로 32×32를 확보하고, 음수 마진으로 지표 줄의 정렬(`justify-between`, `max-w-[425px]`)을 흐트러뜨리지 않는다. 체크리스트 §C의 44×44는 주요 CTA·터치 타깃 기준이고, 이것은 데스크톱 보조 액션이므로 X 자체 히트 영역과 같은 수준으로 맞춘다.
- `aria-label="링크 복사"`, `title`로 무엇이 복사되는지 알린다(AGENTS.md 원칙 2 — 행동 전 기대 설정).

**설계 규칙 예외를 여기 기록한다.** `docs/superpowers/specs/2026-07-19-deck-uiux-design.md` §7은 "액션·시스템 메타는 풋터 존에"를 규정한다. 공유 버튼은 그 규칙의 **의도된 예외**다. 근거: 이 앱의 제품 가치가 X 미러링이고(→ `cb-x-deck-design-system-direction`), 공유 아이콘의 위치는 X 사용자의 손버릇이므로 풋터로 옮기면 학습을 새로 요구한다. 앞으로 다른 액션을 지표 줄에 추가하려 할 때 이 예외를 선례로 삼지 않는다 — 링크 복사만 해당한다.

## D. 토스트 배선

`TweetCard`에는 토스트를 띄울 통로가 없다. 현재 `Toast`는 각 페이지가 자기 상태로 직접 렌더한다(덱: `src/app/w/[wsId]/page.tsx:20,140` / 보관함: `library/page.tsx:149-151`). 카드에서 토스트를 띄우려면 통로가 필요하고, 통로를 페이지별로 만들면 **호스트가 둘이 되어 겹침 버그**가 생긴다(보관함에서 "실행취소" 토스트가 떠 있는 동안 링크를 복사하면 실제로 겹친다).

**`src/lib/toastContext.tsx`를 만들어 `src/app/w/[wsId]/layout.tsx`에 `ToastProvider`를 마운트한다.** 기존 `MemberProvider`(`src/lib/memberContext.tsx`)와 동일한 패턴이고, 덱·보관함이 이 레이아웃을 공유하므로 토스트 호스트가 하나로 통일된다.

API:

```ts
show(message: string, opts?: {
  actionLabel?: string;
  onAction?: () => void;
  duration?: number | null;   // 기본 6000, null = 자동 소멸 없음
  dismissible?: boolean;      // 기본 true (✕ 노출)
}): void
hide(): void
```

- 기본값 6000ms는 덱의 기존 동작(`page.tsx:58`)을 그대로 옮긴 것이다. 링크 복사만 `duration: 2500`을 지정한다 — 확인용 신호라 짧아야 한다.
- 컨텍스트 기본값은 no-op으로 둔다(`memberContext`와 같은 방식). 프로바이더 밖에서 카드가 렌더돼도 터지지 않는다.

**호출부 이관:**

| 위치 | 현재 | 변경 후 |
|---|---|---|
| 덱 재정렬 실패 등 3곳 (`page.tsx:81,87`) | `setToast(msg)` | `show(msg)` — 기본 6000ms 동일 |
| 보관함 undo (`library/page.tsx:149`) | `{undoTweet && <Toast …/>}` | `undoTweet` 변화를 보는 effect에서 `show('팀 보관함에서 뺐어요', { actionLabel: '실행취소', onAction: undoRemove, duration: null, dismissible: false })`, 비워지면 `hide()` |
| 카드 공유 버튼 (신규) | — | `show('링크를 복사했어요', { duration: 2500 })` |

보관함 undo에서 `duration: null` + `dismissible: false`인 이유: 토스트 노출 조건이 **정확히 `undoTweet !== null`**이어야 한다. 5초 타이머가 만료되면 DELETE가 커밋되므로, 토스트가 먼저 사라지거나 사용자가 ✕로 닫아 실행취소 기회를 잃는 상태가 생기면 안 된다. 현재 코드가 이 불변식을 주석으로 명시해 지키고 있다(`library/page.tsx:47-48`).

**`requestRemoveTeam`의 5초 타이머와 `commitRemove` 레이스 방지 로직은 건드리지 않는다.** 이관은 "토스트를 어디서 그리는가"만 바꾸고, 삭제 커밋 타이밍은 그대로다.

## E. 실패 처리

`navigator.clipboard.writeText`는 권한 거부·비보안 컨텍스트에서 거부된다(프로덕션은 HTTPS이므로 정상 동작). 실패 시:

- 버튼을 미리 숨기거나 비활성화하지 않는다. 왜 없는지 사용자가 알 수 없는 것이 더 나쁘다.
- 시도한 뒤 토스트로 알린다: **"링크를 복사하지 못했어요 — 브라우저 권한을 확인해 주세요"**.
- `navigator.clipboard` 자체가 없는 환경도 같은 경로로 처리한다.
- 폴백으로 `document.execCommand('copy')`는 쓰지 않는다. deprecated이고, 실사용 환경(HTTPS)에서 도달하지 않는 코드다.

## F. 범위에서 제외

- 여러 트윗 링크 일괄 복사 — 요청에 없고 선택 UI가 필요하다.
- 본문 텍스트 복사, 인용 형식 복사 — 링크 복사와 다른 기능이다.
- X 공유 메뉴의 나머지 항목(DM 전송, 북마크 등) — 이 앱에서 수행할 수 없는 동작이라 거짓 어포던스가 된다.
- `Toast`에 성공/실패 색 변형 추가 — 현재 덱도 오류 메시지를 같은 검은 토스트로 보낸다. 메시지 문구가 의미를 전달한다.
