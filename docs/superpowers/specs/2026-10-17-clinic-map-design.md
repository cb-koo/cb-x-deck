# 클리닉 지도 — 기획 (2026-10-17, 초안)

> 상태: 스펙 초안. koo 확인 대기.
> 출발점: 로컬 프로토타입 `~/orca/projects/clinic-map`(커밋 04c45c0, 10-16 Strategy-Office 세션). 검토 기록 `~/claude-outputs/clinic-sales_클라이언트지도_검토_20261016.md`.

## 0. 결정 (koo 10-17)

- **cb-x-deck에 넣는다.** monthly-report는 고객이 쓰는 제품이라 넣지 않고, 별도 앱도 만들지 않는다.
- **배경지도는 OpenFreeMap(positron)을 그대로 쓴다.** 키가 필요 없다. 무료 공용 서버라 장애가 나도 보장이 없다는 점은 알고 쓴다. 바꿀 때는 지도 스타일 주소 한 줄만 바꾸면 된다.
- **지도 엔진은 프로토타입과 같다(MapLibre + deck.gl).** 바뀌는 건 앱 뼈대(Vite → Next), 데이터 보관(파일 → DB), 갱신(수동 → 자동), 고객 연결(설정 파일 → 화면)이다.

## 1. 무엇을 하나

clinic-sales가 모은 병원별 추정 매출(피부과·치과·성형외과, 약 1.17만 곳)을 지도에 올린다. 영업과 기획이 **어느 병원에 먼저 연락할지**를 고르는 도구다. 검색 트렌드가 **수요**(일본에서 무엇을 찾나)라면, 이 화면은 **공급**(어느 병원이 외국인 매출을 얼마나 내나)이다.

이 화면이 답하는 질문:
- 외국인 환자 유치기관으로 등록했는데 외국인 매출이 거의 없는 병원은 어디인가? → 우리 서비스가 바로 필요한 곳
- 국내 매출은 큰데 외국인 비중이 낮은 병원은 어디인가? → 예산 여력이 있고 해외 확장 여지가 큰 곳
- 우리 고객 옆에 있는 경쟁 병원은 어디이고, 얼마나 버나?
- 우리 고객과 제안서를 보낸 곳은 지도에서 어디에 몰려 있나?

**내부 전용이다.** 매출 추정 데이터가 들어 있으므로 화면·API 모두 로그인한 팀원만 볼 수 있다.

## 2. 화면 (`/market-map`, 사이드바 '검색 트렌드' 바로 아래 '클리닉 지도')

프로토타입 화면을 그대로 옮긴다. 이번에 바꾸는 것은 ✱로 표시한다.

- **지도 보기 3종:**
  - 클리닉: 점 크기 = 매출, 색 = 외국인 비중. 노란 테두리 = 등록했지만 덜 활용, 흐린 점 = 추정치.
  - 구역: 시군구 → 행정동 색칠(병원 수·매출·외국인 매출·기회 점수).
  - 밀도: 3D 헥사곤.
- **세그먼트:** 등록했지만 덜 활용 · 국내 강자 · 성장 중 · 신규 개원 · 체인
- **필터:** 진료과, 지역, 이름 검색, 외국인 비중·매출 하한, 유치기관만, 정확값만, 영업 상태
- **병원 카드:** 3개월 매출(국내/외국인), 구내 순위, ㎡당 매출 대비 구 중앙값, 유치 대상국, 체인 전 지점, 같은 건물, 반경 경쟁 병원
- **하단:** 매출 × 외국인 비중 2×2(✱ cb-x-deck 차트 키트로 다시 그린다), 화면 안 목록(기회 점수순) + CSV
- **용어 설명 패널:** 오른쪽 패널, `?` 키, `/` 검색, 용어 → 기능 적용. 문구는 `glossaryTerms.ts`를 그대로 가져온다.
- ✱ **스타일:** 프로토타입 CSS 대신 cb-x-deck 디자인 토큰. 글자 크기·행 높이는 도구 화면 기준(14~15px, 행 44px+)을 따른다.
- ✱ **고객 연결(§4):** 병원 카드에 [우리 클라이언트로 연결] / 클라이언트 상세에 [지도 병원 연결].

**성능:** 지도 라이브러리는 이 페이지에서만 브라우저 전용으로 불러온다. 다른 화면의 번들에는 들어가지 않는다.

## 3. 데이터

### 3-1. 원천
- **clinic-sales API** (`https://clinic-sales.vercel.app/api/v1/clinics`, Bearer 키). 진료과 × 달마다 페이지를 넘겨 받는다.
- **행정경계:** vuski/admdongkor ver20260701을 mapshaper로 단순화한 `sgg.geojson`(0.5MB), `dong.geojson`(2.5MB). 공공 데이터라 `public/`에 둔다. 앱의 로그인 검사가 `.geojson`을 제외하지 않으므로 어차피 팀원만 받는다.
- **영업 상태:** monthly-report 테이블(`report.clinic`, `report.report`, `report.lead`, `report.proposal`)을 **읽기만** 한다. 같은 Supabase 프로젝트라 연결을 따로 만들 필요가 없다.

### 3-2. 저장 (마이그레이션 080~, 추가만)
- `market_clinic`: 병원 한 줄. clinic-sales id(자연키) · 진료과 · 이름 · 주소 · 시도·구 · 행정동 코드·이름 · 위경도 · 면적 · 개원일 · 의사 수 · 브랜드·지점 수·체인 · 유치기관 등록·대상국. 갱신 때마다 덮어쓴다.
- `market_clinic_month`: (병원, 달) → 매출·국내·외국인·방문·외국인 방문·추정 방식.
- 파생 지표(구내 순위, 매출 백분위, ㎡당 매출 대비 구 중앙값, 시그널 2종, 기회 점수)는 **수집 때 계산해 `market_clinic`에 저장**한다. 화면은 계산하지 않는다(라벨과 값이 늘 같도록).
- `market_clinic_link`: (병원 ↔ cb-x-deck 클라이언트 또는 monthly-report 리드) + 지점 이름. 한 고객이 여러 지점을 가질 수 있다(블리비 4, 벤자민 2).
  - 리드는 monthly-report에 있으므로 FK 없이 id만 저장한다(`report.clinic.client_id`가 FK 없이 이쪽을 가리키는 것과 같은 방식).
- **처음 한 번:** 프로토타입의 `crm-mapping.json` 규칙으로 연결을 채운다.

### 3-3. 화면에 내려주는 데이터
- `/api/market-map`이 화면에 필요한 칸만 한 번에 내려준다. 지금 파일(13.7MB)에서 쓰지 않는 칸(전체 주소 원문 등)을 빼고 짧은 키로 바꾸면 압축 후 1~2MB로 예상된다. 구현 때 실측해 적는다.
- 병원 카드의 상세(3개월 추이, 같은 건물, 경쟁 병원)는 지금처럼 같은 데이터에서 계산한다. 무거우면 카드를 열 때 따로 받는다.

### 3-4. 갱신 — 월 1회 자동
- 검색 트렌드와 같은 방식: DB 예약 실행(pg_cron + pg_net)이 `/api/market-map/collect`를 부른다. 성과 자동 측정과 같은 시크릿을 쓴다.
- 새 달이 들어왔을 때만 전체를 갱신한다. clinic-sales가 매출을 언제 채우는지 확인해 날짜를 정한다(§7).
- clinic-sales API 키는 Vercel 환경변수 `CLINIC_SALES_API_KEY`로 등록한다(`encrypted`. 런타임에만 쓰지만 규칙대로).
- 화면에 '최종 갱신 · 데이터 기준 달'을 보여준다.

## 4. 영업 상태

| 표시 | 뜻 (koo 10-16) | 원천 |
|---|---|---|
| 서비스 중 | 월간 리포트가 1건 이상 있는 고객 | `report.clinic` + `report.report` |
| 리포트 준비 | 고객으로 등록했지만 리포트가 아직 없음 | `report.clinic` |
| 제안서 발송 | 제안서가 1건 이상 있는 리드(계약으로 넘어간 리드는 고객 쪽으로 봄) | `report.lead` + `report.proposal` |

- 연결은 `market_clinic_link`로 한다. cb-x-deck 클라이언트 ↔ `report.clinic`은 `report.clinic.client_id`로 이미 이어져 있다.
- 지도에서 리드를 새로 만들지는 않는다. 병원 카드의 [제안서 만들기 ↗]는 monthly-report 리드 등록 화면으로 넘긴다.
- **두 앱이 서로의 데이터를 읽는 구조**가 된다. monthly-report는 `public.client`를, cb-x-deck은 `report.*`를 읽는다. 둘 다 **읽기만** 한다는 결정을 ADR로 남기고, monthly-report 쪽에도 알린다.

## 5. 기회 점수·시그널 (프로토타입 규칙 그대로, 진료과 안에서 비교)

- 기회 점수 0~100 = 매출 백분위 40 + (1 − 외국인 비중) 25 + 성장률 백분위 20 + 유치기관 등록 15
- 등록했지만 덜 활용 = 유치기관 등록 & 외국인 비중 < 15% & 매출 백분위 ≥ 30%
- 국내 강자 = 매출 상위 20% & 외국인 비중 < 15%
- 외국인 객단가는 외국인 방문 30건 미만이면 숨긴다.
- **구현 전 점검:** 지금 고객 7곳이 몇 점으로 나오는지 확인한다. 고객이 하위권이면 가중치를 다시 본다.

- 검색 트렌드와 서로 오가는 연결(시술 ↔ 병원)
- VWorld 등 다른 배경지도
- 치과·성형외과의 외국인 매출(clinic-sales에 아직 국내/외국인 구분이 없다. 들어오면 그대로 표시된다)

## 7. 확인할 것

1. **clinic-sales 보안:** 내부 엔드포인트(`/api/clinics`, 내보내기)가 로그인 없이 열려 있다. 이 화면과 별개로 막아야 한다.
2. **clinic-sales 갱신 시점:** 매달 며칠에 지난달 매출이 채워지는지.
3. **사용자:** 지도를 주로 쓸 영업 담당자. 첫 배포 뒤 1~2주 실사용을 보고 다음 단계를 정한다.
