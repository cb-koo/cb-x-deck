## 1. 한 줄 소개

클리닉 클라이언트의 일본 X(트위터) 인플루언서 마케팅을 **글감 찾기 → 원고 만들기 → 인플루언서에게 맡기기 → 게시 확인·성과 측정 → 협찬비 정산 요청**까지 한곳에서 하는 사내 도구. 사용자는 회사 콘텐츠 기획 담당자 소수(2026-10 기준 4명)다.

## 2. 배경과 목표

- **해결하는 문제**
  - 일본 X에서 반응이 좋은 글을 찾으려면 X를 일일이 뒤져야 했다. → 키워드·계정별로 트윗을 모아 보는 '덱'을 만들었다.
  - 원고·일정·비용·게시 확인·정산이 슬랙, 스프레드시트, 구글폼에 흩어져 있었다. → 캠페인 화면 한 곳에서 작업 단위로 이어서 관리한다.
  - 협찬비 지급은 정산 담당 프로덕트(CB 정산데스크)가 처리하는데, 요청을 손으로 옮겨 적어야 했다. → 게시가 확인된 작업을 매주 자동으로 넘긴다.
- **목표(성공했다고 볼 기준)**
  - 기획 담당자가 개발자 도움 없이 리서치부터 정산 요청까지 끝낸다.
  - 같은 작업을 두 번 지급하거나, 게시 확인 없이 지급하는 일이 없다.
  - 어떤 콘텐츠가 LINE 친구추가·예약까지 이어졌는지 숫자로 본다.

### 4-4. 캠페인과 작업

- **캠페인** = 클라이언트 한 곳 × 기간 하나(보통 한 주)의 작업 묶음. 이름은 `클라이언트_N월N주차`.
- **작업** = 인플루언서 한 명에게 맡긴 일 하나. 유형은 투고·인용RT·RT·방문협찬 넷. 단계는 저장하지 않고 상황으로 정해진다: 준비 → 전달 → 게시 → 정산 → 완료, 그리고 취소.
- 섭외·조율(DM 내용)은 기록하지 않는다. 기본은 '진행'이고, 안 됐을 때만 취소·교체로 남긴다.

## 7. 운영 원칙·제약

- **화면 문구 원칙:** 사용자는 비개발자다. 버튼은 내부 개념이 아니라 얻는 것을 말하고("밀도 확인" ✗ → "적정 기준 추천받기" ✓), 결과는 숫자만이 아니라 판단과 다음 행동까지 적는다.
- **비용이 드는 동작은 버튼을 눌러야만 한다:** 덱 자동 수집 없음, 시안 수는 매번 1로 돌아감, 버튼 옆에 예상 비용 표기.
- **검수는 표시만:** 약기법 위험어·금지 표현은 노란 표시만 하고 막지 않는다.
- **기록은 지우지 않는다:** 취소는 사유와 함께 남기고 되돌릴 수 있다. 원고 원본은 고쳐도 남는다. 옛 캠페인 화면도 '보관'으로 남겼다.
- **정산 요청은 정산 화면에서만 만든다.** 캠페인 화면은 정산 화면으로 이어 주기만 한다.
- **시간은 모두 서울 시간(KST).**
- **배포:** ~~저장소에 합쳐도 자동 배포되지 않고, 담당자가 명령으로 직접 배포한다.~~ 저장소 main에 올리면 자동으로 배포된다(2026-10-26 수정 — 실제 배포 기록으로 확인). 배포할 때 데이터 칸 추가를 먼저 적용하고, 칸 삭제·이름 변경은 여러 번에 나눠서 한다(옛 화면이 깨지지 않게).
- **테스트는 연습용 데이터베이스에서만 돈다.** 2026-09-09 테스트 데이터가 정산데스크로 넘어가 유령 지급 10건이 생긴 뒤로, 테스트용 데이터는 서버에서 걸러 내보내지 않는다.
- **자동으로 도는 일:** 리포트 숫자 동기화(매일 04:00), 게시물 조회수 자동 기록(5분마다 확인), 정산 자동 전송(월요일 07:00). 뒤의 두 개는 운영 데이터베이스의 예약 실행으로 켜도록 만들어져 있다(실제로 켜져 있는지는 운영에서 확인).
- **개발용 화면:** `/debug/card`(트윗 카드 확인용, 사이드바에 없음), `/mockup/x-extension`(개발 환경에서만 열림).
