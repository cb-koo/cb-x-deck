[cb-x-deck 소스팀 전달] 상태 회신 operator(처리 담당자) 필드 수용 요청

작성일 2026-09-04 · 요청 주체: 정산 미러(cb-marketing-ex) · 대상: cb-x-deck(결제 요청 소스)
관련: 외부 API 계약 20260828_settlement-external-api_최종.md §5·§6, 마이그레이션 015

1. 요청 한 줄 요약

POST /api/external/settlement/requests/{request_id}/status 요청 본문에 선택 필드 operator: { id, name } 를 추가로 수용해 주세요. 정산 미러에서 그 상태 전이(취소·보류·지급 등)를 실제로 실행한 결제 담당자를 함께 보냅니다.

2. 배경 — 왜 필요한가

지금까지 상태 회신에는 처리 상태만 담겼고 "누가 그 처리를 했는지"는 소스로 전달되지 않았습니다(계약 §5: 담당자는 API로 주고받지 않음).

운영 요구가 바뀌어, 취소·보류를 누른 결제 담당자를 소스(cb-x-deck)에서도 감사·표시할 수 있어야 합니다.

이에 정산 미러가 사람이 실행한 상태 전이마다 담당자를 operator로 실어 회신하도록 구현을 마쳤습니다. 소스가 이 필드를 받아만 주면(저장/무시 무관) 됩니다.

3. 필드 스펙

 | 

 | 필드
 | 필수
 | 타입
 | 설명

 | operator
 | 아니오(선택)
 | { id: string(uuid), name: string }
 | 이 상태 전이를 실행한 정산 미러 결제 담당자.

 | operator.id
 | —
 | string(uuid)
 | 담당자(로그인 사용자) UUID.

 | operator.name
 | —
 | string
 | 담당자 표시 이름(미상 시 "담당자").

동작 규칙:

사람이 실행한 전이에만 담깁니다 — cancelled(취소), on_hold(보류), scheduled(보류 해제/재개), paid(지급), paid→paid(금액 정정).

자동/시스템 전이에는 없습니다 — 예: 수신 즉시 received→scheduled 자동 전환. 이 경우 operator 키 자체가 없습니다.

기존 필드(status·updated_at·note·paid_amount_krw·paid_at·external_id)와 규약·적용 규칙은 그대로입니다. operator는 추가만 됩니다.

4. 예시 요청 본문

취소(사람 실행):

{
  "status": "cancelled",
  "updated_at": "2026-09-04T09:12:33.120Z",
  "note": "콘텐츠 조건 변경",
  "external_id": "S-20260904-001",
  "operator": { "id": "8f2c9e10-1b2a-4c3d-9e4f-000000000001", "name": "전태정" }
}

지급(사람 실행):

{
  "status": "paid",
  "updated_at": "2026-09-06T05:00:00.000Z",
  "paid_amount_krw": 94740,
  "paid_at": "2026-09-06T04:58:10.000Z",
  "operator": { "id": "8f2c9e10-1b2a-4c3d-9e4f-000000000001", "name": "전태정" }
}

자동 전환(operator 없음):

{ "status": "scheduled", "updated_at": "2026-09-04T09:00:00.000Z" }

5. 소스 측에 요청하는 것

operator 필드를 거부하지 말 것 — 현재 소스 검증이 미지 키를 .strict로 막는다면, operator를 허용 목록에 추가해 주세요(저장은 선택).

(권장) 검증한다면: operator가 있을 때 { id: string, name: string } 형태만 확인하고, 아니면 400 { error, field: "operator" } — 정산 미러 목 서버(mock-server/)가 이미 이 규칙으로 구현돼 있어 그대로 미러링하면 됩니다.

(선택) 저장한다면: 상태 이력/감사에 담당자 이름을 남겨, 소스 화면에서도 "누가 처리했는지"를 볼 수 있게.

6. 미수용 시 정산 미러 측 조치 (안전장치)

소스가 operator를 수용하기 전까지는 정산 미러의 상태전송을 재개하지 않습니다(현재 상태전송은 정지 상태).

소스가 미지 키를 400으로 거부하는 계약이면, 수용 전에 재개할 경우 상태 회신 전체가 실패하므로, 그 사이에는 outbox-sender에서 전송 직전 operator를 떼는 env 게이팅(SOURCE_SEND_OPERATOR=false)을 켜 안전하게 재개할 수 있습니다(현재 미구현, 필요 시 추가).

회신 요망: 소스가 operator 수용을 완료하는 시점(또는 계약이 원래 미지 키를 무시하므로 지금 그대로 보내도 되는지)을 알려주세요. 그에 맞춰 상태전송을 재개합니다.

7. 정산 미러 측 현황(참고)

계약 문서 §5·§6에 operator 반영 완료(2026-09-04).

apply_transition RPC가 사람 전이의 outbox body에 operator{id,name} 주입(마이그레이션 015, 스테이징 적용 완료).

목 서버(mock-server/server.ts)가 operator 수용·검증하도록 구현·테스트 통과 — 소스 구현의 참조 규격으로 사용 가능.
