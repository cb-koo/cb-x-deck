## 0. 문제와 방향

- **문제**: 8단계에 필요한 기능(칸)은 다 있다. 그런데 캠페인 하나를 실제로 처리하면 ① 만들고 → ② 작업 넣고 → (DM 조율) → ⑤⑥ 확인 → ⑧ 정산까지 가는 동안 **화면이 손을 끊는다.** 지금 프로덕트는 단계의 결과값을 적는 장부이고, 그림은 단계를 밟는 절차다.
- **방향**: **한 화면에서 전체 플로우를 처리하는 UX.**

## 3. 화면 (확정 — 시안 F, 09-17~18)

좌측 캠페인 목록(접기 가능, 기존 `listCollapsed` 재사용) + 상세. 상세 = 타이틀 · 요약 카드 3장 · 필터/검색 줄 · **표 하나**.

### 3-1. 단계 (R21) — 파생 규칙

| 단계 | 조건 (위에서부터 먼저 맞는 것) |
|---|---|
| 취소 | `cancelled_at` 있음 |
| 완료 | 정산 요청의 그쪽 상태 = 지급 완료 |
| 정산 | 활성 정산 요청 있음(요청됨·접수·지급 예정·보류) |
| 게시 | `posted_at` 있음 (= 정산 대기) |
| 준비 | 인플 미배정, 또는 원고가 있고 상태가 전달됨·미사용이 아님 |
| 전달 | 그 외 — 원고 전달됨, 또는 원고 없는 작업(RT 등)에 인플이 있음 |

정산에서 요청이 취소되면 다시 '게시'로 돌아간다(파생값). 단계 칩 색: 준비 회색 · 전달 파랑 · 게시 녹색 · 정산 보라 · 완료 검정 · 취소 흐림+취소선.

### 3-2. 표 (R26·R27)

```
[필터 ▾] [⌕ 인플루언서 · 원고 검색]  전체 13건 · 만든 순              정산 대기 2건 · 정산에서 확인 →
단계   유형    인플루언서      원고                              게시 예정일        작업 비용
전달   투고   @toppogi0102   ホワイトニングして3日目。正直…       9/15 화 · D+1     ₩80,000  ···
전달   RT     @kawachi_x     —                                 9/17 목           ₩30,000  ···
준비   투고   미정            スケーリングって半年に…             미정              ₩60,000  ···
게시   인용RT @rararanll     日本語で予約できるって…             9/15 화(파랑)     ₩30,000  ···
정산   인용RT @skysky_ca     施術の後に写真もらえた…             9/14 월(파랑)     ₩100,000 ···
완료   투고   @17dsy_        スケーリング後3日目。…              9/14 월(파랑)     ₩60,000  ···
취소   인용RT @ririko_item   🙅 거절 · 일정 안 맞음 · 원고 있었음: … 9/15 화 취소   ₩60,000  ···
```

- **원고 칸 = 본문 첫 줄**(제목·상태 문구 없음). 넘치면 말줄임, 전체는 툴팁. RT는 `—`. 원고 없는 투고류도 `미정`.
- **대상·방문일·증빙·메모는 표에 없다** — 패널(§4)에서 본다.
- `···` = 게시 확인 · 예정일 바꾸기 · 원고 열기(또는 붙이기/새로 만들기) · 인플루언서 교체 · 작업 취소 · 삭제. 취소 행은 되돌리기 · 삭제.
- 필터 드롭다운: 단계 6 / 유형 4 / 지금 볼 것(지연·오늘 게시 예정·예정일 미정). 묶음 안 OR, 묶음 사이 AND. 요약 줄에 고른 것과 건수, [지우기].
- 검색: 인플 핸들(@ 유무 무관) + 원고 제목 + 첫 줄. 서버 목록이 이미 `draft_title`·`draft_first_line`을 실어 보내므로 화면에서 걸러도 된다.
- 정렬: 기본 만든 순(먼저 만든 것 위). 헤더 클릭 → 오름 → 내림 → 기본. 미정은 오름차순에서 맨 뒤.
- 하단 한 줄: 유형별 건수 · 비용 합 · 게시 n/N · 밀림.
- 인플 핸들은 링크가 아니다(koo 09-17 취소).

### 3-3. 요약 카드 (R28) — 제목 한 단어 · 큰 숫자 하나 · 라벨은 숫자 아래 · 주석은 툴팁 · 기호는 `/` 하나

```
작업               성과              [업데이트]    비용
4 / 12             70,200   839   133            ₩250,000 / ₩810,000        ₩3,000,000
게시               조회     좋아요  북마크         소진 / 계획                  9월 예산
▬▬▬░░░░░                                          ▒▒▒▒▒▬▬▬░░░░░░░░░░░░░░
```

- **작업**: 게시 확인된 작업 / 계획된 작업(취소 제외) + 막대.
- **성과**: 게시물 링크가 등록된 완료 작업의 최신 스냅샷 합(`tracked_post`의 views·likes·bookmarks). 숫자는 천 단위 구분만(만 단위로 접지 않음). **[업데이트]** = 링크 있는 작업의 게시물을 다시 조회해 스냅샷 추가(기존 트래킹 수집기 재사용, 게시물당 API 1회). 툴팁에 기준 시각·합계 밖 건수.
- **비용**: **소진** = 게시 확인된 작업 비용 합 / **계획** = 취소 제외 작업 비용 합 + 인플별 추가 비용(현행 월 집계와 같은 정의 — 추가 비용은 작업별이 아니라 소진엔 넣지 않음, 툴팁에 "추가 비용 ₩n은 계획에 포함"). 오른쪽에 클라이언트 **예산**(1차는 현행 월 예산 · "9월 예산", 예산 기간 모델 뒤엔 "9/1–9/28 예산"). 막대 = 예산이 전체 길이: 회색(같은 달/기간의 다른 캠페인 **계획**) → 진한 파랑(이 캠페인 소진) → 연한 파랑(이 캠페인 계획 잔여) → 빈칸(남음). 송금 수수료는 미포함(토글 없음, 툴팁). 카드는 `campaignMonthBudget()` 한 함수로 예산을 받으므로 달→기간 전환 시 카드 코드는 그대로.
- 비율 0.9 : 1.1 : 1.4. 유형별 건수 카드는 뺐다(유형 열·필터로 충분).

## 4. 작업 만들기·채우기 = 오른쪽 패널 (확정, R22~R25)

### 4-1. 입구 둘

- **`+ 작업 추가`** → 패널이 "새 작업"으로 열림. 유형 선택 → 칸들 → **[만들기]** 또는 **[만들고 하나 더]**. 유형만 골라도 만들기 전엔 표에 생기지 않는다(koo 09-18).
- **`한 번에 만들기`** → 작은 창 `인용RT [5] 투고 [2] RT [3] 방문협찬 [0]` → **[작업 10개 만들기]** → 빈 작업(단계 준비·전부 미정)이 생기고 첫 작업 패널이 열린다.
- 옛 작업 추가 팝업(한 작업의 모든 칸을 한 번에)은 **폐기**.

### 4-2. 패널 (폭 560)

```
준비 · 투고                                   ···  ✕
@asyako0520
─────────────────────────────────────────────
인플루언서   [A @asyako0520] [바꾸기]
비용         [₩80,000 (점선)]  [확인]   프로필 단가 · 투고
원고         [새로 쓰기] [직접 쓰기] [있는 원고 고르기 4]   ← 붙으면 제목 · 상태 + [열기] [떼기]
대상 게시글   [https://x.com/…]                              ← 인용RT·RT만
             ☐ 아직 게시 전인 글이에요 — 링크는 나중에
                └ (체크 시) 어느 작업인가요? [@toppogi0102 투고 ▾]  선택 안 해도 됨
게시 예정일   [미정]
메모
─────────────────────────────────────────────
                               ← 이전   8 / 13   다음 →
```

- **칸 순서**(koo 09-18): 인용RT·투고·RT = 인플 → 비용 → 원고(RT 없음) → 대상(투고 없음) → 예정일 → 메모. 방문협찬 = 인플 → 일정(방문일·게시 예정일) → 예산 → 원고 → 메모.
- **이전/다음**은 표 순서(만든 순). 패널에서 고치면 표가 바로 바뀐다.
- `···`(취소·교체·삭제)는 패널 헤더 오른쪽. 새 작업(만들기 전)엔 없음.
- 패널이 열려 있는 동안 표는 어둡게(스크림), 행 클릭으로 다른 작업 전환.

### 4-3. 비용 [확인] (R24)

| 시나리오 | 흐름 |
|---|---|
| 4-1 프로필 단가 있음 · 같음 | 자동 채움 → `프로필 단가 · 투고` → [확인] → ✓ 확정 |
| 4-2 프로필 단가 있음 · 다름 | 자동 채움 → 사용자가 고침 → `프로필 단가 ₩30,000과 다름` → [확인] → 창 "프로필의 인용RT 단가도 ₩30,000 → ₩35,000으로 바꿀까요?" [이 작업만] [프로필도 바꾸기] → 확정 |
| 4-3 프로필 단가 없음 | 빈칸 `프로필에 단가 없음 — 직접 입력` → 입력 → [확인] → 창 "프로필에 투고 단가 ₩50,000으로 저장할까요?" [이 작업만] [프로필에 저장] → 확정 |

- 확정 전: 입력칸 점선, 표의 비용 회색(툴팁 "아직 확인 전"). 확정 후 `✓ 확정`(프로필 갱신했으면 `· 프로필 단가 갱신됨`).
- 프로필 갱신은 기존 `influencer.pricing` + `pricing_changed` 로그를 쓴다. 인플 교체 때의 비용도 같은 [확인] 흐름(ADR 0005 갱신).
- 인플 미정이면 비용 칸 비활성("인플을 정하면 프로필 단가로 채워요").

### 4-4. 대상 (R25)

- 입력은 **링크 하나**. 체크 "아직 게시 전인 글이에요"만 하면 표·패널에 `게시 확인 전` 표시, 그 캠페인의 게시 확인 다이얼로그가 "대상 미정인 RT 작업 n건 — 이 게시물로 채울까요?"를 제안.
- 어느 작업인지까지 고르면(선택) 내부적으로 `target_task_id`를 두고, 그 작업이 게시 확인되는 순간 링크(`post_url`)를 자동으로 채운다 + 알림. 화면은 여전히 링크 하나.

### 4-5. 게시 확인 다이얼로그

`···` 또는 패널에서: 언제(오늘 / 다른 날) · 게시물 링크(선택, 정산 참고자료) · RT면 증빙 스크린샷 **필수** · "확인하면 완료로 내려가고, 비용·인플이 있으면 정산 대기에 잡혀요. 되돌리지 않아요." 기존 `PostedCell` 선택지와 같다. 리포스터 자동 조회는 이 화면에 없음(R11).

## 5. 원고 모드 (확정, 09-18 — koo가 시안에서 1~6단계 확인)

패널의 원고 칸에서 **[새로 쓰기] / [직접 쓰기] / [있는 원고 고르기 n]** 을 누르면 **같은 패널이 원고 모드**로 바뀐다(위에 `← 작업으로`). 패널과 시트는 별개 표면이 아니다. 클라이언트·인플·유형·대상은 작업에서 와서 잠김. 인플 미정 작업에서도 열린다.

### 5-1. 생성 (첫 화면 = 매번 바꾸는 둘만)

> **1.5 예고**: 레퍼런스 고르기([+ 보관함에서] 뒤의 창)는 1차에서 기존 `RefPickerSheet`를 그대로 붙이고, **v2 1차 배포 직후 별건으로 재설계**한다(koo 09-18: 보관함 콘텐츠를 확인·선택하는 UX가 지금 설계에 없음 — 카드 미리보기·좁히기·선택 상태·비교). 패널은 껍데기라 알맹이 교체가 쉽게 만든다.

```
레퍼런스   [🔗 대상 · @toppogi0102 투고]  [+ 보관함에서] [+ 링크]    ← 인용RT는 대상 게시물 자동 포함
방향성     [                                                 ]
▸ 설정     시술 치아미백 · 단문 · 시안 3개 · 제약 켬 — 지난번 그대로  ← 접힘. 클라이언트별 마지막 값 기억
[시안 3개 만들기]
```
- 레퍼런스 출처는 지금과 같이 **보관함 고르기 + 링크 붙이기**. 인용RT의 대상 게시물만 자동. **성과 기반 자동 제안은 넣지 않는다**(koo 09-18: 지금 단계에 필수 아님, 복잡해질 걱정).
- 시안 수 기본 3, 1~5. 만드는 동안 패널에 머무른다(진행 표시). 뒤에서 돌리고 다른 작업 채우기는 실사용 뒤 검토.
- 결과 = 시안 카드 3장, **읽기 + [이 시안 붙이기]만**. 다듬기는 붙인 뒤.
- 붙이면 그 자리가 **원고 카드(`DraftCard`)** 로 바뀐다 — 다시쓰기·번역·이미지·버전·복사·상태(초안→검수 대기→사용 확정→전달됨)·[떼기]. `DraftCard`는 `max-w-[600px]`·내부 고정 폭 없음이라 패널 안 516px에 그대로 들어간다(`/generate`·기존 캠페인 상세에 이어 세 번째 자리).
- 안 고른 시안은 **작업 없는 원고로 남는다**(형제 시안). 서버는 "생성은 미부착, 선택 시 부착" — 기존 `createDraft({taskId})`(첫 시안 자동 부착)와 다른 새 경로.

### 5-2. 직접 쓰기 = X 포스트 작성 UI (koo 09-18)

X 컴포저와 같은 모양으로 쓴다 — 결과물이 X에 올라갈 글이니 쓰는 화면이 같으면 글자 수·줄바꿈·스레드 감이 그대로 잡힌다(덱 = X 미러링 원칙과 같은 결).

- **가져오는 것**: 아바타·핸들(작업의 인플루언서 — 누구 이름으로 나가는 글인지) · 글자 수 원형 카운터(X 규칙: 일본어 등 전각 140자 가중치, 초과 시 빨강) · **스레드**(아래 `+`로 다음 글, 글마다 카운터, 연결선) · **이미지 첨부**(글 아래 미리보기 격자 최대 4장, 기존 Storage).
- **안 가져오는 것**: 이모지 피커·투표·GIF·예약.
- 버튼은 **[저장하고 붙이기]** — 저장 즉시 이 작업에 붙고 원고 카드로 바뀐다. 제목(선택)은 카드에서.
- 저장 구조는 지금 원고 모델 그대로(본문 배열 = 단문/스레드, 이미지 = 기존 첨부). 서버 변경 없음.
- **원고 카드의 편집도 같은 컴포저**로 통일한다 — 지금 `DraftEditModal`(평범한 텍스트 칸)을 이 컴포저로 교체. `/generate`·기존 캠페인 상세에서도 같은 것을 쓰게 되므로 파급을 계획에서 크기 재고, 부담이면 1차는 직접 쓰기만·카드 편집은 후속(koo 09-18: 통일이 맞되 크기 보고).

### 5-3. 있는 원고 고르기
두 묶음 — **같은 재료로 만든 시안**(이 캠페인·같은 클라에서 생성됐으나 안 붙은 형제 시안) / **작업 없는 원고**(그 외 같은 클라이언트). 검색 한 칸이 둘 다에 걸림. 다른 클라이언트 원고는 대상 아님.

### 5-4. 작업 모드의 원고 칸
- 원고 없음: 세 버튼. RT는 원고 칸 없음. 인플이 직접 쓰면 비워 둔다.
- 원고 있음: `제목 · 상태 [열기] [떼기]`. [열기] → 원고 모드의 카드. 표의 원고 열은 본문 첫 줄.

## 6. 취소·교체 세부 (확정 — ADR 0002·0005 요약)

- **취소**: 게시 전만. `where posted_at is null and cancelled_at is null` 조건부 갱신 + DB check로 게시 확인과 상호 배제. 취소 컬럼·원고 떼기·스냅샷·로그는 **한 트랜잭션**. 원고는 떼고 `cancelled_draft_id`·제목 스냅샷 보존. 제외되는 비용은 작업 비용만, 인플별 추가 비용은 남음.
- **되돌리기**: 외부 트랜잭션 하나 — ① 작업 복원 UPDATE(취소 컬럼·스냅샷 전부 지움) → ② 세이브포인트 안에서 재부착 → ③ 한 번 커밋. 중간 커밋 없음. unique 충돌(다른 작업이 그 사이 붙임)이면 세이브포인트만 롤백하고 "원고는 @d 작업으로 갔어요". 3갈래(재부착 / 다른 작업에 갔음 / 원고 없음) — 원고 점유·삭제가 작업 복원을 실패시키지 않는다는 뜻에서 "항상 성공".
- **서버 계약**: 취소·되돌리기·교체는 PATCH에 얹지 않고 **액션 라우트 셋**(`POST …/tasks/[taskId]/cancel | restore | replace`)으로. 각각 `for update`로 posted_at·cancelled_at·(교체는 visit_on까지) 재검사 후 관련 변경 전체를 한 트랜잭션에 넣는다. PATCH의 `influencerHandle`은 배정(없음→인플)·해제·같은 인플만 받되 **같은 상태 제한(게시 전·취소 아님·방문 전)과 정리 규칙**(해제: 전달됨→사용 확정·증빙 제거 / 배정: 비용은 §4-3 [확인] 흐름)을 서버가 적용. 다른 인플로 바꾸기는 400 "교체는 ··· → 인플루언서 교체로".
- **사유 칩**: 이모지+단어, 값은 영어. 슬랙 관례 ✏️ 원고확인 · 💰 지급 · ❌ 취소(완료 리액션 💰/✅/🤑) — **취소 행동은 ❌**. 기본 선택 없음(누르면 켜짐, 다시 누르면 꺼짐). 거절·무응답 전용 이모지는 슬랙에 없음 → §8.
- **교체**: 게시 전만, 방문협찬은 `visit_on < 오늘`이면 불가(당일·미정은 허용 — 날짜 기준이라 "예약일은 지났는데 실제로 안 왔다"는 방문일을 고친 뒤 교체하거나 취소 후 새 작업; 실제 방문 확인은 저장하지 않는 한계). 비용은 §4-3 흐름(새 인플 단가로 채우고 [확인]). 원고 전달됨→사용 확정. RT 증빙 제거. 사유 선택.
- **로그**: `task_declined`는 사유가 `declined`·`no_response`일 때만, payload `{taskId, campaignId, campaignName, taskType, reason, action:'cancel'|'replace'}`. 인플 미배정 작업은 로그 없음. 되돌리기 정정 이벤트 없음(한계).
- **기존 화면의 게시 확인 경로**(수동·자동 조회·트래킹 연결)는 취소 작업을 건너뛰고 문구로 알린다.

   - **예산 기간 모델**(koo 09-18, C안): 클라이언트 월 예산(`monthly_budget` + `budget_overrides`)을 **기간 행**(`시작일 · 종료일 · 금액`, 겹침 금지, 빈 구간 = 미설정)으로 교체. 캠페인은 **시작일이 속한 기간**에 귀속 — 주 단위 캠페인이 달 경계에 걸치는 문제(매달 한 주)를 기간을 월요일 시작으로 맞춰 없앤다. 새 기간 기본값 = 직전 종료 다음 날부터 4주·직전 금액. 현행 월 값은 1일~말일 기간으로 이관. 클라이언트 상세 예산 패널·`spendByMonth`·캠페인 카드 라벨이 바뀜(1~2일). 세부는 그때 grilling 한 라운드.
4. 이번 주 캠페인 일괄 생성, 생성 백그라운드 처리, 성과 기반 레퍼런스 제안은 **후순위**(실사용 뒤).
