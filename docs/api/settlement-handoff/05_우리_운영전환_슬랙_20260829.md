운영 서버에 API가 배포됐습니다. 이제 운영에서 확인하실 수 있습니다.

*접속 정보*
• 주소: `https://cb-x-deck.vercel.app` (스테이징과 경로·응답 모양 동일)
• 운영 API 키: DM으로 따로 보내드립니다 — **스테이징 키와 다른 값**입니다. 채널·문서엔 올리지 말아 주세요.
• 명세: 이전에 보낸 `settlement-external-api.md`와 동일(운영/스테이징 차이는 주소와 키뿐)

*운영 데이터 — 지금은 1건입니다*
• 실제 결제 요청 **1건**만 있습니다(마인드스킨클리닉 · ¥5,263 · `status: "requested"` · `settlement.status: null`). 정산 페이지 운영을 시작하면 매주 늘어납니다.
• 스테이징의 42건은 슬랙 이관 데이터라 운영에는 없습니다. 운영은 정산 페이지에서 새로 만든 요청부터 흘러갑니다.
• 운영 데이터는 `requester.email`에 값이 있습니다(스테이징 이관본은 전부 null이었던 필드) — 슬랙 ID 매핑은 여기서 확인해 주세요.

*운영에서 확인 부탁드리는 것*
1. 키 없이 호출 → 401 (본문 없음)
2. `GET /api/external/settlement/requests?limit=100` → 1건, `next_cursor` 저장
3. 같은 커서로 재호출 → 빈 목록(`has_more: false`), `next_cursor`는 보낸 값 그대로
4. `GET /api/external/settlement/requests/{request_id}` → 단건 200
5. 상태 전송(POST)까지 확인 부탁드립니다 — 스테이징에서 이 방향의 호출 기록이 저희 쪽에 남아 있지 않아, 운영 전에 한 번은 맞춰보고 싶습니다.
   • 위 1건에 `{ "status": "received", "updated_at": "<지금 ISO>" }` → 200 `applied: true`
   • **30초 이상 지난 뒤** 저장한 커서로 다시 GET → 그 건이 `settlement.status: "received"`로 다시 내려오는지(에코) 확인
   • 저희 화면에서도 "정산 접수" 배지로 바뀌는 걸 확인하겠습니다

*운영이라 주의 부탁드리는 것*
• `received` / `scheduled`는 실제 업무 흐름이라 보내셔도 됩니다(저희 담당자 화면 표시만 바뀝니다).
• **`paid`는 실제로 송금이 완료됐을 때만** 보내 주세요 — 한 번 `paid`가 되면 저희 쪽에서도 취소가 막히고(운영 규칙), 되돌리려면 사람이 협의해야 합니다. 테스트 목적의 `paid`는 스테이징에서만 해 주세요.
• `cancelled`도 실제 취소일 때만 보내 주세요 — 저희 요청도 취소 처리됩니다.
• 스테이징은 계속 열어 둡니다. 테스트는 스테이징, 실제 흐름은 운영으로 나눠 쓰시면 됩니다(주소·키만 다르고 코드는 동일).

*운영 개시 후*
저희 담당자가 정산 페이지에서 요청을 만들면 폴링(권장 5분)에 새 건으로 내려옵니다. 가져가신 직후 `received`를 보내 주시면 저희 담당자 화면에 "정산 접수"로 표시됩니다.
