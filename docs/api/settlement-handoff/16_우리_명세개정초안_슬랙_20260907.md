# 우리 회신 (우리 → 정산 프로덕트, 슬랙용) — 2026-09-07 제자리 수정 명세 개정 초안

> 아래 그대로 붙여넣기. 첨부: `docs/api/settlement-external-api.md` 현재 판(2026-09-07 제자리 수정 개정 포함).

---

제자리 수정 명세 개정 초안입니다. 첨부한 `settlement-external-api.md`의 **§3-1(새 규칙·그쪽이 지켜야 할 것 5개)·§5(`revision` 의미, `revised_at` 추가)·§6(`revision` 필드, 409 `revision-mismatch`)·§7·§8(개정 기록)** 이 바뀐 곳입니다. 나머지는 그대로입니다.

*핵심만*
• 수정 시: `request_id`·`external_id`·`task_id` 유지, `status: requested` 유지, `revision` +1, `revised_at` 갱신, `settlement.*` 전부 `null`로 리셋(`settlement.external_id`만 유지).
• 상태 POST에 `revision` 필수(전환 후). 다르면 409 `revision-mismatch` + 최신 Item → 재전송 말고 재판단.
• `revision`은 점프할 수 있고, 처음 보는 요청이 `revision > 0`일 수 있습니다. 취소 여부는 `status`로만.
• 수정 요청은 `on_hold`로. `cancelled`는 폐기.
• 전환 스위치는 저희 쪽에 있습니다. 저희가 먼저 배포하되 스위치를 꺼 두어 **그때까지는 지금과 똑같이 나갑니다.** 그쪽 배포가 끝나면 슬랙으로 시각을 맞춰 켭니다.

*확인 부탁*
• 초안에 이견이 있는 문장. 없으시면 저희는 이 문장대로 구현에 들어갑니다(2~3일).
• 15번에서 여쭌 것: 수정 반영 후 자동으로 지급 예정으로 넘길지, 보류를 건 담당자 확인 뒤로 할지.
