# /generate 뷰 다듬기 설계 (2026-08-10, 워크벤치 3차)

## 배경

2차(뷰 다양화+패널 접기) 사용자 검수 피드백 2건:

1. **뷰 토글과 상태 탭이 구분 안 됨** — 둘 다 같은 알약 칩 + 같은 활성 스타일(파란 테두리+연파랑)이라, "테이블"과 "전체 23"이 하나의 필터 그룹에 두 개 선택된 것처럼 읽힘. 근본 원인: 배타적 모드 전환기(뷰)와 콘텐츠 필터(상태)라는 다른 의미 축이 같은 시각 문법을 공유.
2. **테이블/칸반에서 항목 클릭 → 카드 뷰 이동이 불편** — 트리아지 맥락(스크롤·정렬·열 배치)이 날아가고 왕복 비용 발생. 근본 원인: 정독 표면이 '카드 뷰'라는 전역 모드로만 존재해, 항목 단위 열람(peek)을 전역 모드 전환으로 오용.

## 확정 결정

### 1. 뷰 토글을 세그먼티드 컨트롤로
- 한 덩어리 컨테이너(`rounded-lg border`, 내부 칸은 `border-l` 구분) 안에서 **활성 칸은 진한 채움(bg-x-blue + 흰 글자)** — 필터 알약(테두리+연파랑)과 시각 문법이 명확히 다름.
- 토글과 필터 바 사이에 세로 구분선 1개. 라벨(카드/테이블/칸반)·title 툴팁·aria-pressed는 현행 유지.

### 2. 항목 클릭 = 피크 오버레이 (뷰 전환 제거)
- 테이블 행·칸반 카드 클릭(및 키보드 Enter/Space) 시 **현재 뷰 위에 DraftCard를 그대로 담은 오버레이**를 띄운다. 닫으면(✕·Esc·배경 클릭) 원래 뷰의 원래 자리 그대로.
- 오버레이는 z-40 (RefPickerSheet 선례) — 오버레이 안에서 '편집'을 누르면 DraftEditModal(z-50)이 위에 얹힘. Esc는 편집 모달이 열려 있으면 피크를 닫지 않는다(편집 모달의 Esc가 우선).
- DraftCard의 전체 기능(편집·다시쓰기·번역·버전·상태 변경·삭제)이 오버레이 안에서 동작 — 기존 핸들러를 `peeked` 대상으로 그대로 배선. **삭제 시 피크를 먼저 닫고** 낙관적 삭제+실행취소 토스트는 기존 흐름대로.
- `peeked`는 `drafts`에서 id로 파생 — 원본이 사라지면(삭제 확정 등) 오버레이도 자연 소멸.
- **제거되는 것**: openCard의 뷰 전환·필터 리셋·data-draft-id 스크롤·하이라이트 링(2차 F5 포함) — 피크가 전부 대체. DraftTable·DraftKanban은 무변경(onOpenCard prop에 피크 열기를 배선만 바꿈).
- 카드 뷰는 "피드로 훑는 모드"로 유지(카드 뷰에서는 피크 없음 — 이미 전체가 보임).

## 검증
- tsc 0 / lint 24 기준선 / 기존 테스트 회귀 없음. 화면 동작(오버레이·중첩 모달·세그먼트)은 사용자 dev 검수.

## 범위 제외
- 오버레이 안 이전/다음 항목 내비게이션(피드백 확인 후), 카드 뷰에서의 피크.
