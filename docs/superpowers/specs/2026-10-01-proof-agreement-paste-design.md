# RT 증빙 바꾸기 + 방문협찬 동의서 붙여넣기 — 설계

- 날짜: 2026-10-01 · 브랜치 `cb-koo/proof-agreement-paste`(origin/main `309fe62`에서)
- 화면만 바뀐다 — 서버 규칙·DB 변경 없음

## 1. 왜 (koo 10-01)

1. **RT 증빙을 지우고 다시 올리고 싶다.** 캠페인 v2 작업 패널(`PostedBox`)은 게시된 RT의 증빙을 `증빙 보기`로 **보기만** 한다 — 바꾸기·지우기·(없을 때) 올리기가 없다. 옛 화면(`PostedCell`)엔 `바꾸기`가 있었다.
2. **방문협찬 동의서는 대부분 이미지라 붙여넣기(⌘V)가 필요하다.** 동의서 칸(`AgreementField`)은 끌어다 놓기·파일 고르기만 된다.

## 2. RT 증빙: `바꾸기` 한 번으로 (지우기 없음)

- 게시된 RT는 서버가 증빙 비우기를 거절한다(정산 요청 사전 차단의 전제 — 증빙 없는 게시 RT가 생기면 안 된다). "지우고 다시 올리기"는 **`바꾸기` 한 동작**으로 제공한다: 새 이미지가 다 올라가 저장되는 순간 교체, 그 전까지 원래 증빙 유지. koo 승인(10-01).
- 게시된 RT의 패널 표시(현재 `증빙 보기` 칩 자리):
  - 증빙 있음: 썸네일(64px, 눌러 크게 보기) + 버튼 줄 `크게 보기 · 바꾸기 · 받기`.
  - `바꾸기` 누르면 썸네일 아래(또는 자리)에 교체 상자: `새 스크린샷을 붙여넣기(⌘V) 또는 눌러서 고르기` + `취소`. 이 상태에서만 문서 붙여넣기를 받는다(증빙이 있는 평소 상태에선 붙여넣기 무시 — 엉뚱한 이미지로 덮이는 것 방지, 기존 TaskProofField 원칙). 업로드 중 `올리는 중…`, 성공 시 교체 상자 닫힘 + 짧은 확인(`증빙을 바꿨어요`), 실패 시 원래 증빙 그대로 + 오류 문구.
  - 증빙 없음(옛 데이터): 경고 칩 대신 바로 올리기 상자(`붙여넣기(⌘V) 또는 눌러서 파일 고르기`) — 평소처럼 붙여넣기를 받는다(덮을 것이 없다).
- 저장은 기존 `actions.setProof(task, path)`(작업 PATCH `proof`)를 쓴다. 서버 규칙 그대로.
- 구현은 `TaskProofField`를 확장해 재사용한다(옛 화면·게시 확인 폼과 같은 칸): `바꾸기` 눌렀을 때 붙여넣기 받는 "교체 대기" 상태 추가, `canRemove=false`면 지우기 없음(기존). 버튼 디자인은 §4.

## 3. 동의서 붙여넣기

- 동의서 칸이 화면에 있는 동안 문서 붙여넣기(⌘V)로 **이미지 파일**을 받는다(TaskProofField와 같은 방식: 입력 칸·편집 영역으로 향한 붙여넣기는 건드리지 않음, `pasteModalGuard`로 위에 뜬 모달 우선). PDF 붙여넣기는 클립보드에 파일로 오면 그대로 허용(형식 검사는 기존 `taskAgreementGuard`).
- 이미 동의서가 있으면 끌어다 놓기와 같은 확인: `지금 동의서(○○)를 새 이미지로 바꿀까요?`.
- 붙여 넣은 이미지 파일명은 브라우저가 `image.png` 같은 이름을 준다 → **`동의서_@{핸들}_{YYYYMMDD}.{확장자}`**(서울 날짜, 핸들 없으면 `동의서_{YYYYMMDD}`)로 이름을 지어 올린다. 끌어다 놓기·파일 고르기는 원래 이름 유지.
- 빈 상자 안내: `붙여넣기(⌘V) · 끌어다 놓기 · 눌러서 고르기`. 형식·크기 안내(PDF·JPG·PNG, 10MB)는 그대로.

## 4. 버튼·상호작용 디자인 (koo: 사용자 편의성 신경)

- 한 칸 안의 버튼은 **역할에 따라 무게를 나눈다**(동의서 파일 카드 선례 8d225ed와 같은 체계): 주 동작(크게 보기/보기) = 테두리 버튼, 보조(바꾸기·받기) = 옅은 버튼, 지우기 = 휴지통 아이콘. 높이 h-8, 둥근 모양, 간격 일정. 링크처럼 생긴 파란 글자 버튼 나열은 쓰지 않는다.
- 상태가 바뀌는 동작엔 즉시 피드백: 올리는 중 표시(버튼 비활성 + 문구), 성공 짧은 확인, 실패 이유 문구.
- 교체 대기 상자는 "지금 붙여넣으면 바뀐다"가 분명하게: 점선 상자 + 파란 테두리 강조 + `취소` 버튼, ESC로도 취소.
- 키보드: 모든 버튼 Tab·Enter로 동작, 상자도 `<button>`.
- 두 칸(RT 증빙·동의서)의 모양·문구 패턴을 맞춘다.

## 5. 테스트·확인

- 순수 로직이 생기면(파일명 짓기 `agreementPasteName(handle, date, mime)` 등) 단위 테스트.
- 화면은 하네스가 없어 컨트롤러가 로컬 캡처로 상태별(증빙 있음/교체 대기/증빙 없음, 동의서 빈 칸/있음) 확인 — 실제 업로드는 하지 않는다(운영 데이터).

## 6. 업데이트 소식

`개선` 1건: `RT 증빙을 바꾸고, 동의서를 붙여넣기로 올릴 수 있어요` — 패널에서 게시된 RT 증빙 [바꾸기](붙여넣기 가능), 동의서 ⌘V, 붙여 넣은 동의서 이름 자동.
