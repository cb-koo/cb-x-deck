## 슬라이드가 이미 커버하는 것 (중복 정리 안 함)

## A. 게슈탈트 원리 (CRAP의 뿌리 + 확장)
CRAP의 Proximity/Repetition은 게슈탈트의 일부일 뿐. 나머지도 도구로 챙긴다.

| 원리 | 한 줄 정의 | 우리 서비스 체크항목 |
|---|---|---|
| 유사성(Similarity) | 비슷하게 생기면 같은 기능으로 읽힌다 | 같은 역할의 카드·버튼·지표 타일은 **모양·색·크기 통일**. 다르게 보이면 다르게 동작한다는 신호가 되니 주의 |
| 공통 영역(Common Region) | 같은 배경/테두리 안이면 한 그룹 | 지표 그룹, 필터 묶음을 **카드/배경면**으로 묶어 소속을 명확히 |
| 연속성(Continuity) | 눈은 부드러운 선/정렬을 따라간다 | 다단계 흐름(로그인→분석→결과)·리스트를 **정렬 축**으로 이어 시선 끊기지 않게 |
| 폐쇄성(Closure) | 일부만 보여도 뇌가 완성한다 | 캐러셀/스크롤 목록은 **다음 항목을 살짝 걸쳐** "더 있다"를 암시 |
| 전경-배경(Figure-Ground) | 주인공과 배경을 분리 | 모달은 **어두운 오버레이**, 클릭 가능한 요소는 배경 대비로 "눌러진다" 신호 |
| 초점(Focal Point) | 대비가 시선을 한 점에 모은다 | 화면당 **주인공 1개**(핵심 숫자/주요 CTA)만 강조 |

출처: reallygooddesigns.com/gestalt-principles-ui-ux · figma.com/resource-library/gestalt-principles · blurtest.com/blog/gestalt-principles-in-ui-design-a-practical-guide

## B. Nielsen 사용성 휴리스틱 10 (진단 프레임)
화면을 "예쁜가"가 아니라 "쓸 수 있는가"로 점검하는 표준 10항목.

1. **시스템 상태 가시성** — 지금 뭐가 되고 있는지 항상 보여줌(로딩·진행·완료)
2. **현실 세계와 일치** — 사용자 언어로. 내부 개념어 금지 *(AGENTS.md 원칙1과 동일)*
3. **사용자 통제·자유** — 실수 취소(Undo)·되돌아갈 출구
4. **일관성·표준** — 같은 뜻은 같은 말·같은 위치. 업계 관습 따르기
5. **오류 예방** — 좋은 에러 메시지보다 **애초에 오류가 안 나게** 설계
6. **회상보다 인식** — 외우게 하지 말고 **보이게**(옵션·최근 항목 노출)
7. **유연성·효율** — 초보엔 안 보이되 숙련자엔 단축키/고급 경로 제공
8. **심미적·미니멀** — 관련 없는 정보는 뺀다 *(Less is More와 연결)*
9. **오류 인식·복구 지원** — 에러코드 대신 **원인+해결책**을 평문으로
10. **도움말·문서** — 이상적으론 불필요하되, 필요하면 맥락 안에서 제공

체크: 새 화면을 이 10개로 훑고 위반 지점에 심각도(0~4) 매겨 우선순위화(heuristic evaluation).
출처: nngroup.com · heurilens.com/blog/nielsens-heuristics · blog.logrocket.com/ux-design/conduct-heuristic-evaluation-tutorial

## C. UX 법칙 — 인지 부하 (Laws of UX)
"핵심만 남기기"를 왜/어떻게 하는지의 심리학적 근거.

| 법칙 | 내용 | 우리 서비스 적용 |
|---|---|---|
| **Hick's Law** | 선택지 많을수록 결정 시간 ↑ | 필터·버튼·옵션 수 줄이기. 못 줄이면 **점진적 공개**로 필요할 때만 노출. 추천값을 강조해 결정 유도 *(AGENTS.md 원칙3 '추천' 연결)* |
| **Miller's Law** | 작업기억은 7±2개 | 지표·링크를 **덩어리(chunk)**로 묶기. 긴 리스트는 4~5개 헤딩 아래로 그룹화 |
| **Fitts's Law** | 타깃은 크고 가까울수록 빨리 누른다 | 주요 CTA·터치 타깃 **충분히 크게**(최소 44×44px), 자주 쓰는 건 손닿는 위치 |
| **Jakob's Law** | 사용자는 다른 사이트에 익숙 → 관습대로 | 검색은 우상단, 로고는 홈, 장바구니 아이콘 등 **표준 패턴** 따르기(새로 학습시키지 말 것) |

출처: lawsofux.com · uxdesigninstitute.com/blog/laws-of-ux · myuxacademy.com/blog/ux-design-laws-principles

## D. 시각적 위계 (Contrast의 실전 확장)
"무엇을 먼저 보게 할까"를 크기·대비·여백·위치로 설계.

- **3단계 크기 규칙** — 헤더/서브헤더/본문 정도로 크기는 3개까지만. 위계는 개별 크기가 아니라 **단계 간 대비**에서 나온다(48px 얇은 글씨 < 24px 굵은 글씨).
- **위계는 색만이 아니다** — 크기·굵기·자간·행간·모션·밀도(주변 여백)로도 만든다. 여백 섬에 놓인 요소는 실제 크기보다 중요해 보인다.
- **스캔 패턴** — 글 많은 화면은 **F 패턴**, 요소 적은 화면은 **Z 패턴**. 핵심을 눈이 실제 머무는 곳(상단·좌측)에 배치. 사용자는 시청 시간의 ~57%를 첫 화면(above the fold)에 쓴다.
- **마이크로 위계** — 라벨과 값, 버튼 라벨과 아이콘의 굵기/간격 관계까지 일관되게. 여기가 어긋나면 "덜 다듬어진" 느낌을 사용자가 감정적으로 먼저 느낀다.

## E. 대시보드 / 데이터 시각화 ★ (우리 서비스 핵심 축)
데이터를 "덤프"가 아니라 "결정 도구"로. Tufte·Stephen Few 기반.

- **Data-Ink 비율 최대화** — 데이터가 아닌 잉크(테두리·격자·그림자·3D·장식)는 최소화. 격자선은 옅게 또는 제거.
- **차트는 질문에 맞춘다**
  - 시간 추이 → **선(line)** (X축=시간, 계열 5개 이하)
  - 카테고리 비교 → **막대(bar)** (값 순 정렬, 7개 이하, 막대차트 Y축은 0부터)
  - 부분/전체 → 5+개면 누적막대, 2~4개만 파이/도넛
  - 단일 지표 → **지표 카드(Metric Card)**
  - 상세 열거가 목적이면 → **표**(타일 벽 금지)
- **KPI 카드** — 화면 최상단 큰 숫자(48px+), **각 지표엔 반드시 비교 맥락**(전기간 대비 증감). 3~6개만. 15개 늘어놓으면 아무것도 전달 못 함. *(우리 /usage 스토리텔링과 직결)*
- **한 화면 = 몇 초 읽기** — 히어로 차트 1개 + 보조 지표 몇 개 > 경쟁하는 차트 5개. "모두 강조 = 아무것도 강조 안 됨."
- **정확도 순 인코딩** — 사람은 위치 > 길이 > 각도 > 면적 > 색 순으로 정확히 읽음. 중요한 비교는 가장 정확한 채널(위치/길이)로. 색은 보조 신호로만.
- **위젯 5~7개/뷰**, 각 위젯 내부 구조 통일(제목=좌상단, 컨트롤=우상단). 기본 상태가 한눈에 답을 주고, 인터랙션(필터·드릴다운)은 그 위에 얹을 때만 가치 있음.

출처: desisle.com/resources/saas-dashboard-design-guidelines · perceptualedge.com(Stephen Few) · valiotti.com/dashboard-design-rules · setproduct.com/blog/dashboard-ui-design

## F. Norman 6원칙 (직관성의 기반)
"매뉴얼 없이 이해되는가" = discoverability.

| 원칙 | 뜻 | 체크 |
|---|---|---|
| 어포던스(Affordance) | 생김새가 가능한 행동을 알림 | 버튼은 눌러질 것처럼, 입력칸은 채워질 것처럼 보이게 |
| 시그니파이어(Signifier) | 어디를/어떻게를 알려주는 단서 | 라벨·아이콘·힌트로 "여기 누르세요"를 명시 |
| 매핑(Mapping) | 컨트롤과 결과의 자연스러운 대응 | 좌=이전, 우=다음 등 공간적 직관 맞추기 |
| 피드백(Feedback) | 모든 행동에 즉각·명확한 반응 | 클릭·저장·API 콜에 상태 변화를 즉시 보여줌 |
| 제약(Constraint) | 잘못된 행동을 막음 | 불가능한 옵션은 비활성/숨김으로 실수 원천 차단 |
| 개념 모델 | 머릿속 작동 그림 | 사용자가 예측 가능한 일관된 동작. 거짓 어포던스(눌러도 안 되는 것)는 신뢰를 깬다 |

## G. UI 상태 설계 (AI가 자주 빠뜨리는 것)
모든 데이터/빈 뷰는 **4가지 상태**를 명시적으로 설계. 빈 화면+무설명 금지.

- **로딩** — 200ms 후 **스켈레톤**(최종 레이아웃과 동일). 중앙 스피너+빈 화면은 지양. 스켈레톤은 체감 로딩을 ~30% 줄이고 레이아웃 시프트 방지.
- **빈 상태(Empty)** — ①왜 비었는지 ②다음 할 행동(단일 CTA) ③채워지면 뭐가 보일지. "데이터 없음"은 기회 낭비. 필터 결과 0건과 신규 사용자 0건을 구분.
- **에러(Error)** — 평문으로 ①무엇이 잘못됐나 ②어떻게 복구(재시도/뒤로/문의) ③되돌아갈 길. 스택트레이스·에러코드 노출 금지, 사용자 탓 금지. (지원용 에러 ID는 병기 가능)
- **성공/부분/오프라인** — 성공은 색만이 아닌 시각 피드백. 여러 소스면 부분 로드 처리.
- (고급) **낙관적 UI** — 좋아요·북마크 등은 즉시 반영 후 실패 시 롤백.

체크: 새 뷰는 **로딩·빈·에러·정상** 4개를 JSX 쓰기 전에 먼저 설계.
출처: blog.vibecoder.me/empty-states-loading-states-error-states · agenticdevelopercookbook.com/guidelines/implementing/ui/state-design · skills.smoothui.dev/docs/state-design

## H. 마이크로카피 / UX 라이팅
작은 글자가 전환·이해를 좌우. *(AGENTS.md 원칙1·2·3의 실행 지침)*

- **버튼 = 동사 + 결과** — "제출/확인" ✕ → "리포트 다운로드", "계정 만들기" ○. 1~4단어. "무엇을 하면 무엇을 얻는지".
- **3C** — Clarity(명료) > Concision(간결) > Character(개성) 순 우선. 명료가 최우선.
- **플레인 랭귀지** — 전문용어(min_faves, probe, density…)는 옆에 뜻을 붙이거나 사용자 언어로. *(AGENTS.md 원칙5)*
- **헬퍼 텍스트** — 입력/버튼 옆에 "무엇→무엇" 한 줄(progressive disclosure, 필요한 자리에만).
- **에러 카피** — 무엇이 잘못됐고 어떻게 해결하는지.
- **결과 서술** — 숫자만 던지지 말고 해석+다음 행동. "좋아요 53~346" ✕ → "반응이 드문 편(53~346) → min_faves 100 추천 [적용]" ○ *(AGENTS.md 원칙3)*

## I. 접근성 (WCAG 실무 최소선)
빼기 어려운 기본기. 색약·저시력·키보드 사용자까지.

- **대비** — 본문 텍스트 **4.5:1** 이상(큰 텍스트 3:1), UI 경계·아이콘 **3:1** 이상.
- **색만으로 의미 전달 금지** — 빨강=에러에 **아이콘(✕/⚠)·텍스트·위치**를 함께. 필수 항목은 색이 아니라 별표+"필수".
- **키보드** — 모든 기능 키보드로 조작 가능, 키보드 트랩 없음, **포커스 표시 항상 보이게**(2px 아웃라인).
- **터치 타깃** — 최소 44×44px (Fitts's Law와도 연결).
- **가독성** — 본문 14px+(16px 권장), 행간 1.5+, **200% 줌에도 가로 스크롤 없이**.
- **모션** — `prefers-reduced-motion` 존중.

## J. 디자인 시스템 기반 (Repetition을 시스템으로)
일관성을 눈대중이 아니라 **토큰**으로 강제.

- **8pt 그리드** — 간격은 8의 배수(4·8·12·16·24·32·48·64…). 1×/1.5×/2× 디스플레이에 깔끔히 스냅. Material·Apple·Primer·Atlassian 공통.
- **타입 스케일** — 모듈러 스케일(비율 1.125~1.25). 임의 크기(14/17/22/28) 대신 한 비율에서 파생. Stripe식 "조용한 위계".
- **개수 제한** — 타입 6~8개, 간격 토큰 6~8개. 더 많으면 위계가 흐려지고, 적으면 즉흥이 된다.
- **간격의 의미** — 관련 콘텐츠 4~16px, 액션과 콘텐츠 사이 16~32px, 섹션 구분은 더 크게. "이 요소들은 친구인가?"로 자문.
- **토큰화** — 색·간격·타입을 CSS 변수/토큰으로 통일 → 반복·일관성이 자동으로 유지됨.

## K. 비개발자 / 저디지털 리터러시 배려 ★ (우리 사용자 정의)
우리 사용자 = 비개발 기획자. 속도보다 **확신**을 준다.

- **확신·안심이 핵심 지표** — 이들은 "빠름"보다 "내가 제대로 했다"는 확신을 원함. 실수로 뭘 망칠까 두려워함.
- **전문용어 제거·인간적 언어** — Submit/Proceed/Authenticate/Verify 같은 딱딱한 말 피하기.
- **선택지 최소화** — Skip/Save/Continue/Maybe Later 동시 노출은 초보에게 "어느 게 정답?" 불안을 줌. 가이드가 되어라(게이트키퍼 X).
- **점진적 공개** — 한 번에 다 설명 X. 필요해질 때 고급 기능 노출. 첫 화면은 핵심 1~2개 행동만.
- **맥락 안내** — 막혔을 때 화면을 떠나지 않고 그 자리에서 팁·마이크로카피 제공.
- **기준 질문** — "쓰기 쉬운가?"가 아니라 **"도움 없이도 이해되는가?"**

## L. 즉시 캡처 · 인라인 생성 · 입력 마이크로인터랙션 ★ (행동 지점 흐름)
우리 서비스엔 "덱에서 트윗을 보다가 → 저장 → 한 줄 메모"처럼 **판단이 선 순간 바로 흔적을 남기는** 흐름이 많다. 이 순간의 마찰을 설계로 없앤다. (첫 적용: 덱 ☆ 저장 시점 인라인 메모 캡처)

### L-1. 캡처는 마찰 없이, 정리는 나중에 (Capture ≠ Organize)
- **캡처와 정리는 별개 활동.** 저장·메모를 남기는 순간엔 "외재화"만 시키고 태그·분류·정리는 나중(보관함)으로 미룬다. **캡처 시점에 분류를 강제하면 마찰이 급증**한다.
- **의도→기록 사이 결정 지점을 0에 가깝게.** "저장할까? → 어디에? → 무슨 형식? → 제목은?" 각 결정이 통찰을 흘린다. 필수 필드 0개, 커서만 준비.
- **"사람 속도로 캡처, 기계 속도로 정리."** 캡처 순간엔 최대 충실도·최소 마찰, 나머지는 잊지 않는 시스템(보관함)에 위임. 임계는 대략 **5초/1제스처** — 그 이하면 "할까 말까" 계산 자체가 사라진다.
- 우리 체크: 캡처 입구(☆)는 **1클릭 즉시 저장 유지**, 어떤 결정도 얹지 않는다. 메모는 **선택적**(강제·필수 아님)으로 저장 직후 그 자리에서. 정리(수정·태그·팀 코멘트)는 보관함으로 미룬다.

### L-2. 현재 맥락 안에서 생성 (인지 거리 최소화, pogosticking 금지)
- 새 데이터는 **사용자가 지금 있는 화면에서 바로** 만들 수 있게. 별도 페이지로 보내 왕복(pogosticking)시키지 않는다.
- 작고 잦은 생성·수정 = **인라인(edit/expand-in-place)**. 모달의 open→save→close 세금, 페이지의 navigate-away→come-back 세금을 피한다.
- 모달·페이지 이동은 **방해가 목적일 때만**(파괴적 확인 등). 카드가 그 자리에서 펼쳐지는 inline expansion이 오버레이·내비게이션 없이 방해가 가장 적다.
- 우리 체크: 저장 메모를 보관함으로 보내 왕복시키지 않고 **덱 카드 안에서 인라인 펼침**으로 잡는다.

### L-3. 입력/컴포저 마이크로인터랙션 (기본기 체크리스트)
- **IME 조합 중 Enter 무시**(`isComposing`) — 한국어/일본어 오전송 방지. *(우리 코드 이미 준수)*
- **단일행 = Enter 제출**, 멀티행(textarea) = Cmd/Ctrl+Enter 제출·Enter는 줄바꿈(하나로 정하고 일관되게).
- **autofocus** — 펼침과 동시에 커서 준비(데스크톱). time-to-첫키를 0으로. (모바일은 키보드 팝업 주의)
- **Escape로 닫기**, 입력이 있으면 폐기 확인 또는 보존.
- **입력 보존** — 실패·중단·포커스 이탈에도 초기화 금지. 성공 제출 후에만 비운다.
- **placeholder ≠ 라벨** — 포커스 시 사라지므로 뜻은 힌트/라벨로. 힌트는 입력 위, 에러는 입력 아래(읽기 순서).
- **빈/공백 제출 거부**(trim), 제출 중엔 라벨을 로딩 상태로 바꾸되 포커스는 유지.
- **낙관적 반영 + 성공 피드백** — 저장은 즉시 시각 반영, 성공은 색만이 아닌 명시 신호(F-피드백·G-낙관적 UI와 연결).
