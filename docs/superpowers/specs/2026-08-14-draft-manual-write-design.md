# 원고 직접 쓰기 — LLM 없는 두 번째 입구 (설계)

2026-08-14.

**배경.** `draft` 테이블은 글의 출처를 신경 쓰지 않게 설계돼 있다 — 필수는 본문(`content`)뿐이고 클라이언트·레퍼런스·방향성·모델은 전부 비울 수 있다. 저장 이후의 모든 기능(검수 표식·번역·상태 축·인플루언서 배정·공유 링크·표·칸반·일괄 처리)도 출처를 보지 않는다. 그런데 본문을 채우는 입구가 LLM 생성 하나뿐이라, 사람이 쓴 원고는 관리 밖(메신저·메모장)에 남는다.

**용도(사용자 확인).** 주: (B) AI 결과가 안 맞을 때 백지에서 직접 쓰기, (D) 처음부터 사람이 쓰는 원고도 검수·배정·전달 관리는 한곳에서. 부: (C) 외부에서 받은 원고 등록 — v1에서는 붙여넣기로 커버하고 일괄 등록은 만들지 않는다.

**해결.** 생성 패널에 '직접 쓰기' 진입점을 내고, 저장하는 순간 초안을 만든다. 새 기능이 아니라 **이미 있는 기계에 두 번째 문을 내는 일**이다.

## 원칙

- **LLM을 일절 부르지 않는다.** 생성·한국어 대역·자동 제목 전부 생략. 번역은 필요할 때 기존 버튼으로(비용 opt-in). `model: null`이 직접 작성의 표식이다 — UI 어디서도 `model`을 읽지 않음을 확인했으므로 무해하다.
- **저장 전엔 서버를 부르지 않는다.** 닫으면 아무것도 안 남는다 — 빈 초안 쓰레기 없음.
- **저장 이후는 기존 초안과 완전히 동일하게 취급한다.** 별도 카드·별도 뷰·별도 상태를 만들지 않는다.
- **컴포저의 조건을 승계한다.** 생성이 실패해 직접 쓰기로 전환하는 순간(B) 골라둔 클라이언트·시술이 이미 그 자리에 있다. 이 연결이 금지어 검수의 재료다(D).

## 확정 판단 (코드로 검증한 사실)

- **다시 쓰기가 직접 쓴 원고에서 그대로 동작한다.** `rewriteDraft`는 클라이언트·레퍼런스·방향성을 요구하지 않고, `buildUserPrompt`는 빈 재료를 전부 건너뛴다. "직접 쓰고 AI로 다듬기"가 구현 없이 생긴다.
- **검수 표식은 클라이언트 없이도 동작한다.** 약기법·의료광고 표식은 텍스트만 보고, 금지어만 클라이언트·시술에서 온다.
- **format은 `formatForPosts`(posts 길이 파생)를 재사용한다.** PATCH가 이미 쓰는 규칙이고, 어긋나면 다시 쓰기가 손으로 늘린 칸을 잘라내는 기존 함정까지 자동 회피된다.
- **기존 편집 모달은 창작에 재사용할 수 없다.** 칸 추가·이미지·제목이 전부 기존 `draft.id`로 즉시 PATCH하는 구조다. 작성 모달은 별도 컴포넌트로 만들되, 저장 전엔 전부 로컬 상태다.

## A. `POST /api/drafts/manual` (신규, 얇은 라우트)

요청: `{ posts: string[]; title?: string; clientId?: string | null; procedureIds?: string[] }`

1. `requireMember` 게이트. `memberId`는 게이트에서(위조 차단, 생성 경로와 동일).
2. 검증: `posts`가 비어 있지 않은 배열이고 **모든 항목이 공백이 아닌 문자열**. 아니면 400 `'본문을 입력해주세요'`. 칸 수 상한 없음(기존 편집 모달의 칸 추가와 동일).
3. `clientId`가 있으면 로드해 이름·시술명 스냅샷(생성 경로와 같은 방식). 못 찾으면 400.
4. `insertDraft`: `content` = posts(media 빈 배열), `model: null`, `format: formatForPosts(posts.length)`, `direction: ''`, `referenceMode: 'off'`, `refs: []`, `title`(있으면), 대역·koTitle 없음.
   - `insertDraft`에 `title?: string | null` 옵션을 추가한다 — 지금은 자동 제목(`koTitle`)만 받고 사람 제목은 사후 PATCH로만 들어간다. 작성 모달에서 제목까지 쓴 걸 저장 직후 PATCH 한 번 더로 넣는 건 두 요청이 한 동작인 척하는 것이라 삽입에서 받는다.
5. 응답: `DraftRow` **배열**(생성 POST와 같은 모양 — 페이지 삽입 배선 재사용).

## B. `src/components/DraftWriteModal.tsx` (신규)

편집 모달의 겉모습(600px·X 컴포즈 구조·아바타·글자수)을 따르되 저장 전 로컬 전용.

| 요소 | 내용 |
|---|---|
| 제목 | 선택 입력 — 편집 모달의 제목 칸과 같은 자리·같은 도움말 톤 |
| 본문 | textarea + X 가중 글자수(`xWeightedLength`), 첫 칸 autoFocus |
| 칸 추가/삭제 | **로컬 상태로만**(`addSlot`/`removeSlot` 재사용) — 스레드로 키우기 |
| 이미지 | 없음 — 업로드가 `draft.id`를 요구한다. 저장 후 카드에서 붙인다(기존 흐름) |
| 저장 | 전 칸 비어있지 않을 때만 활성. POST → 성공 시 `onSaved(row)` |
| 닫기 | ✕·Esc·배경 클릭, dirty면 확인(기존 관례, IME 조합 중 Esc 무시) |

컴포저에서 승계한 클라이언트가 있으면 상단에 조용한 한 줄로 표시한다(예: `서울피부과 · 보톡스에 연결됨`) — 어디 소속으로 저장되는지 저장 전에 보여야 한다(AGENTS 원칙 2).

## C. 진입점 — `ComposerFooter`

'원고 만들기' 아래 보조 톤 버튼 **'직접 쓰기'**. `canGenerate` 게이트를 타지 않는다(백지 허용). `generating` 중에도 누를 수 있다 — 생성을 기다리는 동안 직접 쓰는 것을 막을 이유가 없다.

## D. `src/app/generate/page.tsx` — 배선

`writeOpen` 상태 + 모달 렌더. 저장 성공 시 생성 경로와 동일하게 목록 맨 위 삽입 + `revealIfHidden`. 모달에 컴포저의 `clientId`·`procedureIds`를 넘긴다.

## E. 문구 — 편집 모달의 '생성 원본'

`model === null`이면 비교 뷰의 "생성 원본" 라벨을 **"처음 쓴 글"**로. 직접 쓴 원고의 `content`는 첫 저장본이라 의미는 이미 맞고 라벨만 어긋난다. (카드 헤더의 `· 초안 ·` 등 다른 표시는 출처 중립이라 그대로.)

## 테스트

- `draftStore` 또는 라우트 로직의 순수 부분: manual 삽입이 `model: null`·`format` 파생·스냅샷을 올바르게 저장하는지, 빈 posts 거부.
- 기존 `formatForPosts`·`addSlot` 테스트는 이미 있음 — 재사용이므로 추가 없음.

## 하지 않는 것

- **일괄 등록(여러 건 붙여넣기).** C 용도가 부차적 — 실사용에서 여러 건 등록 마찰이 확인되면 그때.
- **작성 모달 안 이미지 첨부.** 저장 후 카드에서 — 업로드 구조상 자연스럽고, 첫 저장을 가볍게 유지.
- **자동 제목·한국어 대역.** LLM 무호출 원칙. 목록 라벨은 본문 첫 줄 폴백(`draftLabel`)이 이미 처리.
- **출처 뱃지("직접 작성" 표시).** 지금 그걸 보고 달라질 행동이 없다 — 필요해지면 `model: null`로 언제든 그릴 수 있다.
