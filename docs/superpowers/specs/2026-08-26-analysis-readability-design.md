# 계정 분석 가독성 재구성 + 프로필 패널 면 문법 — 설계 스펙

- 날짜: 2026-08-26 · 브랜치 `cb-koo/influencer-profile`
- 피드백: "프로필 분석 내용 가독성 떨어지고 내용이 눈에 들어오지 않음" + "캠페인 페이지의 회색 바닥·흰 패널 문법이 가독성에 도움 — 그 원리를 이 페이지에도"
- 근거: 데이터 스토리텔링 리서치(폐기 브랜치 cc0cc63의 10원칙: so-what 먼저·결론적 제목·비교 기준 동반) + 2026-08-26 리서치(Minto 하향식 전달·HypeAuditor/Favikon/Modash 등급·판단어·동급 대비, 서술 ~67단어, Cleveland&McGill 정렬 막대, 희소 히트맵 창 축소).

## 1. 구조 뒤집기 — 결론 → 근거
계정 분석 패널 순서: **① 헤드라인 인사이트(1~2문장)** → ② 수치 타일 3개 → ③ 유형 분포 막대 → ④ 주제×반응 표 → ⑤ 발행 히트맵 → ⑥ 서술 3단락(질문형 제목). 캡션(최근 N건·기간·분석 시점)은 제목 줄 유지.

## 2. LLM 종합(서버, `influencerAnalysis.ts`)
- `summary.headline: string` 추가(스키마 required) — 1~2문장: 첫 문장 = 이 계정이 어떤 계정인가(구성·톤 기반), 둘째 = 협업 관점 핵심(잘 통하는 주제·협찬 표기 유무). 원시 숫자 금지.
- 서술 3단락 규칙: **단락당 2~3문장, 첫 문장이 결론**, **원시 숫자 금지**(대신 "이 계정 평균의 몇 배", "표본의 약 절반" 같은 비교어; 건수 정도만 허용), 이모지·인용 원문은 짧게. 프롬프트에 "읽는 사람은 비개발 기획자, 숫자는 표에 따로 있다" 명시.
- 종합 입력에 **계정 전체 조회 중앙값**과 주제별 배율(topic.medianViews / stats.medianViews)을 미리 계산해 넘긴다 — LLM이 배율을 계산하지 않고 인용만 한다.
- 타입: `InfluencerAnalysis.summary`에 `headline?: string`(구버전 분석 호환 — 없으면 UI가 헤드라인 자리를 생략).

## 3. 숫자 표기 — 한국어 단위 (`src/lib/formatKo.ts`)
`formatKoCount(n)`: 0~999 그대로(천단위 콤마 없음) · 1,000~9,999 → `6.1천` · 10,000 이상 → `57.8만` · 1억 이상 → `1.2억`(소수 1자리, .0은 생략). 분석 화면은 '읽기' 표면이라 X식 K/M 대신 한국어 단위(덱 카드의 X 미러링 표기는 그대로). `judgeEngagement`의 값 표기도 이 함수로(테스트 기대값 갱신).

## 4. 유형 분포 → 정렬 수평 막대
큰 순서, 라벨 · 건수 · 비중(%) 병기, 막대 길이=비중, 단일 색(x-blue). **'기타'가 최댓값이면 회색**으로 낮추고 아래 판단문 "분류에 안 잡히는 글이 가장 많아요 — 잡담·짧은 반응이 많은 계정일 수 있어요". 분모는 분류된 글 수(캡션 "분류 N건 기준").

## 5. 주제 칩 → 정렬 표
열: 주제 · 건수 · 조회 중앙값(한국어 단위) · **이 계정 평균 대비**(×n, 1.5 이상 "잘 퍼짐"/0.7 이하 "낮음" 판단어) · 표본 부족 표시(n≤2 → "표본 부족" 회색). 정렬 = 조회 중앙값 내림차순. 계정 평균 = `stats.medianViews`. 바이럴 각주는 이번엔 표본 부족 표시로 갈음(트윗별 최댓값을 저장하지 않음 — 다음에 필요하면 `maxViews` 추가).

## 6. 히트맵 — 셀 크기 고정 + 창을 데이터 기간으로
셀 **고정 20px·간격 3px**(1fr 폐기 → 계정마다 높이 동일). 창 = 표본 시작 주(일요일)~until, **최소 4주·최대 14주**. 표본이 분석 창(3개월)보다 짧으면 캡션 "8/10부터 100건이 찼어요 — 최근 2.5주 기준". 요일 라벨·월 라벨·툴팁·범례 유지.

## 7. 면 문법 — 회색 바닥 위 흰 패널 (캠페인 상세와 동일 값)
- `page.tsx` 오른쪽 프로필 영역 `bg-x-surface min-h-full`(왼쪽 명부는 흰색 유지 — 캠페인과 같은 결정).
- `profileShared.ts`의 `PANEL`/`PANEL_TITLE`(캠페인과 동일 값) 사용. **패널 1**: 헤더+현황 스트립+알림띠. **탭 바**: 바닥 위(패널 밖). **각 섹션 = 패널 1장**(계정 분석 / 태그 / 고정 메모 / 주고받은 기록 / 명부에서 제거 / 참여 캠페인 / 넘긴 원고 / 협찬 단가). 패널 사이 `space-y-5` 단일 출처 — 섹션 컴포넌트의 `mt-7 border-t pt-5`·`[&>section:first-child]` 오버라이드 전부 제거. 섹션 제목은 `PANEL_TITLE`.
- 제거(DangerZone)는 패널이되 테두리 없이 텍스트만 — 위험 액션이 카드로 승격돼 눈에 띄면 안 된다.
