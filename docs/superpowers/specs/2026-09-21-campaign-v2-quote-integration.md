# 새 작업 원고와 인용 대상 수정 통합

## 브랜치와 로컬 서버

- 공통 기반: main `63b99ba`.
- 새 작업 폼: `cb-koo/campaign-v2-form-draft`, `e825b26`까지 포함.
- 인용 대상 수정: `cb-koo/quote-target-reference-fix`, `57a243a`.
- 통합: `cb-koo/campaign-v2-quote-integration`. 기존 두 워크트리는 그대로 둔다.
- 통합 QA 서버: `http://127.0.0.1:3102`, 스테이징 DB. 3001은 새 작업 폼 단독, 3101은 인용 대상 수정 단독이다.

## 통합 계약

새 작업은 아직 저장된 ID가 없으므로 기존 `quoteTargetTaskId`만으로 인용 대상을 지정할 수 없다. 기존 작업은 그 ID를 계속 사용하고, 새 작업 폼은 `quoteTargetInput`에 대상 작업 ID 또는 X 게시물 링크 하나만 보낸다. 서버는 입력·대상 작업 존재·취소·유형을 검사하고, 작업 참조라면 서버에 저장된 게시 링크를 읽는다. 본문을 요청에서 받지 않으며 원문 조회는 X의 기존 상세 조회 경로만 사용한다.

- 두 문맥을 동시에 지정하면 생성 전에 거절한다.
- 링크가 없는 대상 작업은 기존처럼 방향성 등으로 초안을 만들 수 있다.
- 대상 중복 제거·8건 상한·일반 레퍼런스 검사·캐시·스냅샷·다시 쓰기는 두 진입점이 공유한다.
- 새 작업 폼에서 시안 생성·선택 시 작업을 만들지 않는다. 최종 [만들기]에서 작업과 원고를 함께 연결한다.
- 작업 선택 화면의 게시 링크는 중복 제거·비용 안내에만 사용한다. 서버는 해당 작업을 다시 읽는다.
- 스키마 변경·마이그레이션은 없다.

## 검증

- 생성·프롬프트·인용 대상 통합·선택 계산·폼 호스트·작업 생성 본문 테스트 총 54건 통과.
- 새 작업의 링크 생성 후 원고와 함께 저장, 게시된 대상 작업 참조, 미게시 대상, 취소·없는 대상·RT 유형·잘못된 입력·문맥 동시 지정 검증을 추가했다.
- DB 테스트는 스테이징 가드, `USAGE_RECORDING=off`, AI/X 대역을 사용했다.
- TypeScript, 변경 파일 ESLint, 프로덕션 빌드 통과.
- Chrome 통합 QA에서 저장 전 인용 대상 시안 생성(일반 레퍼런스 없음), 시안 선택 후 폼 복귀, 대상·메모 유지, [만들고 하나 더]의 작업+원고 저장 및 다음 폼 초기화를 확인했다.
- 실제 생성 응답 200, 약 12.2초. 작업 `9582128b-f2de-4401-8548-cffa4d55512b`, 원고 `cd4797a5-1760-475c-a2b8-df759273fa94`, 메모 `QA 통합 0921 · 새 작업 원고 + 인용 대상`. 스테이징에 확인용으로 남겼다.
- 게시 전 대상 작업을 선택하면 본문을 아직 반영할 수 없다는 안내가 보인다.
- 브라우저 QA에서 대상 선택 직후 AI 화면으로 이동하면 대상 정보 조회 동안 선택이 누락되는 구간을 발견했다. 선택 ID를 즉시 반영하고 늦은 응답이 다른 선택을 덮지 않도록 보완했다. 링크 확인 전에는 그 상태에 맞는 안내와 조회 비용을 표시한다.
- Aside에서는 동시 사용자 작업과 충돌해 별도 Chrome 탭에서 진행했다. 로컬 인증 토큰 갱신 충돌로 재로그인한 건은 제품 코드 변경 없이 해결했다.
- 저장 후 다시 쓰기에서 버전 2개 및 인용 대상 작성자·본문·링크 유지 확인. 보완 뒤 대상 선택 직후 AI 화면으로 이동해도 대상 칩과 서버 조회 안내가 즉시 표시되는 것을 확인했다.
- 최종 보완 후 타입 검사·변경 파일 린트·프로덕션 빌드 재통과. 운영 배포는 main 반영 뒤 상태와 커밋을 확인한다.

## 배포 순서

두 기능을 따로 배포하지 않는다. 이 통합 브랜치의 QA가 완료되면 업데이트 소식을 정리하고 main에 함께 반영한다. 기존 두 브랜치를 별도로 다시 머지할 필요가 없다. 운영 배포의 성공과 적용 커밋까지 확인한다.
