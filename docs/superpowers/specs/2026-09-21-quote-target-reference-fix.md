# 인용RT 대상 게시물을 보관함 저장 없이 원고에 반영하기

## 문제와 범위

캠페인 원고 모드가 인용 대상을 일반 `refTweetIds`에 넣지만, 생성 서버는 보관함에서만 레퍼런스를 읽는다. 대상이 보관함에 없으면 생성이 실패하고, 있어도 AI에는 형식·앵글 참고 자료로만 전달된다.

대상의 조회 경로와 프롬프트 역할을 분리한다. 기존 원고·일반 생성·생성 후 시안 선택으로 붙이는 흐름은 유지한다. 미게시 대상의 원고를 대신 읽는 기능, 보관함 자동 추가, 배포·머지는 이번 구현에 포함하지 않는다.

## 계약

- `quoteTargetTaskId`는 인용RT 원고를 준비하는 작업의 ID다. 인용 대상 작업의 ID나 생성 후 부착을 뜻하는 `taskId`와 다르다.
- 서버가 작업 존재·유형·취소 여부와 저장된 대상 정보를 검증한다. 화면이 본문을 임의로 제공하지 않는다. 원고를 준비하는 작업은 게시 전이어도 된다.
- 대상 작업 참조와 직접 링크의 우선순위는 기존 `targetUrlOf`와 일치한다.
- 링크가 아직 없는 미게시 대상은 본문을 자동 반영하지 않는다. 화면이 그 사실을 알리고 기존 클라이언트·방향성·일반 레퍼런스로 생성할 수 있다.
- 링크가 있는데 조회할 수 없는 경우에는 대상 없이 조용히 생성하지 않는다. 삭제·비공개와 일시적 조회 장애를 구분하고, AI 호출 전에 중단한다.
- 대상은 저장된 트윗을 먼저 읽고, 없을 때만 기존 X 조회와 매핑을 사용해 캐시한다. 네트워크 조회는 생성 버튼을 누른 뒤에만 실행한다. 보관함 항목은 생성하지 않는다.
- 유효하지 않은 입력과 일반 레퍼런스 누락을 먼저 검사한다. 대상 본문 조회 실패 시 원고 생성 비용은 발생하지 않지만 외부 조회 자체의 비용은 발생할 수 있다.

## 저장·프롬프트·화면

- 기존 `refs` JSON 스냅샷에 선택적 `role: 'quoteTarget'`을 추가한다. 역할이 없는 기존 항목은 일반 레퍼런스다. DB 마이그레이션은 필요 없다.
- AI에는 대상 본문을 별도 구역으로 전달하고, 해당 게시물에 덧붙일 인용RT 글을 쓰도록 지시한다. 일반 레퍼런스의 참고 방식과 독립적으로 적용한다.
- 전체 다시 쓰기와 스레드 한 글 다시 쓰기도 저장된 대상 스냅샷을 사용한다. 외부 원문이나 작업의 이후 변경에 의존하지 않는다.
- 대상과 일반 레퍼런스는 트윗 ID로 중복 제거하고, 합산 상한은 기존과 같은 8건이다. 중복 항목은 대상 역할을 우선한다. 화면 표시·제출·서버 검증에서 같은 기준을 사용한다.
- 화면은 인용 대상과 일반 참고 자료를 구분하고, 본문을 읽기 전부터 조회 성공을 약속하지 않는다. 비용 안내는 생성 버튼 근처에 둔다.
- 새 원고의 근거 표시에서도 대상 역할을 구분한다. 기존 원고에 대상 역할을 추정해 소급 부여하지 않는다.

## 검증

1. 보관함에 없는 캐시 대상과 처음 조회하는 대상 모두 생성에 포함되고 보관함은 변하지 않는다.
2. 대상 조회 실패·잘못된 작업·일반 레퍼런스 누락 시 AI를 호출하지 않는다.
3. 대상 작업 참조·직접 URL·링크 없는 게시 전 작업을 구분한다.
4. 대상 중복 제거와 8건 상한이 화면·서버에서 일치한다.
5. 저장 후 전체/부분 다시 쓰기에 대상 역할과 본문이 유지된다.
6. 기존 역할 없는 레퍼런스와 일반 생성은 종전대로 동작한다.

실제 AI·X 조회 대신 대역을 사용한다. DB 통합 테스트는 저장소 테스트 가드로 확인한 스테이징에서 실행한다. 변경 파일 린트·타입 검사·빌드 결과를 기록한다. 업데이트 소식은 AGENTS.md에 따라 QA 완료 후 실제 머지 직전에 작성한다.
