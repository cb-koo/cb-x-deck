# 워크스페이스 페이지 (`/workspaces`) 설계

날짜: 2026-08-09
상태: 사용자 승인 대기 (시안은 비주얼 컴패니언으로 확정됨)

## 배경 · 목적

워크스페이스 관리 기능이 사이드바에 추가·삭제 버튼 두 개로만 존재한다. 이름 변경은 불가능하고, 순서도 바꿀 수 없으며, 파괴적 액션(삭제)이 상시 노출돼 있다. 일반 SaaS 패턴(Notion·Linear·Slack)대로 **전환(사이드바)과 관리(전용 페이지)를 분리**하고, 워크스페이스를 한눈에 보고 선택·관리할 수 있는 페이지를 신설한다.

사용자는 비개발 콘텐츠 기획 담당자다. AGENTS.md의 UX 원칙 6개를 적용한다.

## 범위

포함: `/workspaces` 페이지 신설, 사이드바 정리, `/` 진입 동작 수정, 이름 변경·순서 변경 API 신설, 목록 메타 조회 확장.

제외 (별도 묶음, 이 스펙에서 다루지 않음): 전환 시 `?view=table` 쿼리 보존, 사용량 페이지·삭제된 wsId 딥링크·태그 목록의 거짓 표시 3건, 현재 워크스페이스 표시 강화(헤더/탭 제목).

## 1. `/workspaces` 페이지

시안: `.superpowers/brainstorm/40310-1786248272/content/detail-v4-reorder.html` (박스 카드 + 드래그 순서 변경, 삭제 확인은 이름 입력 모달로 확정).

### 레이아웃
- 콘텐츠 폭 **max-width 640px 중앙 정렬**, 흰 배경. 기존 도구 페이지 타이포 스케일(15/13/11px, 제목 20px bold).
- 헤더: 좌측 제목 "워크스페이스", 우측 `+ 새 워크스페이스` 파랑 필 버튼.
- 헤더 아래 안내 캡션(11px, x-muted): "팀 전체가 함께 쓰는 작업 공간입니다. 카드를 클릭하면 해당 덱으로 이동하고, ⠿ 핸들을 끌어 순서를 바꿀 수 있어요." — 행동 전 기대 설정(원칙 2).

### 워크스페이스 카드
- 각 워크스페이스는 독립 카드: 1px `x-border` 보더, radius 12px, padding 16px, 카드 간 gap 10px. hover 시 배경 `x-hover` + 보더 `x-border-strong`.
- **현재 워크스페이스**(사이드바 기준 마지막 방문 = `cbx-last-ws`): 보더 `x-blue` 1.5px + "현재" 배지(11px, `#1573ad` 글자 / `#e3f1fb` 배경, 필).
- 카드 구성: 좌측 드래그 핸들(⠿, 13px, x-muted) → 이름(15px bold) + 메타 줄(13px, x-secondary) → 우측 `이름 변경` · `삭제` 텍스트 버튼(13px).
- 메타 줄: `컬럼 N개 · 저장 후보 N건 · 최근 활동 {상대시각}`. **"저장 후보"는 candidate 수를 뜻하며, 삭제 모달의 수치·용어와 반드시 동일해야 한다**(원칙 4 — 라벨과 값 일치). 최근 활동은 해당 워크스페이스의 candidate/컬럼 중 가장 최근 `created_at` 기준, 없으면 워크스페이스 `created_at`.
- **카드 클릭 = `/w/{id}` 덱으로 이동.** 우측 버튼·핸들은 클릭 전파를 막아 이동하지 않는다.

### 새로 만들기
- `+ 새 워크스페이스` 클릭 → 목록 상단에 인라인 입력 줄(입력창 + `만들기` 파랑 필 + `취소`). 기존 사이드바 생성 로직의 검증을 승계: 빈 이름 방지, 한글 IME Enter 이중 발화 방어(`creating` ref 패턴). placeholder는 "새 워크스페이스 이름" (기존 "클라이언트명" 미승계 — 워크스페이스 ≠ 클라이언트).
- 생성된 워크스페이스는 목록 맨 뒤에 추가된다(position = max + 1).

### 이름 변경 (신규 기능)
- `이름 변경` 클릭 → 카드 안에서 이름이 입력창으로 바뀌는 인라인 편집 + `저장`(파랑 필 소형) / `취소`. 빈 이름 방지, IME 방어 동일.
- 저장 성공 시 즉시 카드·사이드바 select에 반영.

### 순서 변경 (신규 기능)
- **드래그는 핸들(⠿)에서만 시작**된다 — 카드 전체가 클릭(이동) 영역이므로, 이동하려다 순서가 바뀌는 오조작을 막는다.
- 드래그 중: 들린 카드에 그림자, 원래 자리에 점선(`x-blue` dashed) 자리 표시.
- 놓으면 즉시 저장. 실패 시 원래 순서로 되돌리고 에러 캡션 표시.
- 이 순서는 사이드바 select 순서에도 동일하게 적용된다.

### 삭제 (이름 입력 확인 모달 — GitHub식)
- `삭제` 클릭 → 모달: radius 12px, max-width 360px, 그림자.
  - 제목 "워크스페이스 삭제" (20px bold)
  - 본문: "'{이름}'과(와) 컬럼 {N}개 · 저장 후보 {N}건이 함께 삭제됩니다. 되돌릴 수 없습니다." — 카드 메타와 같은 수치·같은 용어(원칙 4). 브리핑·발굴 계정·숨김 처리 등 워크스페이스에 속한 데이터가 모두 삭제된다는 한 줄 부기.
  - "계속하려면 워크스페이스 이름을 입력하세요" + 입력창.
  - `삭제` 버튼(`x-pink` 배경): **입력값이 이름과 정확히 일치할 때만 활성화.** `취소` 보조 필 버튼.
- 마지막 남은 1개는 삭제 불가(기존 서버 규칙 유지): 삭제 버튼 비활성 + 캡션 "마지막 워크스페이스는 삭제할 수 없습니다".
- 현재 보고 있는(=`cbx-last-ws`) 워크스페이스를 삭제한 경우: 페이지에 머물고 `cbx-last-ws`를 제거한다.

### 상태 처리
- 로딩: 카드 스켈레톤 또는 "불러오는 중…" 캡션.
- 실패: "목록을 불러오지 못했습니다" + `다시 시도` 버튼 (빈 상태로 위장하지 않는다).
- 빈 상태(0개): "아직 워크스페이스가 없습니다. 첫 워크스페이스를 만들어보세요." + 생성 입력 바로 노출.

## 2. 사이드바 정리 (`Sidebar.tsx`)

- 전환용 `<select>`는 유지. 옵션 순서는 position 순(목록 API 순서 그대로).
- `+ 워크스페이스 추가` 인라인 입력, `삭제` 버튼과 2단계 확인 바 **제거**.
- 그 자리에 **"워크스페이스 관리" 링크** 하나(→ `/workspaces`).
- 결과적으로 사이드바에서 파괴적 액션이 사라지고 전환 전용으로 단순해진다.

## 3. `/` 진입 동작 수정 (`src/app/page.tsx`)

현재: 항상 목록 첫 번째로 `router.replace`. 변경:

1. `cbx-last-ws`가 있고 **목록에 존재하면** 그 워크스페이스로.
2. 없거나 목록에 없으면(삭제됨) 첫 번째로.
3. **워크스페이스가 0개면 `/workspaces`로** — 기존 "이동 중…" 영구 정지 해소.
4. 목록 조회 실패 시: 에러 문구 + 다시 시도 (무한 스피너 금지).

`/generate`·`/clients`의 GlobalShell 동작(localStorage 우선)과 일관돼진다.

## 4. API · 데이터

### 목록 메타 확장 — `GET /api/workspaces`
- 기존 `{id, name}` 목록에 카드 메타 추가: `columnCount`, `candidateCount`, `lastActivityAt`.
- 워크스페이스별 집계를 한 번의 쿼리(LEFT JOIN + GROUP BY 또는 서브쿼리)로 조회 — N+1 금지.
- 사이드바는 메타가 필요 없으므로 기존 형태를 유지해도 되고, 응답을 공유해도 된다(구현 시 판단).

### 이름 변경 — `PATCH /api/workspaces/[id]` (신설)
- body `{ name }`. trim 후 빈 문자열 400. 존재하지 않으면 404.
- `workspaceStore.ts`에 `renameWorkspace(id, name)` 추가.

### 순서 변경 — `PATCH /api/workspaces/reorder` (신설)
- body `{ ids: string[] }`. 전체 순서를 한 번에 저장(개별 position PATCH 아님 — 드래그 한 번 = 요청 한 번).
- 기존 컬럼 순서 변경(`/api/columns/reorder` + `reorderColumns`)과 동일 패턴: 트랜잭션 + `for update` 잠금, 전달된 id 집합이 현재 워크스페이스 집합과 다르면(그 사이 다른 팀원이 추가/삭제) 409 — 클라이언트는 재조회한다.

### position backfill
- 마이그레이션: 현재 전부 0인 `workspace.position`을 `created_at` 순번으로 1회 backfill.
- `createWorkspace`가 `position = max + 1`을 넣도록 수정.
- 목록 정렬: `ORDER BY position, created_at` (기존 정렬과 하위 호환).

## 5. 라우팅 · 셸

- `/workspaces`는 워크스페이스 스코프 밖 페이지 — `/generate`·`/clients`처럼 GlobalShell 아래에 둔다.
- 워크스페이스 0개로 사이드바가 안 그려지는 경우에도 이 페이지 자체는 완전히 동작해야 한다(빈 상태 + 생성).

## 6. 테스트

- `workspaceStore`: rename(정상·빈 이름·미존재), reorder(전체·부분 id·미존재 id), backfill 후 정렬, createWorkspace의 position 부여.
- API 라우트: PATCH 검증(400/404), reorder 반영.
- UI 하네스는 없음(기존과 동일) — 화면 확인은 배포 후 사용자 확인 절차.

## UX 원칙 체크 (AGENTS.md)

1. 라벨 사용자 언어 — "워크스페이스 관리", "이름 변경", "현재" ✓
2. 행동 전 기대 설정 — 안내 캡션에 클릭·드래그 동작 설명 ✓
3. 판단까지 서술 — 삭제 모달이 결과를 서술 ✓
4. 라벨=값 일치 — 카드 메타와 삭제 모달의 "저장 후보 N건" 동일 수치·용어 강제 ✓
5. 기술 값 노출 최소화 — 해당 없음 ✓
6. 비용 유발 액션 — 해당 없음(DB 조회만) ✓
