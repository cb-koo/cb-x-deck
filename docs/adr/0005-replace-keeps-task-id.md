# 인플루언서를 교체해도 작업 ID는 그대로다

거절·무응답으로 다른 인플루언서에게 같은 일을 넘길 때, 옛 작업을 취소하고 새 작업을 만드는 대신 **같은 작업 행에서 인플루언서만 바꾼다.** 작업 ID를 `payment_request.task_id`·`tracked_post.task_id`·다른 RT의 `target_task_id`가 참조하므로, 행을 갈아타면 그 연결을 옮기는 규칙이 전부 필요해진다. 같은 ID를 유지하면 유형·대상·예정일·원고가 그대로 따라오고 취소 섹션도 늘지 않는다.

## 교체 규칙

- **게시 전에만.** 방문협찬은 **방문일이 지나기 전까지** — 방문한 사람이 게시해야 한다(koo 09-15). 기준은 기존 '방문 완료' 판정과 같은 `visit_on < 오늘`(당일은 허용, 방문일 미정은 허용). 날짜 기준이라 "예약일은 지났는데 실제로 안 왔다"는 방문일을 고친 뒤 교체하거나 취소 후 새 작업으로 — 실제 방문 여부를 저장하지 않는 한계.
- **비용**: 새 인플루언서의 프로필 단가로 다시 채우고 **[확인]을 눌러야 확정**된다(결정 문서 §4-3 — 같음→확정 / 다르게 고침→프로필도 바꿀지 묻기 / 프로필에 단가 없음→입력 후 저장할지 묻기). 확정 전엔 점선·회색. 비용의 출처를 저장하지 않으므로 손입력 여부를 판별하지 않는다 — 확인 한 번이 컬럼 하나보다 싸다. (09-18 갱신: "값이 있으면 유지/새 단가 중 묻기"를 [확인] 흐름으로 통일)
- **원고**: 붙은 채로 따라간다. 상태가 '전달됨'이면 **'사용 확정'으로 되돌리고** "새 인플루언서에게 다시 전달하세요" — 옛 사람에게 전달한 사실이 새 사람에게 전달한 것으로 읽히지 않게.
- **증빙**: 게시 전 올린 RT 증빙은 옛 사람의 것이므로 **제거**한다.
- **사유(선택)**: 취소와 같은 칩(거절·무응답·기타). `declined`·`no_response`면 옛 인플루언서 타임라인에 `task_declined` 이벤트(payload: taskId·campaignId·campaignName·taskType·reason·action `'replace'`). 취소도 같은 이벤트에 action `'cancel'`. 되돌리기 정정 이벤트는 만들지 않는다(한계).
- 기존 화면의 인플루언서 셀 변경도 이 동작을 쓴다(ADR 0003).

## 서버가 보장한다

규칙은 UI 훅이 아니라 서버에 있다. **인플루언서 칸을 바꾸는 모든 요청**(배정·해제·교체)에 같은 상태 제한이 걸린다 — `for update`로 다시 읽어 `posted_at is null`·`cancelled_at is null`·(방문협찬은) `visit_on`이 지나지 않았을 때만. 완료·취소·방문 완료 작업의 인플루언서는 어느 경로로도 바뀌지 않는다.

교체는 **해제 + 배정을 한 트랜잭션에 묶고 사유를 받는 것**이다. 따로 하는 해제·배정도 각자 자기 몫의 정리를 한다 — 그래야 "@a → 없음 → @b" 두 번으로 교체 규칙을 우회할 수 없다:

| 동작 | 상태 제한 | 옛 사람 흔적 정리 (원고 전달됨→사용 확정, RT 증빙 제거) | 비용 | 사유·로그 |
|---|---|---|---|---|
| 배정 (없음→인플) | 적용 | 없음(정리할 흔적이 없음) | 프로필 단가로 채우고 **[확인]**(§4-3) | 없음 |
| 해제 (인플→없음) | 적용 | **한다** | 유지 | 없음(사유를 남기려면 교체나 취소) |
| 교체 (인플→다른 인플) | 적용 | 한다 | 새 단가로 채우고 **[확인]**(§4-3) | 선택, `task_declined` |
| 같은 인플 재선택 | — | 변경 없음(no-op) | — | — |

교체는 별도 액션 라우트(`POST …/tasks/[taskId]/replace`)로 위 표의 한 행을 한 트랜잭션에 넣는다. 배정·해제·재선택은 기존 PATCH `influencerHandle`이 담당하되 같은 상태 제한과 정리 규칙을 서버에서 적용한다. 다른 인플루언서로 바꾸는 PATCH는 400으로 막고 교체 동작을 안내한다.

## Considered Options

- 옛 행 취소 + 새 행 복제 — 참조 이관 규칙 필요, 취소 섹션이 늘어남.
- 같은 행 교체(채택).
