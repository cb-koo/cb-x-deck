# 콘텐츠 생성 — 다중 시안 + 레퍼런스 검색·정렬 설계

날짜: 2026-08-08
상태: 설계 확정 (사용자 승인)
선행 스펙: `2026-08-06-draft-trust-status-design.md` (상태 축 — 본 스펙이 그 위에 얹힌다)

## 0. 배경과 목적

상태 축 배포 후 다음 사이클. 두 기능 모두 "생성 → 고르기 → 전달" 퍼널의 마찰을 줄인다.

1. **다중 시안**: 같은 조건으로 시안 여러 개를 한 번에 받아 고르는 흐름이 없다. 지금은 다시 쓰기를 반복하며 기다려야 한다. 여러 시안을 **동시에 채택**할 수도 있어야 한다(사용자 요구 — 하나만 고르는 모델 아님).
2. **레퍼런스 검색·정렬**: 보관함이 커지면 시트에서 "그때 그 트윗"을 태그 12개 + 스크롤로 못 찾는다. 성과 지표를 보여주면서 지표순 정렬이 없다.

## 1. 다중 시안

### 생성 방식 (접근법 A — 사용자 확정)

- **LLM 1콜로 N개 변형**: `draftOutputSchema`를 `variants: DraftContent[]` 형태로 확장, 프롬프트에 "서로 다른 앵글·훅으로 N개"를 명시해 **시안 간 다양성을 구조적으로 강제**한다. 병렬 N콜(기각)은 같은 프롬프트라 비슷한 결과가 나와 기능 목적(고르는 맛)을 훼손하고 입력 토큰도 N배.
- `count === 1`이면 기존과 동일한 단일 스키마·프롬프트 경로(기존 동작 불변).
- `max_tokens 16000`은 스레드×5시안도 여유. 실패(refusal 포함)는 기존 단일 생성과 같은 에러 UX — 부분 재시도 없음(YAGNI).

### 저장 모델

- 마이그레이션 `017_draft_batch.sql`: `draft.batch_id uuid`(null 허용), `draft.variant_index int`(null 허용). 단일 생성은 둘 다 null — 기존 행과 동일.
- 1콜 응답의 N개 변형을 **초안 N행으로 삽입** (같은 `batch_id`, `variant_index` 0..N-1, 같은 refs/direction/format 스냅샷). 각 행은 완전한 독립 초안 — 상태·편집·다시 쓰기·번역·삭제 전부 기존 그대로.
- 여러 시안 채택 = 각각 '사용 확정', 폐기 = '미사용' 또는 삭제. **새 선택 UI 없음 — 상태 축 재활용.**
- usage 기록은 1콜 1건(기존 `anthropic.draft`) — 비용은 호출 단위라 정확.

### UI

- **컴포저 접힘 패널에 "시안 수" 입력** (number, 1~5, 기본 1) + 도움말 "서로 다른 앵글로 여러 개 만들어 하나 이상 골라요".
- **매 생성 후·페이지 진입 시 1로 리셋** (localStorage에 저장하지 않음) — 3을 잊고 계속 뽑아 비용이 조용히 3배가 되는 사고 경로 차단 (비용 opt-in 원칙 6).
- 비용 캡션 동적: count>1이면 "생성 1회 ≈ $0.02 × 3".
- 생성 중 스켈레톤: count>1이면 "시안 3개 작성 중… 개수만큼 조금 더 걸려요".
- **형제 표시(얇은 표시 — 사용자 확정)**: `batch_id`가 있는 카드의 도구층(상태 칩 행)에 `시안 B · 같은 조건 3개 중`. 라벨은 `variant_index`→A/B/C…, "N개 중"은 로드된 목록에서 같은 `batch_id` 행 수로 계산(형제가 삭제되면 정직하게 줄어듦 — 라벨-값 일치). 접기/펼치기 등 강한 묶음은 하지 않는다.
- 완성 시 N장이 목록 맨 위에 연속 삽입(삽입 순서 = variant_index). 필터 자동 리셋·취소 후 폴링은 기존 로직이 배열을 그대로 수용(newDraftsSince·filterDrafts 모두 다건 대응 확인됨).

### 서버 검증

- `POST /api/drafts` body에 `count` 추가: 정수 1~5, 벗어나면 400 "시안 수는 1~5 사이여야 해요". 미지정 = 1.

## 2. 레퍼런스 시트 검색·정렬

### 원칙

- **전부 클라이언트 사이드** — 시트는 이미 전체 행을 로드한다(수백 건까지 문제없음, 그 이상은 3단 백로그 트리거).
- 검색·정렬은 세션용 렌즈 — 저장하지 않고, 시트를 다시 열면 초기화.

### 검색 (사용자 확정 범위)

- 필터 행에 검색 입력(placeholder "본문·작성자·메모·태그·번역문 검색").
- 매칭 대상: 트윗 본문 · 작성자 이름+핸들 · 메모 텍스트(작성자명 포함) · 태그 · **번역문**(useTranslations 캐시에 로드된 것만 — 시트 열림 시 기번역분이 자동 로드되므로 한국어 검색이 대부분 동작; '전체 번역' 후엔 전부 검색됨).
- 대소문자 무시, 공백으로 나눈 모든 토큰이 매칭되면 통과(AND). 태그 필터와도 AND.

### 정렬 (사용자 확정 옵션)

- 셀렉트: `기본 (메모 우선·최신)` · `좋아요순` · `조회순` · `북마크순` · `최신순`. 기본값은 현행 서버 정렬 순서 유지(메모 우선 → 최신 — 팀이 학습한 순서).
- 지표 정렬은 내림차순, 동률은 최신순 tie-break.

### 선택 보존

- 검색·정렬로 화면에서 사라진 선택은 유지(기존 `cacheRef` + `sel` 구조 그대로 — "N건 적용"과 실제 적용 불일치 없음). 필터 중에도 헤더 "N / 8 선택"이 전체 선택 수를 말한다.

## 3. 에러 처리

- N변형 응답이 count와 다르면(모델이 2개만 반환 등): 받은 만큼 삽입하고 그대로 반환 — 사용자에게는 도착한 카드 수가 곧 사실(막지 않음). 파싱 실패는 기존 defensive parsing 경로.
- 검색 결과 0건: "검색과 일치하는 레퍼런스가 없어요 — 검색어를 줄여보세요" (기존 빈 상태와 구분).

## 4. 테스트

- 순수 함수 추출 TDD: 변형 라벨(A/B/C)·형제 수 계산, 레퍼런스 검색 매칭(범위·AND·대소문자), 정렬 비교(지표·tie-break).
- 실 DB: N행 삽입(batch_id·variant_index 왕복), count 검증 400.
- 프롬프트: variants 스키마·다양성 지시 스냅샷(generatePrompt.test.ts 관례).
- 컴포저·시트 UI는 린트 + 수동(사용자 QA).

## 5. 범위 밖

- 시안 접기/펼치기 그룹 UI(얇은 표시로 확정), 부분 재시도, 서버 사이드 검색(보관함 수백 건 초과 시 3단과 함께), 시안 수 저장.
