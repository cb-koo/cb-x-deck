# 익스텐션 후속 웹 목업

기준: `cb_x_extension/docs/인계/cb-x-deck 기능 추가 목업 인계.md` (2026-10-04).

## 실행

```sh
npm run dev -- --hostname 127.0.0.1 --port 3100
```

- 미리보기: http://127.0.0.1:3100/mockup/x-extension (인플루언서 → 협업 콘텐츠에서 시작)
- 캠페인 작업: http://127.0.0.1:3100/mockup/x-extension?view=tasks
- 클리닉 설정: http://127.0.0.1:3100/mockup/x-extension?view=clinics
- 특정 작업: http://127.0.0.1:3100/mockup/x-extension?campaign=autumn&task=visit-confirmed
- `development`에서만 제공한다. 프로덕션에서는 페이지가 `notFound()`를 반환하며 기존 인증은 유지된다.
- 초기화 버튼 또는 새로고침으로 예약·초안·첨부·설정 모두 초기화된다. 브라우저 메모리에만 저장한다.
- 프론트 목업에는 API 호출·DB 저장·번역·AI 추출·외부 전송이 없다. 지도·X 링크는 사용자가 눌러 외부 화면을 여는 링크다.

## 캠페인과 클리닉 · 최신 피드백 반영

- 캠페인 화면은 기존 프로덕트의 캠페인 목록 → 선택 캠페인의 작업 표 → 작업 상세 순서를 따른다. 기간 상태·공통 단계 라벨은 기존 `campaignJudgment`와 `campaignView`를 재사용한다.
- 표의 **단계 / 유형 / 인플루언서 / 원고 / 게시 예정일 / 작업 비용**을 유지하고 **방문 예약** 열을 추가한다. 준비·전달·게시·정산·완료·취소의 공통 단계는 방문 예약의 대기·확정·방문과 별개다. 방문 예약 확정만으로 공통 작업 단계를 바꾸지 않는다. 방문협찬 상세의 상단 단계에는 대기·확정·방문·업로드·정산·완료를 한 번만 표시하며, 표의 게시 예정일에는 예약 시트와 같은 업로드 기한을 표시한다.
- 기존 목업에 추가했던 진행중·완료·취소/노쇼 탭과 방문 단계별 집계 줄은 제거했다. 전체 유형 작업 수와 방문협찬만의 건수가 섞여 보였고 기존 캠페인 운영에 별도 분류를 덧붙였기 때문이다. 기존 공통 단계·유형 필터와 검색을 사용한다. 취소·노쇼도 같은 캠페인 표에 기록을 남기고 취소 단계로 필터한다.
- 새 방문협찬은 **작업 추가 → 작업 상세 → 이 작업에 예약 추가** 순서로 등록한다. 기존 작업에 예약을 붙일 때 ID·유형·금액·기존 방문 기록을 보존한다. 예약 연결 후 게시 예정일은 업로드 기한과 동기화한다. 인플루언서에서 진입하면 해당 사람과 캠페인 범위를 유지하며, 전체 작업 보기로 필터를 해제할 수 있다.
- 클리닉은 현재 **단일 지점(본점)**으로 운영한다. 지점 관리·분리·추가 UI는 이번 범위에서 제외했다. 기존 예약의 장소 식별자는 참조 보존을 위해 유지한다.
- 기본 정보 / 운영시간 / 방문 안내·양식 3개 탭을 사용하며, 방문 안내·양식 아래에 **지도·방문 안내 / 고객 예약 양식·기재 시트**의 두 묶음으로 배치했다. 클리닉 화면의 탭·클리닉 전환 중 입력은 유지한다. 운영 설정은 하단에서 저장하며, 고객 예약 양식과 기재 시트는 각 항목에서 따로 저장한다.
- **클리닉 예약 접수 사용/미사용은 제외**했다. 현재는 담당자가 작업에 예약 정보를 연결하는 흐름이며, 새 지점 활성화나 외부 고객의 직접 예약 접수 기능이 없다. 운영 여부는 요일별 휴무·공휴일 정책·특정일 예외로 안내한다. 추후 외부 접수를 실제로 중지해야 하는 기능이 생기면 그 범위와 기존 예약 처리 정책을 정의한 후 도입한다.
- 설정 저장은 이후 고객 안내·새 예약에 적용한다. 이미 저장된 예약 시트·이력·동의서는 바꾸지 않는다. 기본 정보는 샘플에서만 저장하며 실제 콘텐츠 생성과 연결하지 않는다.

## 운영시간 UX · 후속 피드백

- 문자열로 운영 구간을 입력하던 화면을 제거했다. 외부 주간·공휴일 카드와 중복되던 모달 내부 탭을 제거했다. 운영 시작·종료를 시간 입력기로 고르고, 점심시간 있음/없음과 점심 시작·종료를 선택한다. 주간 설정의 적용 요일은 개별 선택하거나 평일·주말·매일로 한 번에 선택한다.
- 주간 카드의 `시간 설정`은 **매주 운영시간 설정**, 공휴일 카드의 버튼은 **공휴일 운영 설정**을 연다. 각각 `선택한 요일에 적용`·`공휴일에 적용`으로 해당 설정만 반영한다. 날짜별 설정은 기존 사이드 모달을 사용한다. 닫기·돌아가기·Escape는 모달 안 변경을 버린다.
- 같은 시간인 요일은 한 줄로 묶어 표시한다. 기존 줄의 변경 버튼으로 해당 요일만 수정할 수 있다. 휴무도 같은 요일 선택 흐름을 사용하며, 선택하지 않은 요일은 유지한다. 모달의 적용은 미리보기에 반영하고 `클리닉 설정 저장`으로 저장한다.
- 운영 종료가 시작보다 이르거나 같으면 적용하지 않는다. 점심시간은 운영시간 안에 있어야 한다. 점심시간 없음에서는 숨겨진 점심 입력값이 운영시간에 영향을 주지 않는다. 점심 시작부터 종료 직전까지는 운영시간 밖으로 안내한다.
- 공휴일은 **운영 / 휴무**로 단순화했다. `요일별 시간대로 운영`은 제거했다. 공휴일 운영 설정에서 운영을 선택하면 모든 공휴일에 같은 시간·점심시간을 적용한다. 휴무로 바꿔도 이전 시간은 보존해 다시 운영할 때 사용할 수 있다. 아직 정하지 않은 클리닉은 임의로 운영·휴무를 선택하지 않고 담당자의 선택을 받는다.
- 날짜별 운영 변경은 공휴일·일반 날짜 모두 캘린더를 눌러 같은 사이드 모달에서 설정한다. 예: 공휴일은 기본 휴무이지만 한글날만 10:00–14:00 운영. 공휴일 기본값을 변경해도 이런 날짜별 설정과 평일 운영시간은 유지한다.
- 날짜별로 정한 시간은 공휴일 기본 방침을 바꾸어도 유지한다. `기본 운영으로 되돌리기`는 그 날짜에 따로 지정한 시간을 해제하고 현재 기본 방침으로 다시 표시한다. 일반 날짜의 임시 휴무·연장 운영도 캘린더 날짜를 눌러 설정한다. 별도 공휴일 목록과 날짜 지정 버튼은 제거했다.
- **왼쪽에 매주 운영시간·공휴일 기본 운영을 상하 배치하고 오른쪽에 캘린더**를 둔다. 중복 소개와 캘린더 표시 간격을 줄여 데스크톱에서 설정과 월간 일정을 함께 볼 수 있다. 좁은 화면에서는 세로로 배치한다. 날짜 칸에는 운영·휴무, 운영시간, 공휴일명과 별도 설정을 뜻하는 파란 점을 표시한다. 모바일의 작은 날짜 칸에서는 운영시간을 모달 안에서 확인한다.
- 날짜를 누르면 오른쪽 사이드 모달이 즉시 열린다. 선택 날짜·본점·공휴일명·기본 운영시간을 확인하며 운영/휴무·시작/종료·점심시간·메모를 수정한다. 기본 운영으로 되돌리기도 이 모달 안에 모았다. 날짜를 눌렀을 때는 현재 설정을 보여주며, 적용 전까지 바꾸지 않는다.
- 모달의 적용은 해당 날짜만 캘린더에 반영하고, 최종 저장은 클리닉 설정 저장을 사용한다. 닫기·돌아가기·Escape는 작성 중인 수정을 적용하지 않고 눌렀던 날짜로 초점을 돌린다. 모바일에서는 전체 너비이며 본문만 스크롤하고 헤더·하단 버튼은 고정한다.
- `운영 안내 확인·복사`는 방문 예정 시간이 운영시간에 포함되는지 확인하고 안내문을 복사하는 보조 기능이었다. 날짜별 설정에서 용도가 불명확하다는 피드백에 따라 제거했다. 날짜 모달에는 운영·휴무, 시간·점심시간, 메모, 기본 운영으로 되돌리기와 적용만 남겼다. 예약 등록·수정에서 운영시간을 확인하는 기존 로직은 유지한다.
- 공휴일 정보가 없는 달이나 갱신 실패는 확인 필요로 남기며, 담당자가 날짜를 직접 지정한 일정은 유지한다. 공휴일은 2026년 10월 샘플이며 외부 조회는 하지 않는다.
- 지도와 언어별 방문 안내는 같은 탭에서 편집·미리보기한다. 고객에게 보내는 예약 양식과 클리닉 전달용 기재 시트도 같은 탭에 배치하고 쓰임을 구분해 설명한다.

## 예약 양식·기재 시트 UX · 후속 피드백

- 고객 예약 양식과 기재 시트를 **좌우로 배치**하고 각 제목 옆에 `수정/저장` 버튼을 둔다. 한쪽만 편집하거나 두 항목을 동시에 편집할 수 있다. 저장은 누른 항목에만 적용하며, 다른 항목의 미저장 입력은 보존한다. 좁은 화면에서는 위아래로 배치한다. 중복 미리보기와 이 탭의 공통 저장 바는 제거했다.
- 기재 시트의 치환 항목 목록을 제거했다. 편집할 때 `[인플핸들]` 버튼 하나로 커서 위치에 `@{{handle}}`을 넣는다. 선택한 텍스트가 있으면 대체하며, 새 예약에서는 해당 인플루언서의 핸들로 치환한다. 다른 항목 삽입 버튼은 제공하지 않는다.
- 고객 예약 양식이나 기재 시트가 바뀐 상태로 저장하면 **예약 파싱 형식도 함께 수정해야 해요** 모달을 표시한다. `예약 양식이나 기재 시트의 항목을 수정할 경우, 예약 파싱도 동일한 형식으로 수정해야 합니다. 변경한 내용을 개발자에게 전달하세요.`라고 안내한다.
- 각 양식의 `저장`을 눌러 안내를 확인한 뒤 `확인하고 저장`으로 그 항목만 저장한다. `계속 수정`·닫기·Escape는 작성한 내용을 유지하며 저장하지 않는다. 지도·운영시간의 저장은 양식 초안을 함께 저장하지 않는다. 변경하지 않은 양식의 저장에는 안내가 없다.
- 이 모달은 담당자에게 필요한 작업을 안내한다. 개발자에게 메시지를 보내거나 예약 파싱 코드를 자동 변경하지 않는다. 실제 파싱 연동은 개발자가 함께 수정해야 하며 목업의 예시 응답 파싱 범위는 유지한다. 이미 저장한 예약의 기재 시트는 바꾸지 않는다.

## 체험 순서

- 방문협찬의 게시 확인을 예산·정산 카드에서 제거한다. 게시 카드에서 X 게시물 링크를 검증하고 확인하면 업로드 상태·정산 후보에 반영한다. 비용 없는 작업은 완료된다. 예산·정산에는 게시 후 정산 요청·지급 완료 동작을 유지한다. 게시된 링크와 확인 시각은 샘플에 남으며 실제 게시물 조회·트래킹 등록은 하지 않는다. 링크 검증은 프로덕션의 `parseTweetLink`를 재사용한다.
- 원고 작성·선택은 사이드 창에서 체험한다. 직접 작성한 원고를 저장·연결하거나 기존 원고를 검색·연결하고, 연결한 원고는 열기·수정·떼기가 가능하다. `있는 원고 N`은 해당 인플루언서의 미연결 원고 수이며 연결·해제에 따라 갱신한다. 이미 다른 작업에 연결한 원고는 다시 제안하지 않는다. 작성 중 닫기는 미저장 내용 확인을 거친다.
- `AI로 만들기`는 실제 AI를 호출하지 않는다. 방향 입력과 준비된 샘플 시안·편집·연결 흐름만 제공하며 해당 화면에 이를 표시한다.
- 일정의 `취소·노쇼` 메뉴는 기존 예약 종료 규칙을 사용한다. 게시 카드의 `진행 안 됨`은 제거했다. 방문 전 취소, 방문일 당일 취소/방문 노쇼 선택, 방문 후 업로드 노쇼로 이어진다. 예약 연결 전 방문 작업도 작업 취소가 가능하다. 사유를 저장해야 종료되며, 돌아가기는 기록을 바꾸지 않는다. 예약·변경 내역·동의서·원고·메모를 보존하고 종료 후 읽기 전용으로 표시한다. 게시 확인 이후에는 취소·노쇼 메뉴를 표시하지 않는다.
- 기존 통합 일정 카드, 확정 후 공통 사유 모달, 변경 내역, 동의서·정산 규칙을 유지하며 아래 화면 단순화를 적용했다.

## 방문협찬 화면 단순화 · 반영 완료

- 방문협찬 헤더에 이름·핸들·캠페인·유형·프로필 링크를 모으고 중복 인플루언서 카드를 제거했다. 단계와 일정은 항상 펼쳐 둔다. 일정에는 방문일·업로드 기한, 클리닉·예약자·시술, `지금 할 일`과 해당 단계 행동을 표시한다.
- 카드 순서는 고정한다. 예약 변경 내역 → 협찬 동의서 → 예산·정산 → 원고 → 메모 → 게시를 유지하고, 접힌 상태에도 변경 횟수·최근 변경일, 파일명/동의서 미첨부, 금액·지급 상태/결제 수단 미등록, 원고 제목·상태, 메모 한 줄, 게시 상태를 표시한다.
- 기본 펼침: 대기는 부가 카드 모두 접힘, 확정은 동의서, 방문은 원고·게시, 업로드·정산은 예산·정산, 완료·종료는 부가 카드 모두 접힘이다. 주 버튼은 대기 예약 확정 / 방문일 당일 방문 완료 / 방문 게시 확인 / 업로드 정산 요청 / 정산 지급 완료 중 현재 단계의 한 개만 강조한다. 일정의 이동 버튼은 해당 영역을 펼치고 입력이나 조작 위치로 이동한다.
- 직접 펼친 영역은 이후 단계와 이전/다음 작업 이동 후에도 유지한다. 직접 닫은 영역은 같은 단계에서 계속 닫혀 있고 새 관련 단계에 진입하면 기본 펼침을 적용한다. 초기화·새로고침 시에는 기본 상태로 돌아간다. 접기 자체는 원고·금액·메모·게시 링크 입력을 버리지 않는다. 금액 미저장·파일 오류·게시 링크 오류는 접힌 상태에서도 표시한다.
- `원고 추가`를 누르면 기존 세 가지 원고 작성 방식을 펼친다. 메모는 요약의 수정·추가에서 바로 입력하며 기존 즉시 반영 방식을 유지한다. 종료된 작업은 기존처럼 읽기 전용으로 열람할 수 있다.
- 일정의 `자세히 보기 / 예약 수정 / 취소·노쇼`를 한 줄로 배치했다. 예약 상세 탭과 확정 후 사유 선택·횟수 정책을 유지한다. 취소·노쇼 메뉴를 닫으면 예약과 작성 중인 예약 수정 초안은 바뀌지 않는다.
- 모바일에서도 방문일과 업로드 기한은 나란히 배치해 비교한다. 날짜/시간 수정은 기존 캘린더·사유 모달로 연결한다. 방문협찬 외 유형의 기본 카드·폼은 유지한다.
