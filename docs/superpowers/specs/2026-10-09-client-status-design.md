# 클라이언트 현황 페이지 설계 (2026-10-09)

근거: `~/claude-outputs/20261008_클라이언트현황리포트_리서치종합.md`(리서치 3건 + 용어·해석 규칙 + 리드타임 실측), 차트 키트(`src/components/charts`, 샘플 `/debug/charts`), koo 결정(10-08~09 대화).

## 1. 목적

매주 클라이언트마다 X 바이럴 캠페인의 방향(유지·조정·변경)을 정하는 **내부 판단 화면**. 숫자를 모아 보여 주는 대시보드가 아니라, **결론부터 주는 판정서**.

- 퍼널: 캠페인 집행 → X 반응(조회·북마크) → LINE 신규 인입 → 상담 → 예약 → 방문·매출
- 판정 층(실측 리드타임 근거): 이번 주 = 신규 인입·예약 접수(예약은 첫 문의 3일 안이 8할) / 2~6주 뒤 = 방문·매출(예약 → 방문 중앙 2주)

## 2. 범위

- 대상: LINE 리포트 데이터가 연결된 클라이언트(`client.clinic_code` 있음) — 현재 미모드림·마인드스킨·닥터손유나. 나머지는 전체 화면 맨 아래 "LINE 데이터 연결 전" 한 줄.
- 기준 주: 지난 완결 주(월~일, KST). 오늘이 10/9(목)이면 이번 주(10/5~10/11)는 진행 중이라 **9/28~10/4**가 기준.
- 사이드바: 최상위 메뉴 맨 위 "클라이언트 현황"(`/status`). 매주 월요일 시작점이라 캠페인보다 위.
- 비범위(v1): 7일 안 예약률·코호트(LINE 대시보드 API 연동 후), 판정 규칙 사용자 편집, 클라이언트 공유·내보내기, 좁은 화면 전용 레이아웃(카드가 한 줄씩 쌓이는 것으로 대응).

## 3. 화면

### 3-1. 전체 현황 `/status`

맨 위 "지난주(9/29~10/5) 기준 · 판정은 규칙이 제안하고 담당자가 확정해요". 클라이언트마다 한 줄(열 6개):

| 열 | 내용 | 부품 |
|---|---|---|
| 클라이언트 | 이름, 확정 여부("확정됨 · 이름") | — |
| 판정 | 확정됐으면 확정값, 아니면 제안값(제안 표시) | VerdictChip |
| 이유 | 판정 이유 한 문장 | — |
| 신규 인입 | 지난주 값 + 8주 작은 추이선 + 평소 판정 | Sparkline |
| X 반응 | 지난주 북마크 합 + 조회 합 | — |
| 예약 4주 | 최근 4주 예약자 합 + 직전 4주 대비 증감 | Delta |

행을 누르면 상세. 판정이 '조정 검토'인 클라이언트를 위로 정렬.

### 3-2. 클라이언트 상세 `/status/[clientId]`

1. **판정 머리**: 판정(제안/확정) + 이유 + [제안대로 확정] [판정 바꾸기] + 메모 한 줄. 지난주 확정 판정과 메모가 있으면 "지난주 결정: 조정 검토 — 메모" 한 줄.
2. **근거 카드 3개(한 줄)**: 신규 인입 주별 8주(CategoryBars+평소 띠) / X 북마크 주별(CategoryBars+북마크당 비용 줄) / 예산 소진 속도(BulletList 1줄, 기간 예산이 있을 때).
3. **게시물과 신규 인입 일별 8주**(DayBarsChart + 게시 묶음 원, 크게 튄 날 강조, 전날 게시 상세).
4. **게시물 성적표**(PostScoreTable, 게시 묶음) + **조회와 인입의 관계**(BubbleScatter).
5. **고객 흐름**(FunnelList: 최근 4주 vs 직전 4주 — 신규 인입·상담·예약자, 주별 합) + **최근 게시물 성장 곡선**(GrowthCurves: 최근 14일 게시물, 가장 북마크 많은 글 강조).

모든 카드: 결론 한 줄 + 숫자, 설명은 ? 창(뜻/보는 법/계산/주의), 다음 행동은 규칙에 걸린 카드에만.

## 5. 판정 규칙 v1 (제안 — 몇 주 써 보며 다듬는다)

입력: 신규 인입 주별 8주(평소 = 가운데 절반), 지난주·그 전주 판정, 예약자 4주 합 vs 직전 4주 합, 최근 2주 X 게시 수, 데이터 주 수.

위에서부터 처음 맞는 규칙:

1. 신규 인입 기록이 4주 미만 → **판단 보류** "판단할 데이터가 4주 미만이에요"
2. 신규 인입이 2주 연속 평소보다 적음 → **조정 검토** "신규 인입이 2주 연속 평소보다 적어요"
3. 직전 4주 예약 4명 이상인데 최근 4주가 그 절반 이하 → **조정 검토** "최근 4주 예약이 직전 4주의 절반 이하예요"
4. 최근 2주 X 게시 0건 → **관찰** "X 게시가 2주째 없어요"
5. 지난주 신규 인입이 평소보다 많음 → **유지** "신규 인입이 평소보다 많아요"
6. 그 밖 → **유지** "평소 범위예요"

판정 4종: 유지(파랑) · 관찰(회색) · 조정 검토(주황) · 판단 보류(회색). 규칙은 순수 함수 + 테스트.

## 6. 판정 기록 (마이그레이션 067, 추가만)

```sql
create table if not exists client_weekly_review (
  id uuid primary key default gen_random_uuid(),
  client_id uuid not null references client(id) on delete cascade,
  week_start date not null,               -- 기준 주 월요일
  verdict text not null check (verdict in ('keep','watch','adjust','hold')),
  suggested text not null check (suggested in ('keep','watch','adjust','hold')), -- 확정 당시 제안값(규칙 다듬기 근거)
  memo text not null default '',
  decided_by uuid, decided_by_name text not null default '',
  decided_at timestamptz not null default now(),
  unique (client_id, week_start)
);
```

- 확정 = upsert(같은 주 다시 확정하면 덮어씀). 메모 200자.
- API: `GET /api/status`, `GET /api/status/[clientId]`, `PUT /api/status/[clientId]/review`(requireMember).
