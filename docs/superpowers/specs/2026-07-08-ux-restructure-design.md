# cb-x-deck UX 계층화 설계 (v1.5)

날짜: 2026-07-08
상태: 설계 확정 대기 (사용자 검토 전)
선행: v1 (2026-07-07 완성) — 이 문서는 v1의 단일 페이지 구조를 계층화하는 구조 개편

## 1. 배경과 목적

v1은 사실상 "덱 페이지 하나 + 보관함"의 평면 구조다. 리서치(exa) 등 성격이 다른
기능이 들어오기 전에, 기능 단위 계층(IA)과 내비게이션 골격을 먼저 세운다.

- **사용자 멘탈 모델**: "발굴은 여기, 모니터링은 여기, 모아둔 건 여기"가 구조로 읽히게
- **확장 수용성**: 이후 기능(리서치·설정·통계)이 구조 변경 없이 슬롯에 들어가게
- **팀 사용 준비**: 클라이언트별 작업 분리 + 팀원별 관점을 v2(로그인) 전에 가볍게 도입

## 2. 정보 구조 (IA)

**1차 계층 = 클라이언트 워크스페이스, 2차 계층 = 기능.**
근거: 실작업은 "오늘 어느 클라이언트 일을 하나"로 시작한다. 기능 진입의 기본값(홈)은
덱 — 가장 빈번한 반복 작업(모니터링)이기 때문. 리서치→덱→보관함 순 배열은 작업
퍼널(발굴→탐색→축적) 순서를 따른다.

```
┌──────────┬────────────────────────────────────┐
│ 사이드바  │  메인 영역                          │
│          │                                    │
│ [워크스페이스 스위처 ▾]   ← 1차: 클라이언트     │
│ ──────── │                                    │
│ 🔍 리서치 │  (슬롯만 — exa 기능은 다음 단계)     │
│ 📊 덱     │  ← 홈(기본 진입)                    │
│ 📁 보관함 │                                    │
│ ──────── │                                    │
│ 👤 멤버 선택│  ← 내가 누구인지 (로그인 대체)     │
└──────────┴────────────────────────────────────┘
```

- 좌측 고정 사이드바(폭 좁게, X 스타일). 현재 상단 nav 대체
- 리서치 메뉴는 이번 단계에서 **자리(빈 페이지)만** 만든다 — 기능은 별도 프로젝트
- URL 구조: `/w/[workspaceId]` (덱) · `/w/[workspaceId]/library` · `/w/[workspaceId]/research`

## 3. 데이터 계층: "데이터는 하나, 관점은 여러 개"

### 3.1 공유 레이어 (팀 단일 원본)
- **워크스페이스**: 클라이언트 단위 작업 공간. 컬럼·후보가 여기에 스코프됨
- **컬럼 구성·트윗 아카이브**: 팀 공유. 같은 검색을 팀원마다 반복하지 않음(API 비용·데이터 일관성)
- 트윗 아카이브(tweet 테이블)는 전역 공유 유지 — 트윗 자체는 중립 데이터이며
  워크스페이스 연결은 column_tweet(컬럼 경유)로 성립

### 3.2 개인 레이어 (멤버별 기록) — 저장이 유일한 명시적 액션
- **저장(후보) + 메모·태그**: 멤버별 기록. 같은 트윗을 여러 멤버가 각자 저장·메모 가능
  (unique = 트윗×멤버×워크스페이스)
- **봤음(seen)**: 멤버별 자동 기록 (아래 4절)
- **읽음 버튼(✓읽음·모두 읽음)은 삭제** — 명시적 읽음은 사용자가 쓰지 않는 기능
  (콘텐츠를 보면 그게 읽음이라는 멘탈 모델과 충돌)

### 3.3 멤버 식별 (v1.5 — 로그인 없음)
- members 테이블(이름·색상)에 팀원 등록, 사이드바에서 자기 이름 선택(localStorage 기억)
- 인증·권한 없음. 실제 로그인은 v2(팀 배포) 범위
- 기존 단일 사용자 데이터는 기본 멤버 1명으로 귀속 마이그레이션

## 4. "봤음" 자동 처리 — 뷰포트 감지

**판단 근거**: 이 도구의 약속은 "놓치지 않는 탐색"이라 오류 비용이 비대칭이다.
안 봤는데 봤음 처리(후보를 놓침) ≫ 봤는데 안 봤음(몇 장 다시 훑음).
따라서 "확실히 본 것만 보수적으로 처리"하는 방식을 택한다.

- **기준**: 카드가 뷰포트에 **50% 이상 노출된 상태로 1초 체류** 시 자동 "봤음"
  (X의 조회수 집계와 같은 기준). 화면보다 긴 카드는 "카드가 뷰포트 대부분을 채움"으로 보완
- **기록**: 멤버별(tweet×member). 카드마다 즉시 전송하지 않고 수 초 단위 배치 전송
- **표시**: 기본 뷰 = 전체 표시하되 **내가 본 트윗은 흐리게(55% 투명)**, hover 시 원래
  밝기로 복원. 흐림은 라벨이지 접근 제한이 아님 — 내용·링크·저장 모두 그대로 동작
- **"새 트윗만" 필터** = 내 봤음 기록이 없는 트윗만 표시 (멤버별로 자기 기준)
- **역할 분담**: 봤음 = 자동·효율(다시 안 보기 위함) / 저장 = 판단·가치(다시 보기 위함).
  "나중에 다시 볼 트윗은 저장한다"가 사용 규칙

## 5. 팀 관점 (저장 기준)

- 관점의 단위는 **저장된 콘텐츠** — "그 사람이 뭘 봤나"가 아니라 "뭘 골랐나"
- **보관함**: 멤버 필터(전체/멤버별) — 다른 팀원이 고른 후보·메모를 그대로 열람
- **덱 카드**: 저장자 표시(누가 저장했는지 멤버 배지) — 팀원이 이미 고른 트윗이 보임
- 봤음(seen)의 관점 전환은 하지 않음 — 봤음은 각자의 탐색 효율용 개인 상태일 뿐,
  팀이 서로 확인할 대상이 아님

## 6. DB 변경 (마이그레이션 개요)

신규: `workspace(id, name, position)` · `member(id, name, color)` ·
`tweet_seen(tweet_id, member_id, seen_at)` — PK(tweet_id, member_id)

변경:
- `deck_column` + `workspace_id` (FK)
- `candidate` + `workspace_id`, `member_id` / unique(tweet_id) → unique(tweet_id, workspace_id, member_id)
- `tweet.seen_at` 폐기(컬럼 유지하되 참조 제거 → 후속 정리)

마이그레이션: 기본 워크스페이스 1개("기본")·기본 멤버 1명을 만들고 기존
컬럼·후보를 귀속. 기존 tweet.seen_at은 기본 멤버의 tweet_seen으로 이관.
파괴적 변경 없음(기존 데이터 전부 보존).

## 7. 이번 범위에서 제외 (YAGNI)

- 리서치 기능 자체 (exa 연동) — 이 뼈대 위에 별도 프로젝트로
- 로그인·인증·권한 (v2)
- 팀 통합 관점("팀 누구도 안 본 트윗") — 필요성 확인 전 보류
- 알림·활동 피드, 워크스페이스별 설정
- **LLM 초안 제작** (저장 콘텐츠 벤치마킹 → 콘텐츠 초안 생성) — 향후 기능.
  검토 결과(2026-07-08) 이번 구조가 전제를 그대로 제공하므로 선행 변경 불필요:
  재료=후보(저장), 맥락=메모·태그, 스코프=워크스페이스, 작성자=멤버, 메뉴=사이드바 슬롯.
  구현 시 `draft` + `draft_source`(후보 참조) 테이블만 추가하면 됨.
  단 draft_source는 후보 삭제에 대비해 참조 시점 스냅샷 방식으로 설계할 것.

## 8. 검증 계획

- store 단위: workspace/member/tweet_seen CRUD + 마이그레이션 후 기존 데이터 귀속 확인 (실DB 테스트)
- 뷰포트 감지: 디버그 페이지에서 스크롤 시 배치 기록 동작 확인, 하단 미노출 카드가 기록되지 않는 것 확인
- E2E: 워크스페이스 생성→컬럼 이동 확인 / 멤버 전환→각자 "새 트윗만"이 독립 동작 /
  멤버 A 저장→멤버 B 보관함 필터에서 열람
